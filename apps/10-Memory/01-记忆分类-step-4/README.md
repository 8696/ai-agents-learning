## 本步核心

一次请求按行业两层来读记忆，不是「库里所有长期事实都按当前问句做 Top-K」：

```text
用户敲下一句话
        │
        ├─① 程序性记忆（全员规则，常驻，不检索）
        │     listRules() → 进 system 段开头
        │
        ├─② 核心用户画像（语义记忆 · 长期，常驻，不按问句筛）
        │     事实库里全部语义长期条目整份进 system
        │     问 B 时不会把问 A 用过的 Vue 从 system 里换掉
        │
        ├─③ 本轮相关经历（情景记忆，按问句检索，只活在这一次请求）
        │     只对情景记忆做嵌入 + 余弦 + Top-K=3 + 阈值 0.10
        │     问候 / 「刚才说了什么」 / 纯算术会跳过这一步
        │
        ├─④ 工作记忆（对话历史，累积）
        │     user / assistant 轮次接到 system 后面
        │
        ▼
   拼成 messages ──→ 真发网络请求调模型
```

对应产品 / 论文里的叫法：①+② ≈ ChatGPT 已保存记忆、Letta 核心记忆（Core Memory）；③ ≈ 档案记忆（Archival Memory）按需检索；④ ≈ 工作记忆 / 会话消息列表。

## 数据流

```text
用户点「发一条」
    → POST /api/chat { messages, currentQuery, toggles }
    → runFullPipeline：
         ① listRules()
         ② listFacts() 里筛「语义记忆 + 长期」整份注入
         ③ 需要翻经历时 runRetrieval（候选池不含语义记忆）
         ④ 拼 system + 对话历史 → 调协议 A 对话补全
    → 页面按 ①②③④⑤ 展示输入 / 做了什么 / 输出
```

## 当前能做什么

- 连问「写个按钮」再问「我用什么框架？」：两轮的核心画像都应含 Vue，不会被第二问的情景 Top-K 换掉
- 再问「我处理过哪些批量改价任务？」：③ 换成改价相关经历，② 的画像仍在
- 勾「不注入核心用户画像」再问框架：对照模型还会不会说出 Vue
- 勾「跳过本轮情景召回」：③ 跳过，①② 仍在
- 「结束会话」清空工作记忆；「清空用户记忆」只清空事实库
- 缺密钥 → 503；演示后端 5xx → 另一条失败通道

## 与 step-1 / step-2 / step-3 的关系

- step-1（端口 50100）：分类本身，不持久化
- step-2（端口 50101）：分类 + 写入到 data/facts.json + 重启验证
- step-3（端口 50102）：按余弦召回（教学「检索长尾」；不区分画像常驻）
- step-4（本步）：行业两层读取。建议先在 step-2 落下几条语义事实和情景经历再回本页
