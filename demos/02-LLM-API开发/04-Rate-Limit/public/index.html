429 / Rate Limit · 重试时间线

对应小节：docs/学习模块/02-LLM-API开发/04-Rate-Limit.md。 点按钮跑场景，每次返回 attempts[]，渲染成时间线表。

看什么 / 怎么对照本条要能讲清列
  • ① easy：看时间线里 attempt 1 / 2 状态码是 429、waitBefore 至少 500ms（因为 Retry-After: 0.5），attempt 3 是 200 → 听 Retry-After。
  • ② chaos × 6：连续跑 6 次，对比每次的 waitBefore 列。如果每次都精确等于 200/400/800…（没 jitter），6 次都是同一组数；加了 jitter 后 6 次的 waitBefore 会各自带随机偏移，这就是防 thundering herd 的那一刀。
  • ③ auth：只有 1 行 attempt，状态码 401，立刻抛 NonRetryableError → 不重试 401。
  • ④ forever：4 行 attempt 全是 429，最终抛 RetryExhaustedError → maxAttempts 上限生效。
  • ⑤ ok：1 行 attempt，状态码 200，waitBefore=0 → 成功路径不触发重试。
  • ⑥ 真 API 单次：调一次 MiniMax；通常直接 200 + 真实网络耗时（~100~500ms vs mock 的 1ms）；偶发网络抖动会看到 retry。
  • ⑦ 真 API 并发 20：每个请求独立套 retry；看真 429 + 真 Retry-After 头。每次跑消耗 token（约 0.02 元），按需开启。
