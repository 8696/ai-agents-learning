勾 ✅ 前必须先把这两件事说出来再判闸门：① 该行当前状态（⬜/🔄，已 ✅ 就不重复勾）；② Demo 到 step 几、哪几步已被学习者锁定 ✅。外部条：MD 过 [§7.2](./07-notes.md#72-沉淀--小节进度对齐) **且** Demo 行不是 `未判` **且**（结论=可运行时）至少 1 个 `{小节文件夹}-step-N` 已锁定 + 有对应 `yarn app:…-step-N` + `node scripts/check-demo.cjs` 过 —— 缺一条**不准勾**，直接说缺哪条。step-(N+1) 仍 🔄 打磨中**不阻塞**勾本条。另须过 [05-demo.md §5.4](./05-demo.md#54-目标--代码整合闸门两段式新) 两段闸门 + **独立代码覆盖验证**（详下）。复盘走 [07-review.md](./07-review.md)。

#### 独立代码覆盖验证（`coach complete` 闸门一环 · 2026-09-04 维护模式起生效）

**问题**：§5.4.B 是 MD 自己写的「文档 ↔ 代码」证据表 —— Coach 自己读 MD 看那张表就能"过"，可实际代码真有缺口也漏（2026-09-04 + 2026-09-04 维护后都踩过同样坑：MD 自报 14 行 ✅ 实际有 3 个 UI 缺口）。**信 MD 自报 = 漏变体**。

**规则**：

1. **派独立 subagent 查代码** —— `coach complete` 触发时，Coach 必须派一个 subagent（不带本对话上下文）读已锁定 step-N 的代码（`routes/` · `lib/` · `public/`），对照当前小节 MD 的：
   - **核心对象**（如 ①②③④⑤）
   - **例子**（前端场景；生活例子 1/2 不要求代码）
   - **业务需求**（验收准绳）
   - **易混点**（如果易混点说"必须 X"，代码必须 X）
2. **逐项判定 ✓ / ⚠ / ✗ + 文件路径 + 行号证据** —— subagent 输出表，每项都要有具体证据；找不到证据 = ⚠/✗
3. **严格阻塞**：任一 ⚠ / ✗ → 不准勾 ✅ → 学习者决定「补 / 接受缺口写进 MD 已知缺口节 / 拆条」（`coach complete` 是完成命令，缺口不能"带过"）
4. **MD 自己写的 §5.4.B 表只能作参考**，**不作**判定依据 —— Coach 收 subagent 报告后再判闸门
5. **复盘行不打本闸门**（[07-review.md](./07-review.md) 只过 MD 闸门）
6. **已 ✅ 旧条不回头跑本闸门**，除非学习者点名补漏

**判定清单模板**（写到 §5.4 闸门报告里）：

```markdown
## §5.4 独立代码覆盖验证（`coach complete` 闸门）

跑闸门日期：YYYY-MM-DD（subagent 报告 ID）

| 类 | 项 | 状态 | 证据（文件:行号 / 按钮 id） |
| -- | -- | -- | -- |
| 核心对象 | ① tools schema | ✓/⚠/✗ | ... |
| 核心对象 | ② tool_call 解析 | ✓/⚠/✗ | ... |
| 例子 | 例子 3（天气 chatbox） | ✓/⚠/✗ | ... |
| 需求 | 需求 1（并行 tool_call） | ✓/⚠/✗ | ... |
| 易混点 | "必须 `Promise.all`" | ✓/⚠/✗ | ... |

**判定**：过 / 不过。缺口 N 条：{列每条缺什么 + 建议补在哪 / 是否接受写进已知缺口节}
```
