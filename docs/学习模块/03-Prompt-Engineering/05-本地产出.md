## 外部条 → 这个应用哪一步

| 外部条 | 在客服中台哪一步 |
| ------ | ---------------- |
| 01 角色优先级 | System 放产品规则，User 放客户原文；来信不会当成系统指令改规则 |
| 02 Few-shot | 评价分类走带教案的 Few-shot，不在首页做 Zero/Few 开关 |
| 03 CoT / ReAct | **故意不做** Agent Loop；中台是一次处理出工单 |
| 04 版本管理 | 工单页脚列出本次用过的 Prompt id + version |

8 类 Prompt 资产（抽取、分类、总结、改写、分析、路由、纪要、问答）分别用在来信工单 / 会议待办 / 制度问答三条客服路径里，不是八个 Demo 按钮。

## 这一课解决什么问题

按条 Demo 负责把一刀知识看清楚。本地产出要把**整个模块已经会的事，收成一个客服能用的中台**：贴来信 → 出工单。不是把 01～04 的按钮搬到同一页。

## 是什么

**豆谷客服中台**一件产品，三个工作台（同一套壳，不是三个 Demo）：

| 工作台 | 客服在做什么 | 背后用的 Prompt 资产 |
| ------ | ------------ | -------------------- |
| 客户来信 | 贴原文，拿一张工单 | 路由、抽订单、Few-shot 评价、情感、书面转述、摘要 |
| 会议待办 | 纪要 → 负责人 + 截止日期 | `extract-meeting-actions` v1.1.0 |
| 制度问答 | 只根据制度答，没有就说不知道 | `qa-faq-with-context` |

System 里是产品规则（灰区定义、只出 JSON、缺字段 N/A）。User 里是客户原文，且经过 `{{var}}` 转义。评价这条生产路径走 Few-shot（assistant 只出现在教案里）。版本号写在工单页脚，不单独开「版本管理」页。

Zero vs Few 的**对照实验**仍在按条 Demo `50302`。CoT / ReAct 循环仍到模块 07。

## 为什么

客服不会先点「跑分类 Demo」再点「跑路由 Demo」。他们只处理这一封信。模块知识如果不能藏进这一条路径，就还是课堂开关，不是产出。

## 易混点

| 组 | 差在哪 |
| --- | --- |
| **产品 vs 拼盘** | 产品：一件事做到底。拼盘：同一页上排本模块所有 Demo 按钮 |
| **中台三个工作台 vs 三个 Demo** | 来信 / 纪要 / 制度是客服日常三件事，共用品牌和页脚版本 |
| **生产用 Few-shot vs 对照页** | 中台分类默认 Few-shot；要看 Zero 差在哪去 02 那条 Demo |

## 例子

客服点开示例 1：订单号 + 包装压扁但豆子完好 + 问物流。处理后来信工单上应同时有：去向偏订单查询、抽出 80012345、评价按产品定义偏中评、一段书面转述。页脚列出本次用过的 Prompt id 和 version。

有人在来信里写 `{{system}}` 想搅模板：转义后不会变成第二层占位符。

## 取舍

- 首页不做「故意 429 / 对照 Zero」——那是小节 Demo。产品里空来信 400、接口 502、断网红色 pill 就够 §5.3。
- 8 套资产仍落在 `src/prompts.ts`，各 5 条样本给 CLI 回归；产品用示例来信，不把「样本 #3」当 UI。

## 踩坑

把「模块能力总和」理解成「按钮总和」——上一版工作台就是这样，已返工。

## 代码运行流程

```text
处理来信
  → POST /api/inbox { message }
  → 转义后并行 6 路协议 A
  → #output 一张工单 + used[]
```

## 过关自检

- 打开是客服中台，不是 Demo 开关盘。
- 一封来信能出完整工单，页脚有版本。
- 纪要、制度问答能用。
- 空输入 / 网络错误看得到。
