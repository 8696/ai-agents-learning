### 这一课解决什么问题

把「调 LLM API」从抽象概念变成一条能 30 秒内跑通的本地链路：读配置 → 校验 → 发消息 → 流式打印 → 看 Token 用量。摩擦降到「`yarn dev` 就能试一个想法」。

### 是什么

模块 00 留下的不是五个空项目，是 **一个**能跑的 ChatGPT Mini：

- **Zod 运行时守门**：TypeScript 只管编译期；`process.env` 空没空、URL 对不对，启动时用 Zod `parse` 立刻拦住。
- **OpenAI 兼容协议（协议 A）**：MiniMax 提供与 OpenAI 相同形状的 `/chat/completions` API，所以用 `openai` npm 包 + 改 `baseURL` 即可，不必换 SDK、也不用手写 fetch。
- **Streaming 流式**：`stream: true` 后服务端逐 chunk 推送（前端类比：消费 SSE / `ReadableStream`）。客户端用 `for await` 读 `delta.content` **增量**，体验像 ChatGPT 打字。
- **messages**：现在只有一条 `user`；以后加 `system`、`assistant` 就是多轮（模块 03 / 06 再回填）。
- **协议 B 对照入口**（超前）：`yarn dev:anthropic` 走 `@anthropic-ai/sdk` + `/anthropic`，**同一把 `MINIMAX_API_KEY`**。模块 00 验收仍以 `yarn dev`（协议 A）为准。

概念条目拆在：[API Key / 计费](./01-API-Key-计费.md)、[Node ≥22](./02-Node-22.md)、[密钥安全](./03-密钥安全.md)。本文件只收「这一课串起来之后」的东西。

### 为什么（Agent 开发要懂）

第一周只验证「链路通不通」：能发、能流、能看用量。后面模块 02–04、06、22 都 **回填这一个 app**，起点不稳，后面每加一层都在沙子上盖楼。

小项目里其实已经叠了不少工程点（env、Zod、流式、usage、双协议入口）。当时明确过：这些必须写进项目 `LEARNING.md`（当前地图）和 AGENTS 约定，不能只停在「代码能跑」。

### 易混点

| 容易当成 | 其实是 |
|----------|--------|
| 账号可以三家都注册 | 模块 00 **代码**只接 MiniMax 协议 A。智谱放到模块 02。 |

### 例子

```bash
cd apps && nvm use
cd 01-chatgpt-mini
yarn install
yarn dev "你好"
```

控制台逐字打出回复，最后打印 `usage`（或提示去 MiniMax 控制台）。换协议 B 对照：`yarn dev:anthropic "你好"`——同一把 Key，换 SDK 和 Base URL。

前端类比：`for await` 消费流 ≈ 页面里读 SSE 的 `onmessage`；Zod `parse` ≈ 上线前把环境变量当运行时 schema 校验，而不是只靠 TS 类型。

### 取舍

- **为什么先只接 MiniMax 协议 A**：避免陷进多厂商 / 多协议差异；智谱、Anthropic 对照留模块 02。
- **为什么用 `openai` 包而不是手写 fetch**：SDK 处理鉴权头、流式解析、类型；学习重点在 messages / stream / usage，不在 HTTP 细节。
- **为什么配置放 `apps/`**：5 个 app 共用 Key；根目录留给文档。不抽共享包，加载文件按 app 复制。
- **协议 B 已超前添加**：属于模块 02 范围；模块 00 主路径 `yarn dev` 已通过即可。
- **中国区写死为默认**：控制台、API Base、账单都走国内站，避免助手以后默写成 `*.minimax.io`。

### 踩坑

- MiniMax 国内站是 `api.minimaxi.com`，不是 `api.minimax.io`（海外）。
- Token Plan 订阅 Key 和按量 API Key 不能混用。
- `delta.content` 是增量；`console.log` 破坏打字机效果，用 `stdout.write`。
- 本机 Node 低于 22 → `engines` 拦住 `yarn dev`；在 `apps/` 下 `nvm use`。
- 一上来装三家客户端、建五个空项目：账号能注册 ≠ 本模块代码要接三家。

### 代码运行流程

> 当时切片（函数名）。行号会变，对行请看 [LEARNING.md](../../../apps/01-chatgpt-mini/LEARNING.md)。

从 `yarn dev "你好"` 到控制台输出：

1. `tsx src/index.ts` 启动，`process.argv` 拼出用户消息（无参数则用默认句）。
2. `loadRootEnv()` 用 dotenv 读 `apps/.env` 到 `process.env`。
3. `envSchema.parse(process.env)` 校验 `MINIMAX_API_KEY` / `MINIMAX_BASE_URL` / `MINIMAX_MODEL`。
4. `new OpenAI({ apiKey, baseURL })` 创建客户端（请求实际发往 MiniMax 国内 `api.minimaxi.com/v1`）。
5. `chat.completions.create({ messages, stream: true, stream_options: { include_usage: true } })` 发起流式请求。
6. `for await (const chunk of stream)` 取 `choices[0].delta.content` 写入 stdout。
7. 流结束后打印 `usage`（prompt / completion / total），或提示去 MiniMax 控制台查账单。

关键类型 / 函数：

- `loadRootEnv()` — 从 `apps/` 加载 `.env`，无文件时回退 cwd。
- `envSchema` — Zod 对象，启动期校验 MiniMax 相关环境变量。
- `main()` — 组装 messages、发起流式请求、消费 chunk、打印用量。

对照入口：`index-anthropic.ts` 用同一把 Key，走 Messages API + `/anthropic`。
