### 这一课解决什么问题

把「调 LLM API」从抽象名词变成一条大约 30 秒能跑通的本地链路：读配置 → 校验 → 发消息 → 流式打印 → 看 Token 用量。摩擦降到「`yarn dev` 就能试一个想法」。

概念三条拆在：[API Key / 计费](./01-API-Key-计费.md)、[Node ≥22](./02-Node-22.md)、[密钥安全](./03-密钥安全.md)。本文件只收**串起来之后**还要能讲清的东西。

### 是什么

模块 00 留下的不是五个空文件夹，是 **一个**能跑的 ChatGPT Mini。核心对象各自一句话：

**Zod 运行时守门。** TypeScript 只管编译期；`process.env` 空没空、URL 像不像网址，启动时用 Zod `parse` 立刻拦住。像表单提交前的校验，不是等服务器 401。

**协议 A（本模块验收）。** MiniMax 提供和 OpenAI 同一形状的 `/chat/completions`，所以用 `openai` 包、改 `baseURL` 指向国内 `api.minimaxi.com/v1` 即可。不必手写 fetch，也不必本模块就上三家 SDK。

**Streaming。** `stream: true` 后服务端按块推。客户端 `for await` 读 `choices[0].delta.content`——那是**这一小块的增量**，不是整篇回复。体验像对方在打字。前端对应：消费 SSE / `ReadableStream`，用 `stdout.write` 不要 `console.log`（后者自带换行，打字机效果碎掉）。

**messages。** 现在只有一条 `user`。以后加 `system`、`assistant` 就是多轮，留给模块 03 / 06 回填同一个 app。

**协议 B 对照入口（超前，00 不验收）。** `yarn dev:anthropic` 走 `@anthropic-ai/sdk` + `/anthropic`，**同一把 `MINIMAX_API_KEY`**。对照验收在模块 02。

### 为什么（Agent 开发要懂）

第一周只验证「链路通不通」：能发、能流、能看用量。后面 02–04、06、22 都 **回填这一个 app**。起点不稳，每加一层都在沙子上盖楼。

小项目里已经叠了 env、Zod、流式、usage、双协议入口。这些必须写进项目 `LEARNING.md`（**当前代码地图**，行号会变）和 AGENTS 约定；概念和取舍写在本模块各小节 MD，不要把教材塞进 LEARNING。

### 易混点

| 容易当成 | 其实是 |

### 例子

**1. 整条链路像点外卖：下单 → 校验地址 → 骑手一袋一袋送到门口**

```bash
cd apps && nvm use
cd 01-chatgpt-mini
yarn install
yarn dev "你好"
```

Zod 是「地址填了没」（没填不出门）。流式是骑手按袋送到，你在门口一袋一袋接，不是等整桌菜一次端上来。最后小票是 `usage`；没有小票就去 MiniMax 控制台对账。

**2. 协议 A：同一把插座转接头**

MiniMax 的插孔形状跟 OpenAI 的 chat completions 一样，换一根线（`baseURL`）就能用 `openai` 这只插头。本模块不换三家不同形状的插头。

**3. 协议 B：同一把钥匙、另一扇门**

`yarn dev:anthropic "你好"`：还是那把 `MINIMAX_API_KEY`，走 Anthropic 形状的 Messages API。00 能开这扇门当对照；验收仍以 `yarn dev`（协议 A）为准。

**4. delta：微信正在输入，不是整段转发**

对方发来的每一个小气泡是新敲出来的那几个字。你把气泡拼起来才是全文。`console.log` 每个气泡后硬插入回车，屏幕上就像每字一行。

**5. 前端一条对应**

`for await` 消费流 ≈ 页面里 SSE 的 `onmessage`。Zod `parse(process.env)` ≈ 上线前把环境变量当运行时 schema，而不是只靠 TS 类型「编译过了就当配好了」。

### 取舍

- **为什么先只接 MiniMax 协议 A**：避免陷进多厂商 / 多协议差异；智谱、Anthropic 对照留模块 02。
- **为什么用 `openai` 包而不是手写 fetch**：SDK 处理鉴权头、流式解析、类型；学习重点在 messages / stream / usage，不在 HTTP 细节。
- **为什么配置放 `apps/`**：5 个 app 共用 Key；根目录留给文档。不抽共享包，加载文件按 app 复制。
- **协议 B 已超前添加**：属于模块 02 范围；模块 00 主路径 `yarn dev` 已通过即可。
- **中国区写死为默认**：控制台、API Base、账单都走国内站，避免助手以后默写成 `*.minimax.io`。

### 踩坑

- MiniMax 国内站是 `api.minimaxi.com`，不是 `api.minimax.io`（海外）。
- Token Plan 订阅 Key 和按量 API Key 不能混用。
- `delta.content` 是增量；`console.log` 破坏打字机效果，用 `stdout.write`。
- 本机 Node 低于 22 → `engines` 拦住 `yarn dev`；在 `apps/` 下 `nvm use`。
- 一上来装三家客户端、建五个空项目：账号能注册 ≠ 本模块代码要接三家。

### 代码运行流程

> 函数名以当时切片为准。对行号请看 [LEARNING.md](../../../apps/01-chatgpt-mini/LEARNING.md)（会随回填变）。

从 `yarn dev "你好"` 到控制台输出：

1. `tsx src/index.ts` 启动，`process.argv` 拼出用户消息（无参数则用默认句）。
2. `loadRootEnv()` 用 dotenv 读 `apps/.env` 到 `process.env`。
3. `envSchema.parse(process.env)` 校验 `MINIMAX_API_KEY` / `MINIMAX_BASE_URL` / `MINIMAX_MODEL`。
4. `new OpenAI({ apiKey, baseURL })` 创建客户端（实际发往 MiniMax 国内 `api.minimaxi.com/v1`）。
5. `chat.completions.create({ messages, stream: true, stream_options: { include_usage: true } })` 发起流式请求。
6. `for await (const chunk of stream)` 取 `choices[0].delta.content` 写入 stdout。
7. 流结束后打印 `usage`（prompt / completion / total），或提示去 MiniMax 控制台查账单。

关键符号：`loadRootEnv()`、`envSchema`、`main()`。对照入口：`index-anthropic.ts` 用同一把 Key，走 Messages API + `/anthropic`。
