# **密钥安全**：泄露后第一件事是 rotate，不是只改 `.gitignore`

> 对应模块：[模块 00 · 环境准备](./README.md) · 小节进度第 3 条

- **来源**：本对话（陪跑 Coach）；无外部 URL
- **状态**：已沉淀

### 是什么

密钥、模型名、Base URL **不写死在代码里**。写死再 push，等于把家门钥匙拍照发朋友圈。本仓库约定三份文件各司其职：

| 文件 | 放什么 | 进 git 吗 |
|------|--------|-----------|
| `apps/.env` | 真实 Key 和运行时配置 | **不进** |
| `apps/.env.example` | 只列变量名，不填真实值 | 进（给别人看「要配哪些名字」） |
| 各 `apps/*/src/` | 业务代码，用 dotenv 指向 `apps/.env` | 进（不含 Key） |

五个学习用的子项目 **共用一份** `apps/.env`，不是每个 app 抽屉里各放一把真钥匙。加载时用 `import.meta.url` 从当前文件位置反推 `apps/`（`load-root-env.ts`），**不依赖 `process.cwd()`**——你从仓库根、`apps/` 还是子项目里启动，工作目录会变，文件在磁盘上的位置不会变。

**泄露后的第一件事是 rotate**：到控制台作废旧 Key、发一把新的、改本地 `.env`。只改 `.gitignore`，已经 push 上去的 Git 历史里那串字符还有效，扫描机器人仍能用。

Zod 在启动期 `parse(process.env)`：Key 空、URL 不是合法网址，立刻退出并打印中文错误，而不是等 MiniMax 返回 401 才知道没配。

### 为什么（Agent 开发要懂）

公开仓库里的 API Key 会被自动扫描（GitHub Secret Scanning 一类）。几分钟内就有人拿去跑任务，额度被刷光。Agent 后面会接工具、会写文件、会打外部 API，Key 的权限越大，泄露的损失越大。

模块 00 就把落点钉死：后面四个 app **复制**同一套 `load-root-env.ts`，避免「这个项目忘了加 gitignore」。配置公共化，**代码不抽成共享 npm 包**——学习阶段要能一眼看清每个 app 自己在干什么。

### 易混点

| 容易当成 | 其实是 |
|----------|--------|
| 改了 `.gitignore` 就安全了 | 已经 commit / push 过的历史里 Key 还在。必须 **rotate**，必要时再清历史。 |
| 每个 app 自己一份 `.env` | 5 个项目共用 `apps/.env`。各放一份更容易漏配、漏提交。 |
| 把配置抽成共享 npm 包 | 当时只要配置放公共目录。各 app **复制**加载文件，不建内部 package。 |
| 配置放仓库根 | 根目录留给 README / AGENTS.md / `docs/`；代码配置进 `apps/`。 |
| `process.cwd()` 找 `.env` | `yarn dev` 时 cwd 常常是子项目，找不到 `apps/.env`。 |

### 例子

**1. rotate：门锁换芯，不是把「请勿拍照」贴在门上**

钥匙照片已经发到网上。你在自家门上贴「以后别拍照」——网上那张还开得了门。正确动作：锁芯换掉（控制台作废旧 Key），再给自己一把新钥匙（新 Key 写入 `.env`）。`.gitignore` 是「以后别再拍」；rotate 才是「网上那把立刻失效」。

**2. .env vs .env.example：保险柜 vs 空保险箱说明书**

保险柜里是真钞（`.env`），说明书画了格子「这里放卡号」但不印真卡号（`.env.example`）。把说明书交给 git；真钞留在家里。

**3. 共用一份 apps/.env：一栋楼一个电表，不是每户偷接一根**

五个房间（五个 app）共用楼下电表。各房间再藏一份 Key，总有一间会忘关灯、会把纸条贴出去。改一处 `apps/.env`，全楼跟上。

**4. load-root-env：按门牌找家，不按「我现在站在哪条街」**

`process.cwd()` 像「我现在站在哪」——你在子项目目录里启动，街名变了，找不到 `apps/.env`。`import.meta.url` 像「这张地图印在这栋楼的哪一层」：从源文件位置往上走到 `apps/`，再读 `.env`。无论从仓库根还是子项目启动，家还在原处。

**5. Zod 守门：出门前摸口袋，不是到机场才发现没带护照**

Key 空着，Zod 在启动瞬间喊停（中文报错）。若等到 MiniMax 401，你已经排了网络、排了 SDK，误诊成本高。前端类比：表单提交前校验必填，不是等服务器 400。

**6. 硬编码进 index.ts 再 push：把钥匙焊在大门上并直播**

扫描机器人几分钟内能把焊上的钥匙拆走去刷额度。对：Key 只出现在 `apps/.env`。

### 我追问过的

- 问了：模型配置放到公共地方，没必要每个项目拷一份 → 答在「是什么 / 取舍」：落点是 `apps/.env`，不是每个子项目一份。
- 问了：只是把配置放到公共地方，不是把代码抽出来 → 答在「易混点」：不建共享包；新建 app 时**复制** `load-root-env.ts`。
- 问了：`.env` / `.env.example` / `tsconfig.base.json` 不要放仓库根，放到 `apps` → 答在「是什么」：代码配置进 `apps/`。

### 取舍

- **配置放 `apps/`**：5 个 app 共用 Key，改一处即可；子项目只写业务。
- **不抽共享包**：复制约 20 行加载文件，比维护一个内部 package 更适合这个学习仓库。
- 多环境（本地 / 预发 / 生产）以后用不同 env 或 CI 密钥；模块 00 先保证「本地一份、不进 git」。

### 踩坑

- 错：把 Key 硬编码进 `index.ts` 再 push 公开仓库 → 几分钟内被扫走并跑爆额度。 / 对：只出现在 `apps/.env`。
- 错：推上去之后只改 `.gitignore` → 历史里的 Key 仍然有效。 / 对：第一件事 rotate，再考虑清历史。
- 错：用 `process.cwd()` 找 `.env` → `yarn dev` 时 cwd 是子项目。 / 对：`import.meta.url` 反推。

### 过关自检

- Key 放 `apps/.env`，不进 git；`.env.example` 只列名字。
- 已经推上去了，第一件事是 **rotate**（作废旧 Key、换新 Key），不是只改 `.gitignore`。
