# **API Key / 计费**：按 Token 计费，输入 / 输出分开；订阅 Key ≠ 按量 API Key

> 对应模块：[模块 00 · 环境准备](./README.md) · 小节进度第 1 条

- **来源**：本对话（陪跑 Coach）· 按模块 01 前四篇文风扩写；无外部 URL
- **状态**：已沉淀

### 是什么

调云端大模型，账单按 **Token** 算，不是按「你点了几次发送」。Token 本身是什么（词表里的整数 ID、中文为什么更碎）在 [模块 01 · Token](../01-AI与LLM基础认知/02-Token.md)。本条只把**钱怎么扣、Key 怎么分**钉死。

一次请求通常拆成两截，单价往往也不一样：

| 字段 | 人话 | 谁在花 |
|------|------|--------|
| `prompt_tokens` | 你送进去的：系统说明、用户话、以后还会有的历史 / 工具结果 | 输入单价 |
| `completion_tokens` | 模型吐出来的字 | 输出单价（通常更贵） |
| `total_tokens` | 上面两段相加 | 这一次请求的计费单位 |

**两把 Key 不是同一把。** 同一家公司网页能聊、控制台也能发一把「密钥」，很容易抄错：

- **网页订阅 Key**（ChatGPT Plus、Token Plan 一类）：给**网页产品**用的套餐凭证，像健身房月卡，刷的是门禁。
- **按量 API Key**（控制台里的「接口密钥」）：给**代码调 HTTP API** 用，按 Token 从余额里扣，像水电表。

抄错了，表现是 401 / 鉴权失败，看起来像 SDK 写错，其实是拿月卡去插电表。本仓库模块 00 用的是 MiniMax **按量 API Key**，控制台、API、账单都走**国内站**。

**国内站和海外站也不是同一扇门。** 国内默认 `api.minimaxi.com`；海外常见 `*.minimax.io`。域名写错会连错环境或直接失败，不是「模型名填错了那么简单」。

### 为什么（Agent 开发要懂）

Agent 从第一天就要盯用量。后面多轮对话把历史塞进 prompt、Tool 来回、RAG 把检索片段贴进去，**输入会暴涨**；模型一边想一边写，**输出通常比输入贵**。不知道这次请求花了多少、不知道去哪看账号花费，后面会突然烧钱还查不到是哪一次。

ChatGPT Mini 流结束后打印 `usage`，就是把「这一枪打了多少发」钉在终端上。对不上，再去 [MiniMax 控制台](https://platform.minimaxi.com) 看账单。流式最后一包不一定带 `usage`（看厂商支不支持 `stream_options.include_usage`）；没有数字时，**控制台才是准的**。

模块 00 只验证链路：能发、能流、能看到用量。不在第一周比三家价格。

### 易混点

| 容易当成 | 其实是 |
|----------|--------|
| 网页能聊天 = 代码能调 API | 会员 Key ≠ 按量接口密钥。能进网页 ≠ `yarn dev` 能过鉴权。 |
| Token Plan 订阅 Key | 填进 `MINIMAX_API_KEY` 会 401，不是 `baseURL` 写错。 |
| 「发一条消息 = 收一次固定费」 | 按这条消息里的 Token 数算；同样意思中文通常件数更多（→ Token 那条）。 |
| 国内站 / 海外站同一把环境 | 国内 `api.minimaxi.com`，海外 `*.minimax.io`。抄错域名 = 进错店。 |
| 终端里自己估的「大概几个字」= 账单 | 对账只信 API 的 `usage` 或控制台；心里估字数不算数。 |
| 账号注册了三家 = 模块 00 要接三家 | 代码本模块只接 MiniMax 协议 A；智谱留模块 02。 |

### 例子

**1. Token 计费：出租车按公里，不按「上了几回车」**

你打了三回车，一回 200 米、一回 20 公里。收费看里程，不看「三次」。LLM 看 Token 条数，不看「点了三次发送」。Agent 后面循环十步，就是十段「边开边跳表」，输出那段往往更贵。

**2. 输入 vs 输出：进货过一次地磅 vs 每扫一件再响一声**

超市进货：整车开进大门，过一次地磅（prompt）。收银员每扫出一个商品再响一声（completion）。吐每一个 Token 都要再跑一轮生成，所以输出单价常常更高。终端里那两行 `prompt_tokens` / `completion_tokens` 就是地磅和扫码枪。

**3. 订阅 Key vs 按量 Key：健身房月卡 vs 电表**

月卡刷开门禁，进去跑步不另计步。电表是用一度扣一度。把月卡号填进电表接口，闸门会拒绝，不是跑步姿势不对。Token Plan 的订阅 Key 进 `MINIMAX_API_KEY`，就是这个。

**4. 国内站 vs 海外站：同一品牌两家店**

门口牌子都叫 MiniMax，一家在国内街、一家在海外街。菜单、收银、会员卡不通用。代码里 `baseURL` 写成 `api.minimax.io`，等于开车去了海外店，国内控制台的账对不上，或请求直接失败。本仓库默认国内：`https://api.minimaxi.com/v1`。

**5. usage 和小票：口袋心算 vs 收银台扫描枪**

跑 `yarn dev "你好"`，流结束后类似：

```text
prompt_tokens: …      ← 你送进去的
completion_tokens: …  ← 模型吐出来的
total_tokens: …
```

这是这趟车的小票。流里没带数字，就去控制台看总账。不要用「你好就两个字」去对账——Token 不是按字数切的（细节在模块 01）。

**6. 前端：一次 fetch 的 request + response 都算流量套餐**

不是「请求免费、响应才计费」那么干净；prompt 和 completion 都是 Token。像手机流量：上传下载都扣套餐，只是单价可能不同。

### 我追问过的

- 问了：默认用中国区、现在用 MiniMax、后面还有 GLM → 答在「取舍」：模块 00 只接 MiniMax 按量 Key；智谱放到模块 02。中国区控制台 / API / 账单走国内站，不要写成海外 `*.minimax.io`。
- 问了：配置放到公共地方，但不要抽共享包 → 答在「取舍」和 [密钥安全](./03-密钥安全.md)：Key 集中在 `apps/.env`，代码仍在各 app 里。

### 取舍

- **先盯一家的用量，不在第一周比三家价格。** 模块 00 只验证链路通不通。账号可以三家都注册 ≠ 代码要三家都接上。
- **对账**：以 API 回传的 `usage` 和控制台为准。本地 tokenizer 数 Token 是模块 01 的估窗 / 截断，不能当账单。

### 踩坑

- 错：把 Token Plan 订阅 Key 填进 `MINIMAX_API_KEY` → 鉴权失败。 / 对：按量计费用「接口密钥」。
- 错：Base URL 写成 `api.minimax.io` → 连海外站或直接失败。 / 对：国内 `https://api.minimaxi.com/v1`。
- 错：Key 写进代码再推公开仓库 → 几分钟内被扫走、额度被刷。 / 对：只放 `apps/.env`，泄露先 rotate（见 [密钥安全](./03-密钥安全.md)）。
- 错：拿字数心里估去对账。 / 对：信 `usage` 或控制台。

### 过关自检

- 云端模型按 Token 计费，输入（`prompt_tokens`）和输出（`completion_tokens`）分开算，输出通常更贵。
- 网页订阅 Key 和按量 API Key 不是同一把，混用会鉴权失败，不是代码写错。
- 用量看请求里的 `usage`；对不上或流里没带 usage，去控制台看账单。
