### 一句话讲完这个模块

Agent 能执行真实操作 = 攻击面比传统聊天机器人放大一个数量级——本模块三条覆盖三类防线：Prompt Injection 防「外部数据变指令」、SSRF / Sandbox 防「服务器被骗去请求或执行不该做」、Tool Gateway / OAuth 防「身份与权限失守」。三道防线叠起来 = 让 Agent 在生产里能安全代用户做事。

### 这些条怎么连成一条线

本模块三条外部小节不是平行清单，而是**一根根因 + 两条危险面 + 一道统一防线**：

```
              ┌──────────────────────────────────────┐
              │   根因：LLM 不分「数据」与「指令」      │
              │   （所有外部文本都可能变指令）          │
              └────────────────┬─────────────────────┘
                               │
        ┌──────────────────────┼──────────────────────┐
        │                      │                      │
┌───────▼────────┐    ┌────────▼────────┐    ┌────────▼────────┐
│ 01 Prompt       │    │ 02 SSRF/Sandbox │    │ 03 Tool Gateway │
│ Injection       │    │ （真发请求+真跑代码│    │ / OAuth          │
│ （数据变指令）  │    │  的具体危险面）   │    │ （统一防线）     │
│ 直接/间接/Tool  │    │ SSRF=服务器被骗请 │    │ 身份分离+Scope  │
│ Injection 三种 │    │ Sandbox=服务器被骗│    │ 最小化+审计+OBO  │
└────────────────┘    │  执行             │    └─────────────────┘
                      └──────────────────┘
```

- **01 是根因**：LLM 架构上把数据和指令混在一起 → 所有外部内容（用户输入 / RAG / Tool 返回 / 多模态）都可能变指令。**这一条没解决，下游两条永远有漏洞**。
- **02 是两条具体危险面**：当 Agent 真的能发网络请求（SSRF）和真的能跑代码（Sandbox）时，根因就变成具体的高危入口——服务器被骗去访问内网 / 跑任意代码。
- **03 是统一防线**：所有 Tool 调用必须经 Gateway 做身份 + 权限 + Token 转换 + 审计；OAuth OBO 流让用户身份与 Agent 身份正确分离。**这是把根因和危险面一起治理的执行层**。

三者的关系不是替代，而是**层层堆叠**——01 让你知道为什么攻击会发生；02 让你知道真发请求 + 真跑代码时具体防什么；03 让你知道怎么在执行层把 01 和 02 一起拦住。

### 最容易记错的三条

1. **Prompt Injection vs Jailbreak**——前者让外部数据变指令（架构问题，靠数据 / 指令分离）；后者突破模型内置安全策略（对齐问题，靠训练 / 对齐）。**防御方向完全不同**——把 Jailbreak 防御（更严格对齐）当 Injection 解 = 投毒外部文档照样攻击成功。
2. **Token 转发 vs OBO 流**——前者直接把用户 token 给下游（不安全，Agent 拿到用户能调的所有权限）；后者用 Agent 身份 + 用户授权换新 token（安全，scope 受限）。把 Token 转发当 OBO = **Agent 越权**。
3. **Sandbox vs Container**——Sandbox 是隔离策略的统称（chroot / namespaces / cgroups / seccomp / Firecracker / VM）；Container 是沙箱的一种实现。**Docker 默认共享宿主内核不算「沙箱化」**——容器逃逸是有名漏洞，高安全场景要走 gVisor / Firecracker / VM。

### 踩过的坑（跨小节）

写到这里，本对话未踩到具体代码坑（无 Demo 落地）。记录两条**预防性踩坑**：

- **「上帝 Key 陷阱」**：用长期有效 + 全权限 API Key 调所有 Tool → 一次泄露 = 全权限失守。**判错代价**：Key 被印在日志 / 提交到 Git → 攻击者拿到后给所有用户退款。模块 03「核心概念 1」专门拉出一节提醒；做真实项目时每次给 Agent 配 API Key，先问一句「这是 scope 限定的 OAuth Token 还是上帝 Key」。
- **「Token 直接转发」**：Agent 把用户 access_token 直接传给下游 Tool → 用户能调的所有 Tool，Agent 也能调。**判错代价**：用户 token scope 是 `email.send`，但 Agent 拿到后能调任何 Tool。模块 03「易混点 · Token 转发 vs OBO 流」专门拉出一组对比；做真实项目时每次 Tool 调用前先确认 token 是 OBO 流换出的新 token，不是直接转发的用户 token。
