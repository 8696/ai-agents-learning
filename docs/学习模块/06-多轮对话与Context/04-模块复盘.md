### 一句话讲完这个模块

理解「**模型为什么会忘记，以及如何给模型正确的上下文**」——本模块解决三件事：① 这桌菜（Context）跟抽屉里的小卡片（Memory）分清；② 桌子摆不下怎么裁（滑动窗口 vs 摘要压缩）；③ 裁之前先算账（Token Budget + 软硬双层 + 选择性注入）。

### 这些条怎么连成一条线

| 条 | 它解决什么 | 跟前后条的关系 |
| -- | --------- | -------------- |
| **01 Context vs Memory** | **先分清边界**——两件事用两套机制 | 是 02 / 03 的**前提**：不知道什么能裁 / 什么不能塞，02 / 03 全错 |
| **02 压缩/摘要 vs 滑动窗口** | **两条裁剪策略对比**——丢字面 vs 留语义 | 是 03 的**机制基础**：03 在 02 之上加预算 + 触发判定 |
| **03 Token Budget** | **裁之前先算账 + 选择性注入**——三块分账 + 软硬双层 | 是 02 的**工程化**：把"裁"变成有阈值、有兜底、有选择的系统 |

三步递进：**01 分类 → 02 机制 → 03 工程化**。

- 01 错 → 02 / 03 全错（混了 Context / Memory → 浪费 token + 漏信息）
- 02 没学 → 03 没法选（不知道 trim / summarize 谁好）
- 03 没学 → 02 的"裁"没闸门（救不回来就崩）

模块复盘 = 把这三刀连成一条线：**分清 → 会裁 → 裁得稳**。

### 最容易记错的三条（跨条易混）

1. **Context ≠ Memory**——Context 是「这桌菜」（本次请求 messages 数组），Memory 是「小卡片」（跨会话持久化）。02 / 03 全在 Context 里裁；**不要**把对话历史写进 Memory（混了浪费 token + 漏信息 + 改主意时"幽灵"信息残留）。
2. **"裁剪" ≠ "写 Memory"**——context 装不下时的正确做法是「摘要 / 滑动窗口」（02），**不是**"存到数据库下次调出来"（属于 Memory 路径，详 01 易混点 #3）。常见误判："context 太长 → 写 Memory" → 错；应该是"context 太长 → 裁剪"。
3. **软阈值 ≠ 硬阈值**——软阈值是"选 trim 或 summarize 救到 fit"（**可超**，但要救）；硬阈值是"救不回来就放弃 history 保命"（**不可超**，直接砍到 3 条 messages）。**两条目的不同**：软阈值"能救就救"，硬阈值"救不回来保服务不崩"。Zod 闸门 `hardLimit ≥ outputBudget + 32` 是防"配错死循环"的安全护栏，**不是**业务逻辑。

### 踩过的坑（跨条）

- **logger.ts 顶层只是模板**（01 + 03 都遇）—— 每个 demo 必须完整拷 `lib/logger.ts`；**禁止** `import apps/logger.ts` / 委托顶层；路径必须 `path.resolve(__dirname, "..", "logs")`（**禁止** `new URL("./logs/", import.meta.url)` 落到 `lib/logs/`）；入口必须 `appendFileSync` 写文件 + 五件套（开始/入参/`__code`/返回值/结束）+ `耗时ms`。详 [§5.3.16](agents/05-demo.md) + [AGENTS.md §5.6](AGENTS.md)。
- **KEY_FACT substring 检测**（02 + 03 通用）—— 第一版 substring `["Tina","上海","日料"]` 被反例"你常问上海天气"误判 ✅；必须加**肯定句式**（`你叫 Tina` / `你住在上海`）+ **否定标记**（`未提及` / `不能据此推断`）排除反例。三轮迭代才稳。
- **JSX 字段名含连字符**（03-step-2）—— `result.对-比小结` → JSX 解析时把"对-比小结"当表达式（`对 - 比小结 = ...`），`比小结` 当未定义变量 → ReferenceError，整页白屏。**修法**：字段名不要含连字符；改成 `对比小结`（与 API 出参字段名一致）。
- **Edit 不可见字符**（03 修 log 时）—— `old_string` 含不可见字符差异（编码 / 换行）导致替换失败。**修法**：用 `python3` 脚本做 `str.replace` 更稳。
- **用户可见文案中文化**（全模块）—— 关键英文术语（`trim` / `summarize` / `historyCount` / `hasKeyFact` / `budget` 等）必须用括号附在中文后面：`Token 预算（Token Budget）` / `历史对话轮数（historyCount · 每轮 = 1 条 user + 1 条 assistant）`。JS 变量名 / API 字段名 / CSS className / HTML id **不动**。
- **核心教学点卡片**（03 全 step）—— 之前页面只有"步骤说明"，没有"这一页要让人带走什么"。**修法**：在 `#page-intro` 段内加 `#core-takeaway` 卡片（黄底），写"核心结论 + 怎么观察"两段。详 [§5.3.11.b](agents/05-demo.md)。
- **数据流不能"事后补救"**（03 全 step）—— 必须在拼装 messages 之前**主动**算账（`estimateBudget()` 返回 `beforeBudget/afterBudget` + `dropped`），不能等 API 400 再补救。`#output` 渲染完整 messages + 每段 token 数才能调试。
