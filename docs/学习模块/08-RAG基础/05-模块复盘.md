### 一句话讲完这个模块

模块 08 RAG 基础解决的是**让 Agent 用上它训练时没见过的外部知识**。办法是：把外部文档切成小卡片 → 用嵌入模型把每张卡片和用户的提问都变成向量 → 按方向远近挑出最像的几条 → 把这几条带出处塞进提示词 → 让大模型按材料说话。**改文档就改库，不改模型权重（Weights）**，下一问就按新的答。检索做成的不是写死的流水线，而是 Agent 自己决定要不要调的"工具（Tool）"。

**三条跨条铁律（按条笔记各自看不到）**：

1. **第 1 条 + 第 2 条 = "切块带着章节路径"这条铁律的左半 + 右半**：第 1 条讲"必须切 + 来源不能丢"，第 2 条讲"标题继承让代词断裂的块能被搜到"。合起来——**「切块带着章节路径」= 来源字段（运营可删）+ 章节路径（向量方向可搜），缺一就废**。
2. **第 1 条 + 第 3 条 = "Top-K 单独不能当有答案"这条铁律**：第 1 条讲 Top-K + 相似度分数，第 3 条讲 Top-K 永远能取满、阈值跟着模型走。合起来——**Top-K 不是答案，是候选；阈值才是「够不够格喂模型」的判官；换嵌入模型必须重标定阈值**。
3. **第 1 条 + 第 4 条 = "三件事各管各的"这条铁律**：第 1 条把 RAG 画成"外挂可更新知识"，第 4 条把它和提示词 / 少样本 / 微调分开。合起来——**system + 少样本 → 习惯 / 口吻；RAG → 事实 / 出处；微调 → 深度领域反应**。知识放库里、口吻放 system、深度反应才动权重——三件事各管各的。

**硬币的两面 / 兜底关系**：

- 第 2 条"切块坏了救不回来"（碎句 / 代词丢主语）↔ 第 3 条"尺子选错救不回来"（长块被点积顶到第一）——**两条都是"前一环错了后面只能擦屁股"**。
- 第 1 条"检索做成工具（Tool）" ↔ 第 4 条"闲聊不该检索"——同一个"该不该检索"在两条里分别答"代码上怎么实现"和"选型上怎么判断"。
- 第 1 条"建库三步只在文档变更时跑" ↔ 第 2 条"改切块策略 = 整库重切 + 重嵌入（全量）"——**同一句话的两面：行级 vs 全量的频率分层**。

### 最容易记错的三条

#### 1. RAG = 长上下文优化版（把根因和实现效果混了）

- **真**：RAG 的存在根因 = **喂模型它训练时根本没见过的知识**（私有知识 / 训练截止之后）。省 token / 加快 / 准 是这根因实现后**顺便**得到的副产品，不是它独有的。RAG 相对长上下文真正独有的优势是**能点名出处**（出处 = 可追责、可更新、能拒绝编造）——长上下文答对了你也说不清它看了哪段。
- **错**：把 RAG 当成"上下文窗口省着用"的优化版 → 关注 token 数和检索速度 → 丢了**追责 / 出处 / 更新**这些独有价值。
- **跨条**：第 1 条 RAG 为什么存在（变体 16/17）+ 第 4 条「要引用 → RAG」（变体 2）合起来才是这层判断——法务要出处时，即使政策两年没改仍选 RAG，因为它能挂出"哪一篇 / 哪一段"。
- **判错会怎样**：把"省 token"当根因 → 把它做成"上下文窗口省着用" → 手册过期客服答错 / 出了错对质不了文档。

#### 2. Top-K ≠ 有答案 + 阈值 ≠ 世界通用

- **真**：Top-K 永远能取满——库里 3 条就给你 3 条，哪怕全是 0.12。**Top-K 不是答案，是候选**。要判定"够不够格喂模型"必须配**阈值**，阈值是产品线（跟着模型走），**不是**全世界通用的 0.5 / 0.3 / 0.7。`0.82` 不是 82% 正确，是"夹角比较小"。
- **错**：拿到 3 条就觉得有答案 → 把 0.82 当 82% 门禁 → 把 A 模型的 0.5 阈值直接抄到 B 模型。
- **跨条**：第 1 条变体 11（Top-K 永远能取满）+ 第 3 条变体 10（最高分也低 = 几何上"库里没有"）+ 第 3 条变体 11（分数不是概率 / 不能跨模型比）合起来才是这层判断。
- **判错会怎样**：库里 3 条无关卡片都 0.1，你以为有答案 → 模型按三张不沾边材料编一份"非常官方的折扣码" → **凭空给一个听上去合理但没依据的回答**。最危险的不是"答错"，是"答得像对"。

#### 3. 「换 X vs 换 Y」四种"换"混在一起

RAG 流水线里**四种完全不同的"换"**，判错后果完全不同：

| 操作 | 是什么 | 库 / 权重会怎样 | 重建？ |
| ---- | ------ | --------------- | ------ |
| **换聊天模型**（同家换 id） | 换回答风格 | 库不动 | 不用重建 |
| **换嵌入模型**（换家或换 id） | 换嵌入坐标系 | **旧库作废** | **必须整库重嵌入** |
| **改切块策略**（size / overlap / 切法） | 换切块粒度 | 旧切块粒度与新嵌入对不上 | **必须整库重切 + 重嵌入** |
| **微调**（Fine-tuning） | 改权重里的口吻 / 习惯 | 权重永久变化，**删不掉** | 不涉及库；但混进知识就拔不出 |

- **错**：把"换聊天"等同于"换嵌入"（不重建库，提问对不上）→ 把"改切块策略"等同于"文档变更"（行级删旧+insert，结果漏 insert）→ 把"微调"等同于"加几行 system"（动权重做了 system 能做的事，浪费 + 删不掉）。
- **跨条**：第 1 条变体 18/19（聊天 vs 嵌入是两套 id）+ 第 1 条维护期频率表（行级 vs 全量）+ 第 2 条改切块策略（变体 4）+ 第 4 条三件事各管各的 + 第 4 条隐私（变体 11，进权重当删不掉）——五条笔记各自的某一段，合起来才是这一层。
- **判错会怎样**：换 LLM_PROVIDER 不重建库 → 提问对不上 → 以为检索坏了；改 size 不重建 → 旧嵌入坐标系下的切块和新切块混在一起 → 分数乱跳；把手册当微调数据 → 一改政策 → 模型还在背旧的 → 还指不出出处。

### 踩过的坑（跨条）

跨条才能产生的踩坑——单条笔记里能看到的不列。

#### 1. 四种"换"分不清，库 + 模型 + 权重一起乱

- **真**：四种"换"里每一种的"重建范围"完全不同——换聊天模型（库不动）/ 换嵌入模型（整库重嵌入）/ 改切块策略（整库重切 + 重嵌入）/ 微调（Fine-tuning，永久改权重，知识混进去就拔不出）。
- **错**：换 `LLM_PROVIDER` 以为只是换聊天 → 嵌入坐标系也变了 → 检索对不上 → 以为是检索坏了；改 size / overlap → 忘了整库重切 → 旧嵌入坐标系下的切块和新切块混在一起 → 分数乱跳；把 `LLM_MODEL` 填进 `LLM_EMBEDDING_MODEL` 槽 → 库建失败；把手册当微调数据 → 政策一改 → 模型还在背旧的 → 还指不出出处。
- **跨条**：第 1 条变体 18/19（聊天 vs 嵌入是两套 id）+ 第 1 条维护期频率表（行级 vs 全量）+ 第 2 条改切块策略（变体 4 "改切块 = 全量重建"）+ 第 4 条三件事各管各的 + 第 4 条隐私（变体 11，进权重当删不掉）——五条笔记各自的某一段，合起来才看清"换什么决定重建什么"。
- **判错会怎样**：最危险的不是检索慢或答错，是**花了很多钱重建完发现建错了**——或**花了 GPU + 数据 + 训练费把知识写进权重，文档一改模型还在背旧的**。

#### 2. "省 token / 加快 / 准" 当 RAG 根因

- **真**：RAG 的存在根因 = **喂模型它训练时没见过的知识**。"省 token / 加快 / 准" 是根因实现后**顺便**得到的副产品。RAG 相对长上下文真正的独家优势是**能点名出处**（出处 = 可追责、可更新、能拒绝编造）。
- **错**：把 RAG 当成"上下文窗口省着用"的优化版 → 把精力花在省 token 上 → 忘了出处和追责 → 法务问依据对质不了文档。
- **跨条**：第 1 条 RAG 为什么存在（变体 16/17）+ 第 4 条「要引用 → RAG」（变体 2）合起来才是这层判断。
- **判错会怎样**：客服按过期政策答应客户；答错后你只能说"模型是这么说的"，拿不出"哪一篇 / 哪一段"——长期变成"模型说了算"。

#### 3. Top-K 永远能取满 / 阈值 0.5 不是世界标准

- **真**：Top-K 永远能取满——库里 3 条就给你 3 条，哪怕全是 0.12。Top-K 不是答案，是候选。要判定"够不够格喂模型"必须配阈值。阈值跟着嵌入模型走，不是世界通用 0.5 / 0.3 / 0.7。`0.82` 不是 82% 正确。
- **错**：拿到 Top-K 几条觉得"有答案了" → 把 A 模型调试出的 0.5 阈值直接抄到 B 模型 → 弃权全乱 / 该弃不弃 / 该答不敢答。
- **跨条**：第 1 条变体 11（Top-K 永远能取满）+ 第 3 条变体 10（最高分也低 = 几何上"库里没有"）+ 第 3 条变体 11（分数不是概率 / 不能跨模型比）合起来才是这层判断。
- **判错会怎样**：库里 3 条无关卡片都 0.1 → 模型按三张不沾边材料编一份"非常官方的折扣码" → **凭空给一个听上去合理但没依据的回答**——比硬编更危险，听上去像对。

#### 4. 扫描件空正文 + 表格 / 代码块 / 编号条款切断

- **真**：两种"看着成功但实际是错的"——(1) 解析器报成功但抽出来是空字符串或乱码（扫描版 PDF / 纯图片页）；(2) 切块切坏了表格 / 代码块 / 编号条款（Markdown 表格被切在中间 / 代码块括号不闭合 / "第三条"和它的内容分家）。
- **错**：扫描件空正文 → 解析器说成功就当成"低分卡片"入库 → 检索时命中这种垃圾卡片 → 模型按材料说话 = 按空字符串说话；表格数据行 + 表头分家 → 模型不知道每列什么意思 → 答错。
- **跨条**：第 1 条变体 3（加载失败，含扫描件空正文）+ 第 2 条变体 14（不能腰斩的结构）+ 第 2 条变体 12（递归切分，结构优先 + 按字数切兜底）。
- **判错会怎样**："西藏运费"那一章明明在手册里却总排不上（其实是空正文入库），或发票条款被切断后模型说"按您提供的材料无法判断税率"——客服不知道是**切块切坏了**，在提示词上反复调，问题永远在那里。

#### 5. 凭空给一个听上去合理但没依据的回答 vs 直接弃权

- **真**：system 该给"找不到时怎么办"的指令——任何 RAG 项目的 system 都该包含「找不到就说"库里没有这条信息，我不能编"」。模型自带克制但仍会绕过『不知道』给一个看似合理但没依据的回答："找不到"不等于"编一份看似合理的"，也不等于"给一堆无据可查的'试试 HR / 看看内网'建议"。
- **错**：system 只写"你是售后客服助手" → 库里没有折扣码 → 模型答"建议咨询 HR 或查看公司内网"——这是**凭空给一个听上去合理但没依据的回答**，不是硬编（没编具体折扣码），但滑过"不知道"那条线给一个看似合理但无据可查的回答。
- **跨条**：第 4 条 step-3（左无指令 vs 右含指令）+ 第 1 条变体 11（库里没有 → 弃权通道）+ 第 3 条变体 10（几何上"库里没有"的判定）合起来才是"找不到时该怎么办"的全图。
- **判错会怎样**：业务问从没入库的"隐藏折扣"——检索侧能空命中后说不知道，"不接 RAG（model only）"侧给"问 HR / 看看内网 / 问上级"——把灰色地带当答案，业务用了照样出事。
