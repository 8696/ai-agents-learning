## 是什么

**余弦相似度（Cosine Similarity）= 两条向量夹角的余弦。** 它只量「朝哪边」，不量「箭头有多长」。

嵌入模型（Embedding Model）给每段文字吐出一串实数，就是一条向量（Vector）。第 1 条里，建库时每张切块（Chunk）一条，提问时用户那句话再算一条。检索要问的是：这两条箭头**方向近不近**。

公式用人话：

```text
余弦 = 点积 / (A 的长度 × B 的长度)
```

- **点积（Dot Product）**：对应位相乘再相加。`[1, 2]` 和 `[3, 4]` → `1×3 + 2×4 = 11`
- **长度 / 模（Magnitude / Norm）**：这条箭头有多长。`[3, 4]` 的长度是 `5`
- **除以两个长度**：把「有多长」抹掉，只留下「朝哪边」

取值 **-1 到 1**：

| 几何 | 夹角 | 余弦 | 语义上像什么 |
| ---- | ---- | ---- | ------------ |
| 同向 | 接近 0° | 接近 **1** | 很像（「杯子裂了」vs「运输破损」） |
| 正交 | 接近 90° | 接近 **0** | 基本无关（「杯子裂了」vs「发票抬头」） |
| 反向 | 接近 180° | 接近 **-1** | 对着干（几何上存在；真实嵌入里很少到 -1，见变体 8） |

**一句话（进度表要能讲清的）**：语义近 = 两条向量夹角小 = 余弦高。**不是**「数字更大 / 向量更长 / 两点直线距离更近」。

### 核心对象

| 核心对象 | 管什么 |
| -------- | ------ |
| **方向（Direction）** | 语义写在这里 |
| **长度 / 模（Magnitude）** | 在嵌入空间里常常只是「这段字更多 / 数值尺度」，不是「更重要」 |
| **余弦相似度** | 只看夹角的尺子 |
| **另外两把尺子** | 点积不除长度；欧氏距离（Euclidean Distance）看两点有多远 |
| **分数怎么用** | 排序取前 K 条（Top-K）、阈值（Threshold）弃权、不能当正确率 |

## 数据怎么走：六条二维箭头

真模型是几百到几千维，人眼看不见。二维只为拆开方向和长度。数字是手写教学坐标，不是嵌入模型吐的。

问题向量 `Q = [1, 0]`（水平向右，长度 1）

| 卡片 | 向量 | 假装的含义 | 点积 | 长度 | 余弦 | 欧氏距离 |
| ---- | ---- | ---------- | ---- | ---- | ---- | -------- |
| 短卡片 S | `[1, 0]` | 「破损可补发或退货」一句话 | 1 | 1 | **1.00** | **0** |
| 长卡片 L | `[10, 0]` | 同一句 + 拉长免责 | **10** | 10 | **1.00** | **9** |
| 略偏卡片 S2 | `[0.8, 0.6]` | 「包装完好的商品 7 天无理由退货」 | 0.8 | 1 | **0.80** | 0.63 |
| 近义不同字 SYN | `[0.95, 0.31]` | 「运输途中碎了，可以补发」 | 0.95 | ≈0.9993 | **0.95** | 0.31 |
| 冲突政策 C | `[-0.8, 0.6]` | 「破损一律不退」 | -0.8 | 1 | **-0.80** | 1.79 |
| 无关卡片 F | `[0, 1]` | 「发票默认开个人抬头」 | 0 | 1 | **0.00** | 1.41 |

按**余弦**从高到低：`S = L（并列 1.00） > SYN（0.95） > S2（0.80） > F（0.00） > C（-0.80）`
按**点积**从高到低：`L（10） > S（1） > SYN（0.95） > S2（0.8） > F（0） > C（-0.8）` ← 长卡片赢了
按**欧氏**从低到高（越小越近）：`S（0） > SYN（0.31） > S2（0.63） > F（1.41） > C（1.79） > L（9）` ← 同向的长卡片最远

```text
                          F [0,1] 无关
                          ↑
                          |     S2 [0.8, 0.6] 略偏
                          |    /
                          |   / SYN [0.95, 0.31] 近义不同字
                          O --------→ S [1,0] 短同向
                          └------------------→ L [10,0] 长同向
                              └→ C [-0.8, 0.6] 冲突政策（反向但不极端）
                                    Q 也在这条轴上
```

step-1 用的就是这组数。三侧分请求，不要理解成一个接口同时跑多套。

### 归一化后会发生什么（page-6 演示）

**L2 向量归一化** = 每个向量除以自己的长度，变成长度 1 的单位向量：

- `S [1, 0] / 1 = [1, 0]`（不变）
- `L [10, 0] / 10 = [1, 0]` ← 跟 S 完全重合
- `SYN [0.95, 0.31] / 0.9993 ≈ [0.9507, 0.3102]`（约不变）
- `C [-0.8, 0.6] / 1 = [-0.8, 0.6]`（不变）

归一化后三尺子对照：

| | 归一化前 | 归一化后 |
| --- | --- | --- |
| S 余弦 / 点积 | 1.0 / 1.0 | 1.0 / 1.0 |
| L 余弦 / 点积 | 1.0 / 10 | 1.0 / 1.0（跟 S 完全重合）|
| 余弦 vs 点积 | 不相等 | **完全相等**（cosine == dot in normalized space）|
| 欧氏 | 0（重合）/ 9（最远）| 0（L 归一化后等于 S）|

「cosine 列 == dot 列（数字一字不差）」 = 验证 L2 归一化是否生效的几何依据。

### scaleFactor 模拟换模型会发生什么（page-4 演示）

**scaleFactor = N** = 所有分数 × N，模拟「换嵌入模型后分数尺度整体变了」：

- cosine ×2 → 1.0 × 2 = 2.0（**越界**！cosine 理论上 ∈ [-1, 1]，2.0 在几何上无意义）→ 演示「分数尺度不属于几何」
- dot ×2 → 10 × 2 = 20（仍 dot，不越界）
- euclidean ×2 → 0 / 9 / ... × 2

阈值是产品线 = 跟着模型走——同一阈值 0.5 在 scaleFactor=1 时三侧全 answer，在 scaleFactor=2 时 cosine 越界（其他尺子仍 answer）。**换模型必须重标定阈值**。

## 为什么（Agent 开发要懂）

第 1 条检索的分数会干三件实事。尺子选错，三件都会歪。

1. **谁进提示词（Prompt）。** 前 K 条按分数排。点积会让长切块、长政策稳定赢；欧氏会让长切块稳定输。用户问「杯子裂了怎么退」，库里同时有一句「运输破损可补发」和一整章《售后服务》，错尺子会把整章塞进去——第 2 条刚讲过，整章是三个主题的折中点，喂进去等于噪音。
2. **「库里没有」怎么判。** 第 1 条弃权看的是最高分够不够用。这个「分」就是本条这把尺子。把 `0.72` 读成「72% 正确」，会在不该答的时候硬答，或在该答的时候弃权。
3. **调参时你在调什么。** 切块变大、换嵌入模型、加重叠（Overlap），页面上的分数都会动。不懂几何，会把「长块分数变了」误判成「切块策略更好了」。其实可能只是长度变了，方向没变。

前端后果：搜索框返回的不是「字面命中」，是「方向最近的 K 张卡片」。你在接口里看到的 `score`，是夹角，不是置信度（Confidence）。

## 各变体（是什么 / 为什么 / 例子揉在一起写）

### 变体 1 · 公式：先乘再抹掉长度

```text
A = [1, 0]     B = [10, 0]
点积 = 10
|A| = 1        |B| = 10
余弦 = 10 / (1×10) = 1
```

除法不是装饰：整把尺子的意义就是把长度约掉。零向量长度为 0，分母是 0，算不了余弦——step-1 对这种入参返回 400。

### 变体 2 · 同向不同长（本条主对照）

S 和 L 方向一模一样，余弦并列第一。语义上它们该并列。这是本条最容易翻车、也必须先看见的一组。

生活：两个人都朝东北走，一个 10 步、一个 1000 步。方向一样，现在站的位置可以差很远。  
前端：两个接口都返回成功，一个多带了 20KB `debug`。语义都是「成功」；按 payload 体积排会把带调试信息的当成更重要。

### 变体 3 · 点积：不除长度，长的赢

点积 = 余弦 × 两个长度。长度一涨，分数就涨。没先归一化就直接点积，等于把「写得长」当成「更相关」。

### 变体 4 · 欧氏距离：量「现在站多远」

S 和 Q 重合，距离 0。L 和 Q 同向但差 9，距离很大，很冤。切块从「一句 FAQ」改成「整节政策」时，用欧氏排序，长块即使方向没变也会掉出前 K 条。

和第 2 条的交接（对照，不换条）：切块变长，**方向**可能被多主题平均掉（太大丢细节），**长度**也会变。本条的尺子解释「长度不该单独决定远近」；切坏了方向本身会漂，那是切块的事，不是换尺子能救的。

### 变体 5 · 先归一化：三把尺子开始说同一种话

**归一化（L2 Normalize）**：每个向量先除以自己的长度，变成长度为 1 的单位向量（Unit Vector）。只保留方向。

之后：余弦 = 点积（分母是 `1×1`）；欧氏距离和余弦变成单调相关：余弦越高，欧氏越小。排序不再打架。

```text
L [10, 0] 归一化 → [1, 0]
S [1,  0] 归一化 → [1, 0]
现在点积、余弦都是 1，欧氏是 0
```

很多向量库的「余弦模式」，内部就是：先归一化，再做点积。页面上仍应标成「余弦分数」，不要写成「点积分数」，避免下次有人关掉归一化。**page-6 已加归一化开关**——`/api/score-normalize` body 带 `normalize: true` 时 `scoreVectors` 先对 query 和每张卡都除以自己的长度。**几何依据**：归一化后 cosine 列 == dot 列（数字一字不差）。

**「归一化」有两种层，都叫 normalize 但不一样**——详见 page-6 #core-takeaway：

| | L2 向量归一化（本页做的） | 分数归一化（min-max / z-score） |
| --- | --- | --- |
| 层 | 向量层（除以自己长度） | 分数层（按比例重排） |
| 例子 | long [10,0] ÷ 10 = [1,0] | [1, 1, 0.95, -0.8] → [1, 1, 0.97, 0] |
| 作用 | cosine == dot（向量库默认） | 跨批次拉到 [0,1] 区间（显示层） |

### 变体 6 · 同向：语义近

夹角小，余弦接近 1。这是检索「命中」的几何含义。余弦 = 1 表示方向完全一样，不一定原文逐字相同。`0.88` 也可能是一句好的同义改写，不是「88 分正确」。

生活：「杯子裂了」和「运输途中碎了」——用词不同，指向同一类售后事件。  
前端：搜索「清空购物车」命中按钮文案「移除全部商品」。

### 变体 7 · 正交：语义无关

夹角约 90°，余弦约 0。不是「反对」，是「两件不同的事」。售后里最常见：问题是破损，卡片是发票 / 积分 / 开票抬头。

### 变体 8 · 反向：几何上有 -1，真实嵌入很少这么极端

`[1, 0]` 和 `[-1, 0]` 余弦 = -1。真实文本里，「可以退」和「一律不退」常常不是 -1，更像「同一售后主题下的两种结论」——方向仍可能中等偏高。

> **负余弦 ≠ 你在业务上认定的「反对意见」。**  
> 「库里没有」不能靠「等一个 -1」。第 1 条的弃权，靠的是最高分够不够用。

**page-5 已加「可退 vs 不退」对照**——`TEACHING_CARDS.conflict` = `[-0.8, 0.6]`，与 query=[1,0] 余弦 = -0.8。**不到 -1**，但比其他所有卡都低。**真实嵌入里反向但很少到 -1**（这是 step-1 选 -0.8 不选 -1 的原因——造 -1 容易，「真实嵌入很少到 -1」的故事在 2D 上讲不清）。

### 变体 9 · 前 K 条：按余弦降序取

检索不是 `WHERE vector = 问题`。第 1 条已经写过：SQL 只是把行读出来，进程里对每一行算余弦，排序，取前 K 条。本条补的几何：**排序键是夹角分数，越大越近。**

```text
0.86  破损补发
0.71  7 天无理由
0.40  破损运费
0.08  发票抬头
K=3 → 前三条进提示词，发票被丢掉
```

step-1 做了全表排序，**page-2 已加 Top-K 截断**——`/api/score-topk` body 带 `k` 时 `scoreVectors` 全表排序后切前 K 进 `topK`、剩下的进 `dropped`。**判定按全表算（不是按 topK 算）**——避免「长同向被 K=1 挤出 topK 后判 long-loses」污染 step-1 的几何对照结论。

### 变体 10 · 阈值：最高分也低 = 几何上「库里没有」

前 K 条永远能取满——库里有 3 条就总能给你 3 条，哪怕全是 `0.12`。所以 **Top-K 单独不能当「有答案」**。

最高分仍接近 0，意思是「最近的那张卡片，夹角也差不多 90°」。这时应弃权，而不是把三张无关卡片喂给模型让它编。

阈值是你们定的产品线，**不是全世界通用的 0.3**。换嵌入模型，同一对文本的分数尺度会变。第 1 条已经禁写「0.25 全球及格」；本条补原因：分数是夹角的函数，夹角怎么被模型摊到 0~1，每家不一样。**page-3 已加阈值开关**——`/api/score-threshold` body 带 `threshold` 时 `scoreVectors` 拿 `topK[0].score = maxScore` 比阈值，输出 `decision: "answer" | "abstain"` + `abstainReason` + `maxScore`。

阈值方向跟尺子有关：余弦/点积 越大越近 → maxScore < threshold 弃权；欧氏 越小越近 → maxScore > threshold 弃权。**page-3 「调高阈值到 1.5」按钮演示**：同一组向量，三侧决策不同——cosine maxScore=1.0 < 1.5 弃权；dot maxScore=10 > 1.5 仍 answer；euclidean maxScore=0 < 1.5 仍 answer。

### 变体 11 · 分数不是概率，也不能跨模型比

`0.82` 不是「82% 会答对」，也不是「82% 是同一句话」。它只是「夹角比较小」。

更不能拿 MiniMax 嵌入上的 0.82，去和智谱嵌入上的 0.82 比谁更准。换模型等于换坐标系，数字不能直接减。运营若要求「低于 80% 不准答」，是在把夹角误读成正确率。**page-4 已加 scaleFactor 开关演示**——`/api/score-cross-model` body 带 `scaleFactor: 2` 时所有分数 ×2：cosine 1.0 → 2.0 越界（演示「分数尺度不属于几何」），dot 10 → 20，euclidean 0/9 → 0/18。

⚠ **跨模型重标定关心 4 件事，本页只覆盖 2 件**：
- ✓ ② 分数尺度变了
- ✓ ③ 阈值要重标定（跟着模型走，不能直接抄）
- ✗ ① 向量值不一样（包括维度可能不同：A 300 维 vs B 768 维）——本页都是 2 维，看不见
- ✗ ④ 分数不能跨模型直接比（真实跨模型是分布形态变了，不是简单倍数）

真跨模型对照 = 真调两家嵌入 SDK（突破 §5.3.0「本地计算是例外」硬规则）——本仓库尚未学到。学到嵌入 SDK 后可以加 page-7「真跨模型对照（双 SDK）」。

### 变体 12 · 余弦距离：越高越远，排序反了会翻车

有的库返回的是**余弦距离（Cosine Distance）** = `1 - 余弦`（有的实现还会再折到 0~2）。

| 名字 | 1 表示什么 | 排序 |
| ---- | ---------- | ---- |
| 余弦相似度 | 最像 | **从大到小** 取 Top-K |
| 余弦距离 | 最不像 | **从小到大** 取 Top-K |

名字里都有「余弦」，接错排序就是把最不像的喂给模型。**page-5 已加距离排序对照**——前端并发三 metric（`/api/score-cross-model`）+ 自算 `1 - cosine`，4 个「正确排序」按钮 + 2 个「错排序」按钮（红框 ❌）。

⚠ **错排序按钮演示的不是 demo 代码错，是业务 bug**：演示的是「代码错把 cosine distance 当 cosine similarity 排序」。后端 `scoreVectors` 永远按正确方向排序，前端展示层故意按错的展示方向再排一遍，让你能看到这种 bug 的输出长什么样（第 1 名变成 conflict / 破损一律不退，业务事故）。下次接向量库看到「第 1 名是最不像那张」→ 立刻检查返回字段是 cosine 还是 cosine distance。

### 变体 13 · 近似最近邻：加速，不改几何（对照第 1 条）

库到百万级，不会每次把全表读进进程再扫。生产用近似最近邻（ANN，Approximate Nearest Neighbor）：先用索引缩小候选，再在候选里算同一把尺子。

**ANN 改的是「找谁来比」的速度和完整性，不改「近 = 夹角小」。** 近似可能漏掉真正最近的一条，分数含义不变。第 1 条 Demo 是全表扫描；本条不实现索引。纯知识变体，不单独逼一个 step。

## 易混点

| 对比 | 差在哪 | 判错会怎样 |
| ---- | ------ | ---------- |
| 余弦 vs 点积 | 余弦除以长度；点积不除 | 长切块、长政策稳定赢，短而准的 FAQ 被压住 |
| 余弦 vs 欧氏 | 余弦看夹角；欧氏看两点距离 | 同义长块被判「远」，从 Top-K 掉出去 |
| 相似度 vs 距离 | 一个越大越好，一个越小越好 | 排序方向反了，把最不像的喂给模型 |
| 分数 vs 正确率 | 夹角函数 ≠ P(答对) | 用 0.8 当 80% 门禁，该弃权不弃、该答不敢答 |
| 同模型阈值 vs 跨模型阈值 | 换嵌入模型 = 换坐标系 | 把 A 模型的 0.3 抄到 B 模型上，弃权全乱 |
| 反向 vs 业务冲突 | -1 是 180°；「可退 / 不退」仍是同一主题 | 等负分来发现冲突政策，永远等不到 |
| 长度 vs 重要性 | 模长常跟文本长短 / 数值尺度有关 | 以为向量长就是「更关键的知识」 |
| 余弦 1 vs 原文相同 | 1 = 方向相同 | 误以为只有复制粘贴才能得 1；或把 0.9 当成「不够一样」丢掉好命中 |
| 本条尺子 vs 第 1 条流水线 | 本条是怎么打分；第 1 条是分完之后怎么生成 | 会背公式，仍说不清分数进提示词之前干了什么（对照即可，不换条） |
| **L2 向量归一化 vs min-max 分数归一化** | **前者改向量层（除以长度）；后者改分数层（按比例重排 max=1）** | **都叫「normalize」但层不一样——接错会让 cosine 列 == dot 列的验证失效** |
| **错排序按钮演示的 vs demo 代码错** | **前者演示的是「业务 bug：把 cosine distance 当 cosine similarity 排序」；后者是 demo 自己有 bug** | **混淆会让几个月后复习的你觉得 demo 不可信** |

## 例子

每个核心对象自己走一遍，不共用一句总类比。

**方向 = 语义 → 指南针，不是步数。**  
两个人都朝东北。检索问的是「朝没朝同一件事」，不是走了多少米。数据：问题向量和短同向都是 `[1, 0]`，夹角 0°。

**长度 ≠ 更重要 → 气声说「东北」和喇叭喊「东北」。**  
音量（长度）不同，方向相同。数据：`[1, 0]` 和 `[10, 0]`，余弦仍是 1；点积从 1 变成 10。

**余弦 → 两个进度条都朝 100% 走。**  
一个 10 像素宽、一个 500 像素宽，只要朝同一边，余弦都接近 1。

**点积被长度收买 → 长政策赢短 FAQ。**  
同一句「破损可退」，后面粘 800 字免责。点积把长的顶到第一，短而准的卡片被压住。

**欧氏惩罚长块 → 整节政策变「远」。**  
切块从一句改成一整节，落点和问题差了一截，欧氏把它排到最后。

**正交 → 破损问题撞上发票卡片。**  
`[1, 0]` 对 `[0, 1]`，余弦 0。不是反对，是两件不同的事。

**前端检索 → 搜索「清空购物车」命中「移除全部商品」。**  
字面匹配失败，方向近。这就是第 1 条说的：客人说「杯子裂了」，库里写「运输破损」。

**step-1 可观察例子（前端场景）**：同一页三列，各 POST 自己的 `/api/score-*`。余弦列短/长并列；点积列长赢；欧氏列长最远。输出区能看见本次请求参数、调用流程、完整响应。

**Top-K 截断例子（page-2）**：4 张售后卡，K=3 → 第 4 名（最低分那张）进「被截掉」区。把 K 改成 4 → 被截掉区变空。**判定按全表算**——把 K 改成 1，长同向在点积这一侧稳赢这一条，但「短 vs 长」对照仍按全表算，不会因为长被截出 topK 就判 long-loses。

**调高阈值弃权例子（page-3）**：同一组向量、同一个 maxScore，余弦 maxScore=1.0，调高阈值到 1.5 → 弃权；点积 maxScore=10 > 1.5 → 仍 answer；欧氏 maxScore=0 < 1.5 → 仍 answer。**同一组向量，三侧决策不同**——阈值是产品线，不是几何真理。

**模拟换模型例子（page-4）**：scaleFactor=2（模拟 B 模型）→ 所有分数 ×2，余弦并列 2.0（**越界**！cosine 理论上 ∈ [-1, 1]，越界 = 该模型返回的分数不能直接当余弦看）。点积 10 → 20，欧氏 0/9 → 0/18。**业内通用阈值 0.5 是不存在的**——每家嵌入模型的 0.5 含义不同。

**距离排序反了例子（page-5）**：默认 cosine 降序 → 第 1 名是短同向（cosine=1.0）。点 ❌「cosine 升序」→ 第 1 名变成 conflict（cosine=-0.8，最不像那张）。**这是业务上「错把 cosine distance 当 cosine similarity 排序」的 bug 输出长什么样**——后端 scoreVectors 永远按正确方向排序，是前端展示层故意按错方向再排一遍。

**归一化后 cosine == dot 例子（page-6）**：默认未归一化 → dot 长同向赢 10。打开归一化 → L [10,0] 变 [1,0] 跟 S [1,0] 完全重合，**cosine 列 == dot 列（数字一字不差）**。点积比余弦少一次除法——这就是向量库内部默认归一化的原因（计算快 + 排序方向统一）。

## 取舍

**step-1 用二维手写坐标，不用真嵌入模型。**  
本步要看见「方向 / 长度」拆开。真嵌入是几百维，人眼看不见同向不同长；二维能画出来，三把尺子的翻车也是同一组数。真近义 / 冲突分数等几何看懂了再加，不预判步数。

**三侧分请求，不做一个「同时打三种」的超级接口。**  
教学点就是换尺子。一个 `/api/compare` 同时跑多套，页面上看不见「这一侧自己请求」。对照可以同页，左 / 中 / 右三列，各 POST 自己的 URL。

**空对象 body = 用教学集；显式 `cards: []` = 400。**  
happy path 不用先填表。第一类失败要能和「演示后端 5xx」一眼分开。

**六 mode 共用同一 `scoreVectors` 核心函数**（而不是每个 mode 一个函数）。  
新增 mode 时**只加可选入参**（`k` / `threshold` / `scaleFactor` / `normalize`），不动核心排序/截断/弃权逻辑。优点：单一真相源；缺点：`scoreVectors` 入参越来越长（已 5 个 mode 共用）—— 通过拆出 `judgeShortVsLong` 到 `lib/flow/judge-short-vs-long.ts` 让 score-vectors.ts ≤ 280 行；通过拆出 `PageIntroNormalize` 到 `components/intro-normalize.js` 让 layout.js ≤ 250 行。

**改动很小时不开新 step-N+1，在当前 step 内加页面 + 导航承接**（[agents/05-demo.md §5.3.14 新规则](./../../../agents/05-demo.md)）。  
新增 page-2 ~ page-6 都按这条规则——共享同一 `scoreVectors` + 加可选入参 + 加 UI 控件 + 加判定分支 = 「改动很小」。如果开新 step 文件夹，端口/认知都浪费。

**判定按全表算，不按 topK 算**。  
避免「长同向被 K=1 挤出 topK 后判 long-loses」污染 step-1 的几何对照结论——这是 page-2 关键实现细节。

## 踩坑

- 用点积当检索尺子：长政策、长切块稳定赢，短 FAQ 被压住。
- 用欧氏当检索尺子：同义长块被判远，从 Top-K 掉出去。
- 把 `0.82` 当成 82% 正确，或把 A 模型的阈值抄到 B 模型。
- 等负分来发现「可退 / 不退」冲突——真实嵌入很少到 -1。
- 向量库写 `cosine` 却按距离降序取 Top-K，把最不像的喂给模型。
- 以为余弦 = 1 必须原文相同；或把 0.9 丢掉。
- 切块切坏了方向本身漂了，却只怪尺子（那是第 2 条的事）。
- **Top-K 永远能取满**——库里 3 条就一定能给你 3 条，哪怕全是 0.12；只看 Top-K 会把三张无关卡片喂给模型让它编。**必须配阈值**。
- **阈值跟着模型走**——scaleFactor=2 时 cosine 1.0 变成 2.0，越界（cosine 理论上 ∈ [-1, 1]）；阈值 0.5 在原模型是「高」，在 B 模型可能是「中」。**业内通用阈值 0.5 是不存在的**。
- **错排序 bug**：`results.sort((a, b) => b.score - a.score)` 默认降序——但库返回的可能是 cosine distance，越小越近。**业务代码必须先看返回字段是 similarity 还是 distance，再决定降序还是升序取 Top-K**。
- **「归一化」两层混淆**：L2 向量归一化改向量本身（除以长度）；min-max 分数归一化改分数比例（让 max=1）。都叫 normalize 但层不一样——下次看到归一化要先问「改的是哪层」。
- **JSX 文本节点里写 `<` 被当新标签**：写文案时如「0 < 0.9」会被 Babel 当成 JSX 标签开始——**必须包成表达式 `{"<"}`**（已在 AGENTS.md §5.3.4）。
- **Number.NEGATIVE_INFINITY 不是 finite**：`Number.isFinite(-Infinity) === false`。用 `null` 作「无限位」哨兵更稳。

## 过关自检

关上文件后还能讲出来，用售后的话说：

> 库里每张卡片和问题都是一条箭头。**意思近就是夹角小，余弦高。** 箭头谁更长，不该单独决定谁更相关——所以要除以长度（或先归一化）。点积不除，长政策会赢；欧氏看落点，长政策会输。取出前 K 条是按这个分数排的；分数低仍能取满 K 条，所以还要阈值决定喂不喂模型。**0.82 不是 82 分正确，换嵌入模型还得重标定。**

**六 mode 主对照**（对着 step-1 六 page 各跑一次）：

- **raw**：余弦并列、点积长赢、欧氏长远 → 三把尺子拆开「方向 / 长度」的本质
- **topk**：改 K=1/2/3/4，看第 4 条进/出 `dropped`；判定按全表算（不按 topK）→ 避免 K 污染对照结论
- **threshold**：默认 0.5 全 answer；调高到 1.5 → cosine 弃权 + dot / euclidean 仍 answer → 「同一组向量三侧决策不同」
- **cross-model**：scaleFactor ×2 → cosine 1.0 → 2.0 越界；×0.5 → cosine 1.0 → 0.5；→「分数尺度不属于几何 + 阈值要重标定」
- **contrast**：cosine 升序（错）→ 第 1 名变成 conflict（cosine=-0.8）；→ 演示业务 bug 不是 demo bug
- **normalize**：cosine 列 == dot 列（数字一字不差）→ 验证 L2 归一化生效的几何依据

六 mode 全跑 + 「错排序演示业务 bug」「归一化有两种层」两个澄清讲清，本条余弦相似度 100% 闭环。
