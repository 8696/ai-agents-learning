## 一句话讲完这个模块

> 复杂 Agent 系统的本质是「**业务规定的步骤不能靠模型即兴**」：先用一张状态机把站点、边、State 画出来，让代码决定下一步去哪；再让这张图能跨进程活下来——每一步写一份纯数据快照、杀进程之后按任务运行编号读回来，已经对外发生过的副作用（扣款、发短信）不会被恢复时的「再进一次」重复触发；最后让图在某些边前停住，等人承担决定再继续。三件事一层叠一层，缺了第一层就画不清业务，缺了第二层就扛不住发版和崩溃，缺了第三层就拿「钱已经转出去、人是事后看到的」当常态。

## 这些条怎么连成一条线

| 关系 | 谁是谁的什么 |
| --- | --- |
| **01 状态机 → 02 检查点** | 01 把图、节点、边、State、调度器立起来；02 把这个调度器「跑完一步就退出」这件事变成「跑完一步 → 写快照 → 进程死了 → 按编号加载 → 再跑下一步」。**没有 01，02 没有快照可存的对象**（散落变量 stringify 出什么没有型），**没有 02，01 跨不过一次发版或一次重启** |
| **02 检查点 → 03 人机回圈** | 02 把「暂停是合法的」这一前提立起来——人点头可能要等 40 分钟，期间进程一定会经历重启；03 把「停在等待节点」这一站画在 01 的图上，把「人的决定」写进 02 的 State 和检查点。**没有 02，03 的暂停等于把单子扔进内存**；**没有 03，02 只是把转账的结果更可靠地保存下来，并不能阻止转账发生** |
| **01 ↔ 03（等待节点是图上的一个普通节点）** | `waitForHuman` 是图上画好的一条边，「出边事先画好：通过 → 执行、拒绝 → 取消、超时 → 与拒绝同一条安全边」。它复用 01 的全部机制——节点、State、调度器、合法转移——只是这个节点函数**不调用支付 / 删除**。机制同构、教学独立 |

也可以这样说：**01 是骨架（没有图就没有站点），02 是肌肉（没有持久恢复就扛不住现实世界的时间），03 是刹车（没有暂停就没有责任分配）**。一条机器 Agent 变复杂，就是从「会转圈」往「会画图 → 会写盘 → 会等人」三级跳。

| 验收项 | 我的回答 |

| 有显式的 State 定义（TS 类型），而不是散落的变量 | `CafeState` / `TicketState` 一份 Zod schema 描述整张图共享的对象；节点函数只返回 `Partial<State>`，由调度器合并；`object-view` / `cafe-desk-pane` 把整份 JSON 摊开在页面上与 TS 类型对照。**反例**：`let drinkName` 在文件顶、`let drinkType` 在闭包里——当下就对不齐、Checkpoint 也存不住 |

| 进程杀掉重启后，能从上一个 Checkpoint 恢复继续执行 | step-1 `pages/resume.html` 给「显示『在终端杀掉再起服务』的命令」按钮：`<pre>` 块里 `lsof -nP -iTCP:50121 -sTCP:LISTEN` + `kill -9 <PID>` + `yarn app:11-02-...-step-1`；浏览器 hard reload 后同一 `runId` 仍能从磁盘恢复，`currentNode` 不是入口、余额不变 |

| 至少有一处并行执行（两个独立任务同时跑） | 01 step-1 `/pages/parallel.html`：从 `fork` 画 `brewShot` 和 `steamMilk` 两条边，两边都写回 State 之后才进 `assemble`；`parallel-step-once.ts:runParallelArms` 用 `Promise.all` 同时跑、合并 `{ ...shot, ...milk }`——own 合并对照 whole 盖掉 |
| 能画出这个 Workflow 的状态图 | mermaid 渲染在 `cafe-pipeline.js`，高亮当前节点；边表在画法 9 步第 9 步（`cafe-pipeline.js:51-57`）——`from / to / readsField` 三列。任意一条带条件的边，能指着说出 State 哪个字段在做决定 |

## 最容易记错的三条

| # | 容易混成一句 | 差在哪 | 判错会怎样 |
| --- | --- | --- | --- |
| 1 | **「下一步去哪」由模型说了算（模块 07）vs 由代码说了算（模块 11）** | 同样是「决定下一步」，机制完全不同：模块 07 是 prompt 里说「你看着办」、靠 `tool_calls` 数组；模块 11 是路由表 + 边表 + 节点函数表——模型只在「需要生成文本」的节点内部被调 | 把模块 07 的循环轨迹图当业务状态图交出去——那只证明你会转圈，不证明你会画自己的图；或者在模块 11 的图上又让模型临时决定调什么工具——边表变成装饰 |
| 2 | **检查点存住 = 有人机回圈** | 检查点解决「进程死了单还在」；人机回圈解决「单在，但人没点头就不能往下做」。暂停点只有一个合法位置：支付 / 删除 / 发送的函数**还没被调用**那一刻 | 以为写了检查点就等于有审批；恢复后调度器把转账跑完，钱已经出去了 |
| 3 | **杀进程 = 节点失败** | 节点失败：进程还活着，热饮机坏了写 `lastError` 走失败边，HTTP 仍 200；进程被杀掉：整份 Node 进程没了，内存一起没了，只剩磁盘上最后一份写完整的检查点。`pages/node-fail.html` vs `pages/charge-crash.html` 是两组独立演示 | 把热饮机坏了当成「杀进程再起来」，本节缺第二/四种时机的演示——客人投诉「明明只点了一杯、扣了两次」 |

## 踩过的坑（跨条）

- **把模块 07 的循环轨迹图当业务状态图交出去。** 那只画了通用循环，没画你的任务。01 易混 2。
- **存档器其实是另一个内存 `Map`。** 同进程测试通过，真重启全丢。LangGraph `MemorySaver` 名字带 Memory，杀进程一样丢——那是同进程里下一次调用还能接上，**不是**持久恢复。02 变体 B + 易混 2。
- **只演示「完整检查点已经在磁盘上再停进程」。** 看不见「钱扣了、文件还没写完」会再进扣款节点——客人投诉的真正来源。02 变体 C 第二种时机。
- **只做调度器跳过、不做工具幂等。** 第二种杀进程时机扣两次钱。三道保护不是替代关系。02 变体 E + 易混 3 / 4。
- **`JSON.stringify` 成功不等于可恢复。** `Date` 变字符串、`Map` 变 `{}`、`undefined` 字段被丢掉——读回来类型走样，路由走错站。02 变体 K + 易混 7。
- **半份文件覆盖上一份完好快照。** 没有原子写入，第四种时机（写到一半）会留下半份 JSON，下一次启动解析失败。02 变体 I + 易混 11。
- **两件任务运行共用一个文件名或同一个用户 id 当键。** 恢复拿错单，短信发到别人手机。02 变体 F + 易混 8。
- **改参数 ≠ 批准。** 改参数的接口顺手把 `status` 写成 approved，钱按新数字走了，人还以为自己只是在改草稿。03 变体 C + 易混 7。
- **超时默认通过。** 凌晨没人值班，系统把「没人反对」当成「同意」，大额转账自己走了。03 变体 G + 易混 10。
- **只在同一次页面会话里点通过，从没停过服务。** 证明不了人机回圈能跨进程。03 变体 E + 踩坑。
- **每一步都问人。** Agent 退化成表单向导，真正危险的那一下失去意义。03 变体 H。
- **先执行再弹确认。** 那是通知，钱已经没了。03 变体 B + 易混 1。
- **System Prompt 写「转账前必须问用户」当关卡。** 模型为了把任务做完会跳过。03 变体 D + 易混 8。
- **把 `messages` 整段塞进检查点。** 体积膨胀、和模块 06 裁剪打架；只有后面路由还要读的字段才进 State。02 变体 L。
- **图改名了旧检查点硬跑。** 拿旧名字查节点函数表找不到，进入不存在的节点。02 变体 J。
- **并行节点 return 整份 State。** 后写的把先写的字段盖成 `null`。01 变体 G + 踩坑。
- **路由不互斥或不穷尽。** `next` 为空调度器崩溃；两个 `if` 都能命中时顺序说了算走错站。01 变体 B。
- **节点自己改 `currentNode`，调度器不验边。** 破坏「有限」，FSM 退化成普通流程图。01 变体 F + 易混 15。
- **多子图编排：跨子能力不传 State / 强依赖靠 LLM 自觉 / 子图各自管 State / 外层 LLM 没 phase 门禁。** 强依赖必须画在状态机边上，外层要一份对外可见的总 State 挂在外层。01 易混 16/17/18 + 踩坑四条。
