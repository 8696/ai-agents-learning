## 一句话讲完这个模块

检索增强生成（RAG）失败，多数不是大模型笨，是检索侧出错。本模块从四个维度各补一刀：**检索通道**（向量 + BM25）、**名单顺序**（精排）、**送进检索器的那串字**（改写 / 扩展 / 假想文档嵌入）、**库与问句的粒度**（父子切块 + 多路查询）。每一刀都多花钱或多占词元预算（Token Budget），**一次只加一个变量，每次都跑评测集**。

## 这些条怎么连成一条线

四条外部小节按「检索流水线的位置」从底层到顶层排：

```text
   库怎么切、问句怎么扩
   ┌──────────────────────────────┐
   │ 04 切块与查询变体（底层）      │
   │  · 父子切块：检索 ≠ 生成单位  │
   │  · 多路查询：N 条问句 × N 次   │
   └──────────────────────────────┘
                ▼
   送进检索器的那串字
   ┌──────────────────────────────┐
   │ 03 查询改写（入口前）          │
   │  · 改写 / 扩展 / HyDE         │
   └──────────────────────────────┘
                ▼
   检索通道
   ┌──────────────────────────────┐
   │ 01 BM25 / 混合检索（通道）    │
   │  · 向量 + BM25 + 融合         │
   └──────────────────────────────┘
                ▼
   名单顺序
   ┌──────────────────────────────┐
   │ 02 Rerank（中间）             │
   │  · 粗召回给宽候选 + 精排改顺序 │
   └──────────────────────────────┘
                ▼
           生成（Generate）
```

| 节 | 修哪一侧 | 它救不了的失败 |
| -- | -- | -- |
| 01 BM25 / 混合检索 | 检索通道 | 检索到的切块对了但答错 |
| 02 Rerank | 名单顺序 | 切块没进名单 |
| 03 查询改写 | 送进检索器的字 | 库里匿名切块仍漂 |
| 04 切块与查询变体 | 库与问句的粒度 | 精排救不了没进名单的父块、没进名单的第二邻域 |

**互不替代**：

- 02 精排只改已进名单的顺序。名单里没有的切块、02 救不出来
- 03 改写只改问句。库里匿名切块（封面里的公司名、季度）03 救不出来，要靠 04 的情境检索
- 01 混合检索只补召回侧。检索命中了但模型读不懂，要靠 04 的父子切块（搜小块、读父块）
- 04 多路查询只补召回侧。同一意图多种邻域它救得了；一句里两个独立意图要靠 03 拆子问题

**两个对照硬币**：

- 02 与 03 都涉及「动问句」，但 02 改的是「已经搜到的怎么排序」（改后），03 改的是「送进检索器的字」（改前）
- 03 的查询扩展 vs 04 的多路查询：扩展是「1 条查询 + 1 次检索 + 补词」，多路是「N 条查询 + N 次检索 + RRF 合并」——同样要补词，扩展救不了多邻域

**一条暗线**：第 02 条精排的失败归因章节要求「一次错误回答先问是哪一环——切分 / 检索 / 重排 / 生成」。本模块四条小节正对应其中三环（切分 = 04、检索 = 01/04、重排 = 02），生成留到模块 14。

## 最容易记错的三条

1. **精排能补检索失败吗？**——不能。精排只给已经进名单的切块改顺序。名单里没有的父块上下文、没有的第二邻域，精排变不出来（对应 §5.4 易混表「精排能补这四种」条）
2. **查询改写是给模型改问句吗？**——不是。是把**送进检索器的那串字**对齐到库词。生成阶段模型看到的提示词里仍应保留用户原句（对应 03 文档「什么是」节末段）
3. **多路查询 = N 次生成？**——不是。**1 次** chat completions 调用返回 N 行（temperature=0.3 大概率是同义改写；按角度明确写提示词能更稳）→ **N 次**本地检索 → **1 次**对话补全。账单与延迟按 2 次模型调用 + N 次本地余弦计，不是按 N × 2（对应 04 文档「3b」「3d」节）

## 踩过的坑（跨小节）

1. **四种手段同一天全开**——变好了不知道是谁起的作用。本模块验收写过：一次只加一个变量，每次都跑评测集（来源：模块 08 / 09 通用纪律 + 01 「`α` 是加权融合的旋钮」 + 03 「扩展救不了多邻域」 + 04 「一次只加一个变量」节）
2. **只展示最终答复**——关上文件后以为做了精排 / 改写 / 多路，其实只是块调大了。每个 step 都强制页面分开展示请求参数 / 调用流程 / 响应结果三件（§5.3.10 / §5.3.11），不只露成功按钮
3. **指望精排补检索失败**——名单里没有的切块、没进名单的第二邻域，精排变不出来。02 与 04 都明示这条边界
4. **混合检索只走一边**——向量漏编号、BM25 漏同义；只走一边就把对方那一边的短板留下。01 step-1 同库同问句分请求对照是避免这条的唯一办法
5. **多路查询当成 N 次生成**——账单与延迟按 Agent 扇出爆炸。04 step-2 实测 1 次生成 + N 次本地检索 + 1 次答复，总共 2 次模型调用；中间 N 路只是本地余弦排序
