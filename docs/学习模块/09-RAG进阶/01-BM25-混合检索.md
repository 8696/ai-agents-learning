## 是什么

**一句话（进度表要能讲清的）**：向量检索（Vector Search）不擅长必须对上的字——专有名词、编号、错误码；**BM25（Best Matching 25）** 靠关键词把这些漏掉的卡捞回来。口语同义反过来：BM25 不擅长，向量补。真实知识库两种问法都有 → 要**混合检索（Hybrid Search）**，不要赌只走一边。

模块 08 已经会「按意思找近的卡片」。本条多一条尺子：**按词找**。

**BM25** 是搜索引擎里最常用的关键词打分公式。Elasticsearch、Lucene 默认就是它。它不把句子变成方向，只问三件事：

1. **查询里的词，这篇有没有、出现几次**（词频，Term Frequency）——有比没有好，但出现 50 次不会比 5 次强 10 倍，分数会**饱和**。
2. **这个词有多稀有**（逆文档频率，Inverse Document Frequency）——「的 / 怎么 / 退货」到处都有，几乎不加分；`SKU-8821`、`ERR-4401` 几乎只在一张卡出现，一对上就猛拉分。
3. **这篇有多长**（文档长度归一，Document Length Normalization）——长文更容易碰巧撞上查询词，所以要打折，避免「手册全文」永远压过「那一条规定」。

人话：**BM25 = 更聪明的 Ctrl+F。** 不是「有这个字就算」，是「稀有词对上了，而且别靠文章又臭又长作弊」。名字里的 25 只是这套公式家族的版本号，勾进度不要求背来历。

**稠密检索（Dense Retrieval）** = 模块 08 那条：嵌入模型（Embedding Model）把文本变成一长串小数，几乎每位都不是 0，用余弦比方向。

**稀疏检索（Sparse Retrieval）** = BM25 这条：一篇文档像「词 → 重量」的对照表，没出现的词重量是 0。查询也是几个词。只在对上的词上计分。

**混合检索** = 同一句问话，两边**各自**出一份排行榜，再融合成一份名单。不是「两个分数直接相加」这么简单——量纲不一样，硬加会翻车。

```text
用户问句
    ├─ 嵌入模型 → 问题向量 → 和每张卡算余弦 → 向量排行榜
    └─ 切成词   → 对每张卡算 BM25         → 关键词排行榜
                         ↓
                  融合（加权 或 倒数排名）
                         ↓
                  混合 Top-K  → 再交给生成（Generate）
```

本条停在「名单怎么凑」。融合之后还可以再精排，那是第 2 条的事。

## 为什么（Agent 开发要懂）

检索增强生成失败，很多时候不是大模型笨，是**检索根本没把那张对的卡交上去**。模块 08 只走向量时，有三类问句会系统性漏：

| 问句类型 | 向量容易怎样 | 后果 |
| -- | -- | -- |
| **编号 / 工单号 / 错误码**（`SKU-8821`、`ERR-4401`、`RFC-9110`） | 嵌入会把罕见符号「抹平」成「某种商品 / 某种错误」 | Top-K 里全是同类政策，唯独没有那一张 |
| **产品名 / 接口名 / 人名**（库里刚出现的专有名词） | 模型训练时没见过，向量漂到近义词 | 答成别的型号的保修 |
| **必须逐字命中的字段**（配置键、枚举值、路径） | 方向近的卡很多，精确那张不一定第一 | Agent 引用错条目，看起来「很像对」 |

客服场景：用户贴 `ERR-4401`，库里有一张「ERR-4401 = 库存锁定失败，重试即可」。向量可能捞来「库存不足怎么处理」「下单失败常见原因」——意思近，**编号不对**。模型根据错材料一本正经地安抚，工单继续炸。

生成阶段只看见前 K 条，**没看见的卡等于不存在。** 模型不是「忽略了编号」，是你根本没把编号那张卡喂给它。

## 核心对象

| 核心对象 | 管什么 |
| -------- | ------ |
| **稠密 / 向量检索** | 按意思近；抹平用词差异，也抹平编号差异 |
| **BM25 / 稀疏检索** | 按词命中；稀有词（编号、专名）决定排名 |
| **混合检索** | 两边各自出榜，再融合成一份 Top-K |
| **融合：加权分数** | `α × 向量分 + (1-α) × BM25 分`；必须先把两把尺子拉到同一刻度 |
| **融合：倒数排名融合（RRF）** | 不看分数看名次：`1 / (k + 名次)` |
| **切词（Tokenizer）** | BM25 看见的是词不是整句；切碎编号就搜不到 |

## 各变体

### 变体 1 · 纯向量漏编号 / 专名

嵌入模型的工作是：把千差万别的字，压成「意思相近就靠近」的方向。模块 08 第 3 条已经演过：`杯子裂了` 和 `运输破损` 字面不同，夹角可以很小。

同一套「抹平差异」的能力，碰到编号会反噬：

- `SKU-8821` 和 `SKU-8822` 对模型来说，都是「某个货号」，方向可能几乎一样。
- `ERR-4401` 可能被当成「错误 / 失败」的近亲，和「库存不足」挤在一起。
- 全新内部代号（`FitCheck Pro`、内部接口名）训练语料里没有，向量没有锚点，只能漂到普通近义词。

```text
问：SKU-8821 保修几年？
  → 嵌入 → 一条向量
  → 和库里所有卡比余弦
  → 可能的 Top-3：
      0.81  「路由器保修政策（通用）」
      0.79  「SKU-8800 系列保修说明」
      0.74  「电子产品保修须知」
  → 真正写着 SKU-8821 = 保修 2 年 的那张，排在第 12
```

生活：快递柜取件码 `A8K2` 认的是这四个字符。向量像热心保安：「您是来取件的吧？最近取件的格子都在这边。」格子很多，**码对不上。**

前端：全局搜索输入 `ECONNRESET`。按意思搜，出来一堆「网络错误怎么排查」；用户要的是标题就叫 `ECONNRESET` 的那篇排障说明。

### 变体 2 · 纯 BM25 中编号

BM25 看到 `SKU-8821`，不会问「这像不像商品编号」。它问：问句切成哪些词、这些词在各张卡出现几次、有多稀有、文章是否特别长。

`SKU-8821` 若全库只出现 1 次，逆文档频率极高 → 含这个词的卡直接冲到最前。「保修」「几年」太常见，几乎只是配菜。

```text
问：SKU-8821 保修几年？
  → 切词 → ["SKU-8821", "保修", "几年"]
  → 对每张卡打 BM25
  → Top-1：那张「SKU-8821 路由器保修 2 年」
  → 「通用路由器保修」里没有 8821，分数上不来
```

生活：图书馆按书号找书，不是按「一本讲悲伤的小说」。

前端：`Cmd+P` 搜 `rate-limit.ts` 必须精确；「那个限制请求次数的文件」才需要语义。

### 变体 3 · 纯 BM25 漏同义

BM25 **不理解同义**。库里写「运输破损可补发或退货」，用户写「杯子裂了怎么退」——两边几乎没有共同词，BM25 分数可以接近 0。这正是模块 08 向量赢的地方。

| | 向量 | BM25 |
| -- | -- | -- |
| 擅长 | 换词、口语、近义 | 编号、专名、必须对上的字符串 |
| 不擅长 | 编号被抹平、近义型号互抢 | 一个共同词都没有 |
| 单独用 | 售后口语还行，工单码常翻车 | 搜代号很准，闲聊政策常空手 |

**只上 BM25、不上向量**，模块 08 的「字不同也能中」会整段消失。混合不是「向量不够高级再叠一个」，是两边各补对方的盲区。

生活：只认身份证号的门卫，听不懂「就是上次来修过冰箱的那个人」。

前端：`Ctrl+F` 搜「节流」，搜不到写着 `throttle` 的那一段。除非切词表把它们当成同一个词——那已经靠近第 3 条的查询改写 / 同义词，本条不整节展开。

```text
问：杯子裂了怎么退？
  → 切词 → ["杯子", "裂了", "怎么", "退"]
  → 库里那张是「运输破损可补发」
  → 共同词 ≈ 0 → BM25 接近 0 → 进不了 Top-K
  → 同一句走向量：方向近 → 能进 Top-K
```

### 变体 4 · 混合：两边召回再融合

```text
同一句问话
  → 请求 A：嵌入 + 余弦 → 向量 Top-K（比如 20）
  → 请求 B：切词 + BM25 → 关键词 Top-K（比如 20）
  → 融合：两份名单合成一份，再取最终 Top-K（比如 5）
  → 这 5 张才进提示词（Prompt）
```

关键点：

- **两边都是检索，不是一边过滤一边排序。** 常见错法：先 BM25 筛一堆，再在子集里算向量。编号问可以；口语问会在第一刀就被 BM25 砍死，向量永远没机会救。
- **并集再融合** 才是「两边都能救人」：口语靠向量进名单，编号靠 BM25 进名单。
- **混合 ≠ 把两次结果拼成一个数组就结束。** 不融合、不重排，第一名是谁完全看你 `concat` 的顺序。

生活：派出所按身份证号出一份名单，居委会按外貌出一份。两份**都**交给你，再决定先拜访谁——不是先按身份证筛完，再让居委会在剩余名单里猜。

前端：电商搜索同时走「标题关键词」和「向量相似商品」，再合成一页。只走关键词：搜「能当桌垫的大鼠标垫」可能空手；只走向量：搜型号 `G304` 可能出来一堆别的鼠标。

### 变体 5 · 加权分数，必须先拉齐

```text
混合分 = α × 向量分 + (1-α) × BM25 分
```

`α = 1` 只信向量；`α = 0` 只信 BM25；`0.5` 各半。

**坑：两把尺子的刻度不一样。**

| 尺子 | 常见数值 | 越大越好？ |
| -- | -- | -- |
| 余弦相似度 | 实务里常见 0.2～0.9，理论上 -1～1 | 是 |
| BM25 | 0 到十几、几十，没有固定上限 | 是 |

不归一化就加：BM25=12.4 对上余弦=0.81，加法几乎只听 BM25。`α` 调到 0.8 也救不回来——不是权重没调好，是把「摄氏度」和「米」加在一起。

正确顺序：① 各自在**本批结果里**拉到同一区间（常见 min-max 到 0～1）；② 再加权。

这和模块 08 第 3 条的 **L2 向量归一化**不是一层：那里改的是**向量本身**（除以长度）；这里改的是**已经打完的分数**。都叫归一化（Normalize），层不一样。接错的后果：你以为在调语义比重，其实还是 BM25 说了算。

生活：语文 85 分（百分制）+ 体育 12 秒（跑 100 米）。不先换算，加法没有意义。

前端：把 `relevanceScore`（0～1）和 `viewCount`（0～100000）直接加去排搜索——浏览量碾压一切。

### 变体 6 · 倒数排名融合（RRF）

**倒数排名融合（Reciprocal Rank Fusion，RRF）** 不看分数，只看名次：

```text
RRF(文档) = Σ  1 / (k + 名次)
```

`k` 常见取 60，避免「只在一个榜上第 1」的文档把所有分抢走。只上一个榜也可以计分。

生产里很多人默认它，因为：

- **不用对齐量纲。** 余弦和 BM25 各玩各的。
- **对「某一侧分数爆表」不敏感。** BM25 因极稀有词拿到 40 分，也不会把向量侧第 1 名直接踹走——它贡献的是名次，不是原始分。
- 代价：丢掉分数里的强度信息。向量侧第 1 名 0.92、第 2 名 0.51，RRF 只知道「1 和 2」。

| | 加权分数 | RRF |
| -- | -- | -- |
| 看什么 | 分数（必须先拉齐） | 名次 |
| 怕什么 | 忘了归一化；两侧分数分布变了 `α` 要重调 | 强度差被抹平 |
| 适合 | 两侧分数稳定、想精细偏哪边 | 刻度说不清、先求稳 |

**RRF 不是重排序（Rerank）。** RRF 还是在「两份粗名单怎么合成」；重排序是拿一份已经召回的名单，用更贵的模型再打一遍分。本条的融合发生在**召回之后、精排之前**。

生活：两个评委分别排名，不报分数。第 1 名票最重，第 10 名几乎没票。不用先统一百分制还是十分制。

前端：一个榜按相关度、一个榜按时间，最后按名次倒数相加——不用把「相关度 0.83」和「3 小时前」加在一起。

### 变体 7 · 按问句偏置权重

没有全世界通用的 `α`。看问句长什么样：

| 问句信号 | 该偏谁 | 为什么 |
| -- | -- | -- |
| 含连字符编号、全大写错误码、明显货号 | 偏 BM25（`α` 小） | 对上这几个字符才算对 |
| 口语、换词、描述现象 | 偏向量（`α` 大） | 共同词很少 |
| 两者都有：「SKU-8821 杯子裂了怎么退」 | 混合必须两边都开 | 编号定位商品，口语定位政策 |

产品上可以：人先调一个全局 `α`（教学上最清楚）；或用很浅的规则（问句匹配 `/[A-Z]+-\d+/` 就降低 `α`）。**不要**在本条做成「再让大模型改写问句」——那是第 3 条。

判错会怎样：编号问仍把 `α` 钉在 0.9 → 混合名义上开了，实际还是纯向量，本条的补丁等于没打。

生活：同时报了身份证号和「住在 3 栋、上次来修冰箱」。号能对上就先信号；只有外貌描述就信居委会。

前端：搜索框检测到用户粘贴了 `ERR-4401`，关键词通道权重升高；输入「接口总是超时怎么办」则语义通道升高。

### 变体 8 · 中文怎么切词

BM25 的输入不是整句，是**词袋（Bag of Words）**。切错了，后面公式再正确也是在给错词打分。

| 切法 | 「SKU-8821 保修几年」可能变成 | 后果 |
| -- | -- | -- |
| 按空白 / 标点，保留连字符 | `SKU-8821`, `保修`, `几年` | 编号作为一个词，逆文档频率极高，能中 |
| 按连字符再拆 | `SKU`, `8821`, `保修`, `几年` | `8821` 仍较稀有，还能中 |
| 按单字 | `S`,`K`,`U`,`8`,`8`,`2`,`1`,`保`,`修`… | 编号被撕碎，BM25 退化成噪声 |
| 中文不分词、整句当一个词 | 整句几乎永远对不上库里的短卡 | 全军覆没 |
| 「退货政策」切成 `退货`+`政策` | 能对上「退货」「政策」 | 正常 |
| 「退货政策」切成单字 | 单字太常见 | 逆文档频率崩，排名乱 |

英文空格天然是词边界；中文没有。生产里 BM25 前面通常有分词器。教学上要看见的不是「哪个分词库最好」，而是：

> **同一句问话、同一批卡，只改切词，BM25 排名可以完全不同。**  
> 向量侧不受这套切词影响（它走嵌入模型自己的分词）。所以「切坏了」只砸关键词通道，混合至少还有向量托底——前提是你没有「先 BM25 过滤再向量」。

生活：查字典。你要查「退货」，目录如果按单字排成「退 / 货」，精确词条被淹没。

前端：搜索 `userId` 被拆成 `user` + `id`，半个站的变量都中；整词保留则只有真写了 `userId` 的中。

## 易混点

| 容易混成 | 其实是 | 判错会怎样 |
| -- | -- | -- |
| BM25 = `LIKE '%词%'` / 正则 | BM25 是**打分排序**，不是布尔过滤 | 过滤只有「在 / 不在」；没有「稀有词更值钱、长文要打折」 |
| 混合 = 两次结果 `concat` | 必须融合（加权或 RRF），再取 Top-K | 第一名取决于你先拼哪边，像随机 |
| 混合 = 先关键词过滤再向量 | 那是「漏斗」，口语问会在第一刀死掉 | 变体 3 的失败被写进架构 |
| 余弦分数和 BM25 分数可以直接加 | 量纲不同，必须先拉齐，或改用 RRF | `α` 怎么调都像没开向量 |
| RRF = 重排序（Rerank） | RRF 是合成两份粗名单；重排序是对一份名单再打更贵的分 | 以为本条已经做完精排 |
| 向量归一化 = 分数归一化 | 前者除向量长度（模块 08 第 3 条）；后者拉齐已经打好的分 | 接错层，验证对不上 |
| 「稀疏」= 向量很多 0 所以更差 | 稀疏是**词维度**上大部分是 0；不是质量差 | 以为 BM25 是过时低配，编号场景不敢开 |
| 上了混合就不用看失败在哪一侧 | 混合只是合成；仍要能拆开看两边 Top-K | 效果变了不知道是谁救的（本模块验收点名：一次加太多变量） |

和模块 08 的对照（只讲清这一步，不换条）：

- 第 1 条检索：默认画的是「问题向量 → 前 K 条」。本条说：那只是通道 A；通道 B 是词。
- 第 3 条余弦：语义近 = 夹角小。本条说：夹角小**解决不了**「必须对上这几个字符」。
- 阈值弃权还在：两边分数都低、融合后仍然很低，仍然应该说不知道。混合提高的是「该中的卡进得来」，不是「永远有卡可答」。

## 需求清单

验收准绳，不是一次搭完整应用的施工单。每条对应一个变体。落 Demo 按知识动态推进；`coach complete` 才按这里逐条对。

**需求 1 · 编号问，向量会漏**  
业务场景：售后知识库里有 `SKU-8821 路由器保修 2 年`，也有「路由器通用保修」。  
目标：证明向量不擅长编号。  
知识点：变体 1，稠密检索抹平罕见符号。  
验收：同一库、问「SKU-8821 保修几年」，**纯向量** Top-K 看不到（或排不到前 K）那张编号卡；页面能看见完整排名。

**需求 2 · 同一编号问，BM25 能中**  
业务场景：同上。  
目标：证明 BM25 补的就是专名 / 编号。  
知识点：变体 2，逆文档频率让稀有词决定排名。  
验收：同一问句走**纯 BM25**，Top-1 是那张 `SKU-8821` 卡；请求与向量侧**分开**，禁止一个接口打包两条轨迹。

**需求 3 · 口语问，BM25 会漏、向量能中**  
业务场景：库里只有「运输破损可补发」，用户问「杯子裂了怎么退」。  
目标：证明不能只上 BM25。  
知识点：变体 3，词袋没有共同词。  
验收：纯 BM25 进不了 Top-K（或分数接近 0 且排后）；纯向量能进 Top-K。

**需求 4 · 混合让两种问句都进最终名单**  
业务场景：同一库既有货号卡又有政策卡。  
目标：两边召回再融合，而不是先过滤。  
知识点：变体 4。  
验收：编号问、口语问各点一次混合；两边的「该中的卡」都出现在融合后的 Top-K；能看见「来自向量 / 来自 BM25 / 两侧都有」。

**需求 5 · 加权融合必须先拉齐分数**  
业务场景：值班同学把余弦和 BM25 直接相加，发现怎么调 `α` 都像没开向量。  
目标：量纲不同不能硬加。  
知识点：变体 5。  
验收：同一问句能对照「未归一化加权」vs「先 min-max 再加权」；未归一化时排名接近纯 BM25；拉齐后调 `α` 排名会动。

**需求 6 · RRF 按名次合成**  
业务场景：不想维护分数校准，只要两份榜合成一份。  
目标：融合可以不看分数。  
知识点：变体 6。  
验收：同一问句走 RRF，页面列出各侧名次和 `1/(k+rank)`；不把余弦原始分和 BM25 原始分相加。

**需求 7 · 编号问降低向量比重**  
业务场景：问句带 `SKU-` / `ERR-` 时仍用「口语默认 `α`」会漏。  
目标：权重随问句类型偏置。  
知识点：变体 7。  
验收：两条预设问句（编号 / 口语），偏置后编号问的融合 Top-1 是编号卡；口语问仍能中政策卡。

**需求 8 · 切词能看、切错也会丢**  
业务场景：中文知识库，编号带连字符。  
目标：BM25 看见的是词，不是整句。  
知识点：变体 8。  
验收：页面展示本次切出来的词；「整词保留连字符」能中编号卡，「撕成单字」后同一问句 BM25 排名明显变差。

## 取舍

| 场景 | 更稳的做法 | 不要选的 |
| -- | -- | -- |
| 知识库里既有政策口语又有货号 / 错误码 | 混合；两边各自出榜再融合 | 只上向量，或只上 BM25 |
| 两侧分数刻度说不清、先求能跑 | 倒数排名融合（RRF） | 原始分直接相加 |
| 两侧分数稳定、想精细偏语义或偏关键词 | 先拉齐再加权，人调 `α` | 不拉齐就调 `α` |
| 问句明显是编号 | 降低 `α`（偏 BM25），两边仍都开 | 把 BM25 当第一刀过滤器 |
| 只要演示「向量漏、BM25 补」 | step 先做分请求对照，先不融合 | 一上来五个旋钮一起加（本模块常见坑） |

## 踩坑

- **先 BM25 过滤再向量**：口语问在第一刀死掉，向量救不了。混合必须两边都能把卡送进融合。
- **余弦分 + BM25 分硬加**：BM25 数字大一个数量级，混合名义上开了，实际纯关键词。
- **一个接口打包两条轨迹**：对照看不出「哪一侧漏」。向量和 BM25 必须分请求。
- **用假排名冒充向量**：本条要证明的是真嵌入会抹平编号。本地写死的「向量分」不算。
- **切词把编号撕成单字**：BM25 通道等于没开。页面应能看见切出来的词。
- **一次加上混合 + 重排序 + 查询改写**：效果变了不知道是谁的功劳。本模块验收写明：一次只加一个变量。

## 过关自检

合上文件，用售后的话说：

> **向量不擅长必须对上的字（编号、专名、错误码），会把差异抹平。BM25 靠稀有词把那张卡捞进名单。** 口语同义没有共同词，只留 BM25 会空手。混合是两边各自出榜再融合，不是先过滤，也不是把分数硬加。加权要先拉齐刻度；也可以只看名次做倒数排名融合。切词坏了只砸关键词通道。
