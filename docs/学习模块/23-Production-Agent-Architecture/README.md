## 验收

> 本地节奏 / `coach next` 勾本地前对照本节。

**一句话目标**：综合前面所有知识，能独立设计一套生产级 Agent 架构。

**动手产出**：一份完整的架构设计文档 + 架构图；回头把 `apps/` 各子文件夹 README 补到 [2.7.2 交付标准](../../03-学习路线.md#272-交付标准apps-子文件夹)；对照 [2.8 综合验收](../../03-学习路线.md#28-综合验收模块-23-收口) 做一次全程收口。

**验收标准**
- [ ] 画得出完整架构图：Runtime、Workflow Engine、持久化、队列、可观测、评测、安全各在什么位置
- [ ] 每个技术选型都能说出至少两个备选方案和取舍理由
- [ ] 有容量和成本估算（比如 1000 DAU 下每月多少钱）
- [ ] 有扩展性方案（并发上来了怎么办）
- [ ] 有故障预案（模型服务挂了、向量库挂了怎么办）
- [ ] 能简明扼要地向别人讲完这套架构
- [ ] `apps/` 各子文件夹 README 达到交付标准：做什么、怎么跑、数据流、选型取舍；按文档能跑通
- [ ] `apps/` 各子文件夹有与代码目录一致的数据流
- [ ] 不看资料能讲完一次请求的数据流，以及至少三个「为什么不选另一种方案」
- [ ] `apps/` 各子文件夹能复盘：最难的三个点、怎么处理的、若重做改哪三处
- [ ] 不看资料、用自己 `apps/` 里的例子串讲：Token / Context、一次 Tool Calling、Agent Loop 与停止条件、RAG 流水线与答错归因、MCP 三原语与 stdio vs HTTP
- [ ] 给定新约束能独立画出一套 Agent 架构，并标出评测、观测、安全、成本各在哪一层（不是只能讲已经写过的 Demo）

**自测问题**：设计一个企业知识库 Agent 系统。如何支持每天 10 万次 Agent 调用？`apps/` 子文件夹打开 README 能否独立跑通并看懂数据流？不看资料能否把 Token → Tool Call → Agent Loop → RAG → MCP 串起来？

**常见坑**：架构图画得很漂亮但没有取舍说明。关键是**你为什么不选另一个方案**。`apps/` 各子文件夹各自能跑，但讲不清它们怎么连成一条能力链，也不算本模块过关。
