┌─────────────────────────────────────────────────────────────┐

└───────────────────────────┬─────────────────────────────────┘

六条关系是**从 0 到 1 全链路**：
- **骨架（01）**：架构怎么叠
- **数字（02）**：能不能赚钱
- **落地（03）**：怎么交付
- **经验（04）**：怎么复利
- **认知（05）**：怎么讲清
- **应用（06）**：怎么扛事

**任何一层缺失，整体就不完整**——例如：架构（01）没数字（02）→ 不知道赚不赚钱；架构（01）没落地（03）→ 交付不出来；架构（01）没原理（05）→ 讲不清整体。

### 最容易记错的三条

1. **Runtime ≠ Framework**——Runtime 是**把能力叠起来**（部署 + 集成）；Framework 是**SDK 帮你写 Agent**（开发）。两者**不互换**——把 Framework 当 Runtime 用 → 写出来容易，部署 / 监控 / 评测都没人管；把 Runtime 当 Framework 用 → 在写代码时错位。
2. **路由 ≠ 降级**——路由按**任务难度**选模型（省钱主动）；降级按**主模型挂了**换备用（保命被动）。两者**目标完全不同**——把降级当路由做 = 主挂了用户难题被发到小模型 = 用户体验崩塌。详模块 19「易混点 3.1」。
3. **Demo 复盘 ≠ 模块复盘**——Demo 复盘是**单条 Demo**（`apps/{小节}-step-N/REVIEW.md`）；模块复盘是**整个模块**（`docs/学习模块/{模块}/04-模块复盘.md`）。两者**粒度不同**——Demo 复盘讲三问；模块复盘讲整个模块怎么连成一条线。

### 踩过的坑（跨小节）

写到这里，本对话未踩到具体代码坑（无 Demo 落地）。记录三条**预防性踩坑**：

- **「架构图漂亮但没取舍」= 评审质疑 → 项目卡住**：画了一个架构图但没标「为什么不选另一个方案」→ 评审追问 → 答不出 → 项目延期。模块 06「核心概念 9 方案对比」专门拉出一节；做真实项目时每个核心选型必须列 2 备选 + 取舍。
- **「Demo 能跑但讲不清」= 同事接不住**：自己写的 Demo 跑得起来，3 个月后讲不清「为什么这样设计」→ 同事接不住 → 推倒重来。模块 03「`apps/` 交付标准」+ 04「Demo 复盘」专门拉出两节；做真实项目时每个 `apps/` 子文件夹必须三问填满 + 选型取舍写清。
- **「忽略风险标注」= 上线后出事没人救**：只画架构不标风险 → 上线后某个组件挂了不知道怎么办 → **故障 = 几小时白花**。模块 06「核心概念 5 风险标注」专门拉出一节；做真实项目时每个组件必须标 4 类风险（可靠性 / 安全 / 性能 / 成本）。
