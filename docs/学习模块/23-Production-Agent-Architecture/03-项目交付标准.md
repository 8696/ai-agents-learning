### 是什么

**`apps/` 交付标准**是把**每个 `apps/{小节}-step-N/` 子文件夹**当作一个**完整可交付的小项目**——打开 README就能跑、不看资料能讲清一次请求怎么走、为什么这样设计。

#### 为什么是「沉淀型」小节

这节**不是新知识**——是**把前面 22 个模块的 `apps/` 经验沉淀成可复用标准**：

```
Demo 写完 ≠ 可交付

可交付 = 能跑 + 能看 + 能调 + 能讲清
```

#### README 必备字段

| 字段 | 作用 | 例子 |
|------|------|------|
| **名字** | 一句话说清这 Demo 做什么 |「最小流式 Chat UI」|
| **端口** | `runtime-ctx.ts` 里的 default | `50038` |
| **启动命令** | `yarn app:XX-XX-name` | `yarn app:00-01-mini-app-step-1` |
| **数据流图** | 单次请求怎么走 | ASCII |
| **选型理由** | 为什么这样设计 | koa + tsx + HTM |
| **环境变量** | `.env.example` | `LLM_API_KEY=...` |
| **依赖关系** | 哪些 step 依赖哪些 | step-2 依赖 step-1 |
| **常见故障** | 端口占用 / Key 错 / DB 连不上 | 排错清单 |
| **日志位置** | `logs/YYYY-MM-DD.log` | — |
| **健康检查** | `GET /health` 返回 200 | — |

一句话：**`apps/` 交付标准 = 「打开 README 就能跑 + 不看资料能讲清」**。

### 为什么（Agent 开发要懂）

`apps/` 仓库是**给未来读代码的自己 / 同事**留的——几个月后回来看要能秒懂：

具体后果（举四个最常见的）：

1. **找不到入口**：3 个月后看 `apps/05-02-tool-calling/` 不知道哪个文件是入口 → 30 分钟白花。
2. **跑不起来**：新克隆仓库的人按 README 跑不起来 → 「文档是骗人的」。
3. **讲不清设计**：「为什么用 koa 不用 express」→ 说不清 → 没法维护。
4. **交接失忆**：换人维护 → 新人完全不懂 → 推倒重来。

`apps/` 没交付标准 = **3 个月后自己都看不懂**。

### 易混点

`apps/` 交付标准常被和它的「邻居文档」混淆。**判错任何一个会让交接失忆**——必须分清。

#### `apps/` README vs 小节文档

| | `apps/` README | 小节文档 |
|---|---|---|
| **读者** | 开发者（要跑 Demo） | 学习者（要学概念） |
| **重点** | 启动 / 端口 / 数据流 / 选型 | 是什么 / 为什么 / 易混 / 例子 |
| **形式** | 命令行 + ASCII | 概念 + 表格 + 例子 |

**判错会怎样**：把小节文档写进 README → 开发者看 5 分钟不知道跑哪个命令。

#### 数据流图 vs 架构图

| | 数据流图 | **架构图** |
|---|---|---|
| **粒度** | **单次请求**怎么走 | **模块关系** |
| **焦点** | 哪个文件调哪个文件 | 哪个服务调哪个服务 |
| **画法** | ASCII / 简笔 | mermaid / 方块图 |

**判错会怎样**：把架构图当数据流图 → 开发者找不到「这次请求调了哪些函数」。

#### 选型理由 vs 优缺点

| | 选型理由 | 优缺点 |
|---|---|---|
| **焦点** | **为什么选 A 不选 B** | A 有什么好 / 什么不好 |
| **决策** | **可执行的取舍**（场景 A 用 / 场景 B 用） | 信息性 |
| **适合** | 维护时复用 | 评估时参考 |

**判错会怎样**：只列优缺点 → 看的人不知道「我的场景该用哪个」。

#### 环境变量 vs 配置文件

| | 环境变量 | 配置文件 |
|---|---|---|
| **注入** | 启动时动态 | 代码里写死 |
| **改值** | 不改代码 | 改代码 + 重启 |
| **适合** | Key / URL / 环境差异 | 业务逻辑 |

**判错会怎样**：把 Key 写在配置文件 → 提交到 git → 泄露。

#### 依赖 vs 端口 vs 启动

| | 依赖 | 端口 | 启动 |
|---|---|---|---|
| **问什么** | 装什么 | 跑在哪 | 怎么跑 |
| **例子** | `yarn add koa` | `localhost:50038` | `yarn app:00-01-...` |

**判错会怎样**：文档只写启动命令 → 不知道跑哪个端口 → 访问3000（默认）失败。

### 核心概念（变体 / 分支全扫）

`apps/` 交付标准有 10 个变体。

#### 1. README 必备字段清单

**完整 README 模板**（见「是什么 · README 必备字段」表）。

**例子**：餐厅菜单 = 名字 + 价格 + 图片 + 过敏信息 → `apps/` README = 名字 + 端口 + 启动 + 数据流 + 选型 + 环境变量 + 依赖 + 故障 + 日志 + 健康检查。

**需求 1（README 必备字段）**：为 `apps/00-01` 这条 step 写完整 README；10 个字段全有。

#### 2. 数据流图模板

**ASCII 数据流图**（单次请求怎么走）：

```
用户 ── GET /api/xxx ──► 路由层 (routes/)
 ↓
                         服务层 (lib/flow/)
                              ↓ 外部 API（LLM / Tool）
                              ↓
                         流式响应 ──► 用户
```

**字段**：每节点标注**文件名 + 函数名**。

**需求 2（数据流图）**：为 `apps/` 某 Demo 画 ASCII 数据流图；每节点标文件。

#### 3. 选型理由模板

**每个选型至少 2 备选 + 取舍**：

```
为什么用 koa？
 vs express：koa 更轻、async/await 原生支持
  vs fastify：fastify 快但生态小；koa 文档全 本场景：轻 + 全 → koa
```

**需求 3（选型理由）**：为 `apps/` 某 Demo 的 3 个核心选型各写理由；每个 2 备选。

#### 4. 环境变量清单

**每个变量一行**：

```bash
# .env.example
LLM_API_KEY=sk-xxx          # 必填
LLM_MODEL=claude-sonnet-4   # 默认
PORT=50038                  # 默认
LOG_LEVEL=info              # 可选
```

**需求 4（环境变量）**：为 `apps/` 某 Demo 写 `.env.example`；4 个变量齐全。

#### 5. 启动命令三件套

**三件套**：

```bash
# 1. 装依赖
yarn install

# 2. 类型检查
cd apps && yarn typecheck

# 3. 启动
PORT=50038 npx tsx apps/00-01-.../server.ts
# 或
yarn app:00-01-mini-app-step-1
```

**需求 5（启动三件套）**：为 `apps/` 某 Demo 写完整启动命令；含装依赖 + typecheck + 启动。

#### 6. 日志位置 + 健康检查

| 项 | 标准 |
|----|------|
| **日志** | `apps/{demo}/logs/YYYY-MM-DD.log` |
| **健康** | `GET /health` → 200 |

**需求 6（日志 + 健康）**：实现 `GET /health`；日志路径符合规范。

#### 7. 常见故障排查

**排错清单**：

| 症状 | 排查 |
|------|------|
| **端口占用** | `lsof -i :50038` + kill |
| **Key 错** | 检查 `.env` |
| **DB 连不上** | 检查连接字符串 |
| **依赖装不上** | `rm -rf node_modules && yarn install` |
| **TypeScript 错** | `cd apps && yarn typecheck` |

**需求 7（故障排查）**：写常见故障清单；至少 5 种。

#### 8. 依赖关系图

**哪些 step 依赖哪些**：

```
step-1 (基础)
 ↓
step-2 (依赖 step-1)
 ↓
step-3 (依赖 step-2)
```

**字段**：每个 step 能不能**单独跑**（不需要前置）。

**需求 8（依赖关系）**：画 3 个 step 的依赖图；标能不能单独跑。

#### 9. 选型 vs Retrofit 对比表

**5 大选型对比**：

| 选型 | 选了什么 | 备选 1 | 备选 2 | 取舍 |
|------|----------|--------|--------|------|
| **框架** | koa | express | fastify | 轻 + 全 |
| **端口** | 50000+ | 3000 | 8080 | 不撞常用端口 |
| **语言** | TypeScript | JavaScript | Python | 类型安全 |
| **流式** | SSE | WebSocket | 长轮询 | 单向足够 |
| **存储** | Redis（队列） | BullMQ + Postgres | SQS | 简单 |

**需求 9（选型对比）**：为 `apps/` 某 Demo 写 5 大选型对比表。
