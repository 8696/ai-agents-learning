### 是什么

**容量 / 成本估算**是 Agent 上线前的**最关键一步商业判断**——把「现在能跑 100 次 / 天」外推到「1000 DAU 时成本多少」。

#### 估算的意义

```
现在（Demo）：100 次 / 天 → 不知道真上线多少钱 ↓ 估算
1000 DAU → 单次成本 × 调用次数 × DAU × 30 天 = 月成本
       ↓ 决策
价格定多少 / 融资多少 / 要不要做```

#### 三块成本

| 成本项 | 占大头 | 例子 |
|--------|--------|------|
| **LLM API** | **60~80%** | Claude / GPT / 智谱 API |
| **服务器** | 10~20% | 云服务器 / K8s / Serverless |
| **存储 + 观测** | 5~10% | DB / Redis / Langfuse / Datadog |

**重点**：LLM API 占绝对大头，**先估算 LLM，再算其他**。

#### 外推公式

```
月成本 = 单次任务成本 × 每用户每日调用次数 × DAU × 30

单次任务成本 = LLM 输入 Token × 输入价 + LLM 输出 Token × 输出价
 + Tool 调用成本 + 重试 / 降级额外成本
```

**例子**：
```
单次任务成本 = 1.5 元（LLM 0.8 + Tool 0.5 + 重试 0.2）
每用户每日调用 10 次
DAU = 1000
月成本 = 1.5 × 10 × 1000 × 30 = 45 万元 / 月
```

一句话：**容量 / 成本估算 = 「单次任务成本 × 规模 → 月成本」——估算误差要接受 ±50%，但数量级必须对**。

### 为什么（Agent 开发要懂）

Agent 上线前必须算清成本——**不是「技术上能跑」就够了**：

具体后果（举四个最常见的）：

1. **融不到资**：产品上线发现月成本 50 万但用户付费 100 → **毛利 -49 万** → 项目死。
2. **定价错误**：成本 ¥1 / 次，定价 ¥0.1 / 次 → **每单亏 90%** → 用户越多亏越多。
3. **算错容量**：1000 DAU 时 QPS 50，没扩容 → **服务崩**。
4. **算错成本**：只算大模型，看不见 Tool 调用成本 → **低估 50%**。

Agent 没有容量 / 成本估算 = **上线就死**。

### 易混点

容量 / 成本估算常被和它的「邻居指标」混淆。**判错任何一个会让决策失准**——必须分清。

#### QPS vs 并发数

| | QPS | 并发数 |
|---|---|---|
| **定义** | 每秒请求数 | **同时**在跑的请求数 |
| **关系** | QPS × 平均响应时长 = 并发 | 并发 / 平均响应时长 = QPS |
| **适合** | 评估容量 | 评估服务器数 |

**判错会怎样**：把 QPS 当并发 → 服务器数算少；把并发当 QPS → 扩容算多。

#### 单次任务成本 vs 总成本

| | 单次 | 总成本 |
|---|---|---|
| **包含** | 一次成功调用的成本 | 单次 + 重试 + 降级 + 缓存失败 |
| **适合** | 简单估算 | 真实预算 |
| **关系** | 总成本 ≈ 单次 × 1.5~2（经验值） | — |

**判错会怎样**：只算单次成本 → **低估 50%**；真实生产有重试 / 降级 / 失败重投。

#### DAU vs MAU vs 同时在线

| | DAU | MAU | 同时在线 |
|---|---|---|---|
| **定义** | 每日活 | 每月活 | 峰值在线 |
| **用途** | 月成本估算 | 长期增长 | 容量规划 |
| **关系** | DAU ⊂ MAU | MAU ⊃ DAU | 同时在线 = DAU × 1%~5% |

**判错会怎样**：用 MAU 算月成本 → **多估 10 倍**；用 DAU 算容量 → **少估 10 倍**。

#### 峰值 QPS vs 平均 QPS

| | 平均 | 峰值 |
|---|---|---|
| **倍数** | 1x | **3~5x** |
| **适合** | 月成本 | 服务器数 |
| **何时** | 白天平均 | 早上 / 中午 / 晚上高峰 |

**判错会怎样**：按平均算容量 → 峰值来时服务崩。

#### 毛利率 vs 净利率

| | 毛利率 | 净利率 |
|---|---|---|
| **扣什么** | 收入 − 成本 | 收入 − 成本 − 税 − 运营 |
| **典型值** |50~70%（Agent 业务） | 20~40% |

**判错会怎样**：只看毛利率 → 忘了运营 /人工 / 营销成本 → 净利亏。

### 核心概念（变体 / 分支全扫）

容量 / 成本估算有 10 个变体。

#### 1. 单次任务 Token 模型

**单次任务成本拆解**：

```
单次任务 = 思考 (LLM) + Tool × N (LLM) + 流式输出 (LLM)
        = 输入 Token × 输入价 + 输出 Token × 输出价
        + Tool 调用成本（API价）
```

**例子**：
```
思考: 输入 2000 token × ¥3/1M = ¥0.006
Tool 决策: 输入 2500 × ¥3/1M = ¥0.0075
Tool ×3: 输入 500 × 3 × ¥3/1M = ¥0.0045
输出: 1000 × ¥15/1M = ¥0.015
合计: ¥0.033
```

**需求 1（单次 Token 模型）**：在 `apps/` 某个 Demo 上统计 100 次真实调用；输出单次任务平均 Token + 成本。

#### 2. DAU → QPS 模型

**推导链**：

```
1000 DAU
× 每用户每日调用 10 次
= 10000 次 / 日
÷ 86400 秒
= 0.12 QPS（平均）

但峰值 = 平均 × 3~5
= 0.4 ~ 0.6 QPS
```

**例子**：餐厅扩容 = 客人多 → 加桌 → 加服务员。

**需求 2（DAU → QPS）**：实现 DAU 到 QPS 的推导；输出峰值 QPS。

#### 3. 成本外推公式

```
月成本 = 单次任务成本 × 每用户每日调用 × DAU × 30

= ¥0.033 × 10 × 1000 × 30
= ¥9900 / 月（仅 LLM）
+ 服务器 ¥3000
+ 存储 + 观测 ¥1000
= ¥13900 / 月
```

**需求 3（成本外推）**：写一个成本外推公式；输入 DAU / 调用次数 / 单价 → 输出月成本。

#### 4. 三大成本项拆分

| 成本项 | 占总成本 | 例子（1000 DAU） |
|--------|---------|------------------|
| **LLM API** | **70%** | ¥9900 |
| **服务器** | 20% | ¥3000 |
| **存储 + 观测** | 10% | ¥1000 |
| **合计** | 100% | ¥13900 / 月 |

**例子**：家庭电费（月费几百）→ LLM Token（月费几千到几万）。

**需求 4（成本拆分）**：把月成本拆成 3 大块；输出饼图。

#### 5. 高峰 QPS × 3~5 倍冗余

**容量公式**：

```
容量 QPS = 峰值 QPS × 3 (冗余)

峰值 QPS = 平均 QPS × 3~5

0.12 × 3~5 × 3 = 1.1~1.8 QPS（需支持的容量）
```

**需求 5（容量冗余）**：按峰值 × 3 算容量；配置服务器数。

#### 6. 按用户分摊

**不同用户不同成本**：

| 用户类型 | 单次成本 | 原因 |
|----------|----------|------|
| **免费用户** | ¥0.05 | 用便宜模型 + 限流 |
| **付费用户** | ¥0.20 | 用贵模型 + 不限流 |
| **VIP 用户** | ¥1.00 | 实时 + 大模型 + 多次 Tool |

**需求 6（按用户分摊）**：按用户角色拆算单次成本；输出成本矩阵。

#### 7. 毛利率估算

```
收入 = 用户数 × 客单价 × 频次
成本 = 单次成本 × 调用次数

毛利率 = (收入 − 成本) / 收入

例：
收入：1000 DAU × ¥10/月 = ¥10000
成本：¥13900（上面估算）
毛利率 = (10000 − 13900) / 10000 = -39%（亏！）
```

**关键**：**月成本要先于收入算清楚**，定价才有依据。

**需求 7（毛利率）**：写一个毛利率计算器；输入收入 + 成本 → 输出毛利率。

#### 8. 不确定性区间

**乐观 / 中性 / 悲观**：

| 场景 | 单次成本 | DAU | 月成本 |
|------|----------|-----|--------|
| **乐观** | ¥0.02 | 500 | ¥3000 |
| **中性** | ¥0.05 | 1000 | ¥15000 |
| **悲观** | ¥0.10 | 2000 | ¥60000 |

**关键**：**用区间估算，不用单点**——给决策者留弹性。

**需求 8（区间估算）**：输出三档场景的成本表。

#### 9. 规模上限触发器

**何时扩容**：

| 指标 | 阈值 | 动作 |
|------|------|------|
| **QPS** | > 70% 容量 | 加 Server / Worker |
| **延迟 P99** | > 3s | 排查 / 扩容 |
| **成本 / 月** | > 预算 80% | 报警 + 优化 |
| **失败率** | > 5% | 排查 + 熔断 |

**例子**：餐厅扩容 = 客人多 → 加桌 → 加服务员 → 招厨师。

**需求 9（规模触发器）**：实现 4 类监控 + 自动告警。

#### 10. 成本看板

**看板上要有什么**：

| 指标 | 数据源 |
|------|--------|
| **每日 LLM 成本** | 各 API provider 用量 |
| **每日调用次数** | Agent Loop 日志 |
| **单次任务平均成本** | Token 总和 / 调用次数 |
| **按用户分摊** | user_id 维度聚合 |
| **毛利率** | 收入 / 成本 |

**需求 10（成本看板）**：实现 5 项指标采集 + dashboard；命中时告警。

### 例子

#### 餐厅扩容 vs Agent 扩容

餐厅加桌（人多了）→ Agent 加 Worker（请求多了）。

对应：**QPS 高 → 加 Worker**。

#### 家庭电费 vs LLM Token

家庭电费（月费几百）→ LLM Token（月费几千到几万）。

对应：**基础设施的固定支出**。

#### 出租车公司 vs Agent 公司

出租车公司（车数 × 单车日流水）→ Agent（QPS × 单次成本）。

对应：**规模化的成本外推**。

#### 单次任务成本拆解

思考 ¥0.006 + Tool ×3 ¥0.0045 + 输出 ¥0.015 = ¥0.033 → 一个月 ¥9900。

对应：**Token 累加的真实成本**。

#### 毛利率 -39%（亏）

收入 ¥10000，成本 ¥13900 → 亏 39% → 定价 ¥15/月 → 毛利回到 +35%。

对应：**毛利率倒推定价**。

#### 峰值 × 3 冗余

平均 QPS 0.12，峰值 × 3 = 0.36，再冗余 × 3 = 1.1 → 至少配 2 台 8 核服务器。

对应：**容量规划的实际数字**。
