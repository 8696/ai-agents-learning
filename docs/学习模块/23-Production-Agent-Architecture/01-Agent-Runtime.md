### 是什么

**Agent Runtime** 是把前面 22 个模块的**所有能力叠成一条完整的「用户请求 → Agent 回复」链路**——不是某一个工具，是**整体架构**。

#### 完整架构层次

```
用户 ──HTTP──► 客户端（前端）
 │
                  ▼
            ┌─────────────────────────────────┐
            │ API 网关层                       │
            │ - 鉴权 (OAuth/JWT)             │
            │ - 限流                          │
            │ - 请求路由 │
            │ - 流式响应头设置               │
            └────────────────┬────────────────┘
                             ▼
            ┌─────────────────────────────────┐
            │ 异步层（可选）                   │
            │ - 短任务 → 直接进 Loop │
            │ - 长任务 → 进任务队列 (BullMQ)  │
            └────────────────┬────────────────┘
                             ▼
            ┌─────────────────────────────────┐
            │ Agent Loop 层                   │
            │ - 思考 → 调 Tool → 思考 → ... │
            │ - 多模型路由（按难度选）         │
            │ - Prompt Caching（省 Token）    │
            │ - 最大轮次 / 超时控制           │
            └────────────────┬───────────────┘
                             ▼
            ┌─────────────────────────────────┐
            │ Tool Gateway 层                │
            │ - 用户身份 + Agent身份分离     │
            │ - Scope 校验 │
            │ - 限流 + 参数校验 │
            │ - 审计日志                      │
            └────────────────┬───────────────┘
                             ▼
            ┌─────────────────────────────────┐
            │ 下游服务（DB / API / 对象存储） │
            └────────────────┬────────────────┘
                             ▼
            ┌─────────────────────────────────┐
            │ 观测层（横切） │
            │ - Trace / Span（每步） │
            │ - 指标（耗时 / 成本 / 失败率）  │
            │ - 日志（脱敏）                  │
            └─────────────────────────────────┘
```

#### 每层的「取舍」

| 层 | 做什么 | 不做什么 | 关键取舍 |
|----|--------|----------|----------|
| **API 网关** | 鉴权 / 限流 / 路由 | 不做业务逻辑 | 简单 vs 复杂（Kong / Nginx / Serverless） |
| **异步层** | 长任务异步化 | 不做 Agent 逻辑 | 同步实现（快）vs 异步（不超时） |
| **Agent Loop** | 思考 + 调 Tool | 不直接调下游 | 固定流程（ReAct）vs 自编排 |
| **Tool Gateway** | 身份 + Scope + 审计 | 不做业务 | 强校验（安全）vs 弱校验（灵活） |
| **观测层** | Trace + 指标 + 日志 | 不做业务决策 | 全量采集（贵）vs 采样（漏） |

一句话：**Agent Runtime = 「把前面 22 个模块叠成一条能跑、能看、能调、能评的完整链路」**。

### 为什么（Agent 开发要懂）

**前 22 个模块都是「点」**——熔断 / 路由 / RAG / MCP / 评测 / 观测……**怎么把它们叠起来**是 Agent 单独的能力。

具体后果（举四个最常见的）：

1. **能力凑不齐**：Agent 写得很好，但生产跑起来超时 / 鉴权失败 / 工具失败时崩 → **不能上线**。
2. **观测缺失**：Agent 出错找不到是哪一步错 → **调试困难**。
3. **评测脱节**：改了 Agent 代码，不知道变好还是变差 → **盲调**。
4. **架构混乱**：每加一个能力堆一个新层 → **复杂度爆炸**。

Agent 没有 Runtime = **Demo 能跑，生产必崩**。

### 易混点

Agent Runtime 常被和它的「邻居机制」混淆。**判错任何一个会让架构失守**——必须分清。

#### Agent Runtime vs Agent Framework

| | Agent Runtime | Agent Framework |
|---|---|---|
| **做什么** | **把能力叠起来**（部署 +集成） | **SDK 帮你写 Agent**（开发） |
| **典型** | 完整服务（网关 + 队列 + Loop + Tool + 观测） | LangChain / Vercel AI SDK / OpenAI Agents SDK |
| **关注** | 生产部署 / 运维 / 监控 | 写 Agent 代码 |

**判错会怎样**：把 Framework 当 Runtime 用 → 写出来容易，部署 / 监控 / 评测都没人管。

#### 同步链路 vs 异步链路

| | 同步 | 异步 |
|---|---|---|
| **HTTP 边界** | 立刻返回（SSE 流式） | 立刻返回 task_id |
| **适合** | 短任务（< 60s） | 长任务（> 60s） |
| **关系** | 同步实现 + 异步 fallback | 异步实现统一 |

**判错会怎样**：长任务走同步 → HTTP 超时；短任务走异步 → 过度投入。

#### API Gateway vs Tool Gateway

| | API Gateway（前端） | Tool Gateway（Agent 内） |
|---|---|---|
| **位置** | 客户端 ↔ 服务端 | Agent ↔ 下游 Tool |
| **职责** | 鉴权 / 限流 / 路由 | 身份 + Scope + 审计 |
| **关系** | **两层都要** | — |

**判错会怎样**：只有 API Gateway → 用户身份没传到 Tool；只有 Tool Gateway → 外部攻击没挡住。

#### 观测 vs 监控

| | 观测 | 监控 |
|---|---|---|
| **做什么** | Trace + Span + 指标 + 日志（**完整视图**） | 实时告警 + dashboard（**当前状态**） |
| **适合** | 排查 / 调试 / 优化 | 故障响应 |
| **关系** | 监控靠观测的数据 | — |

**判错会怎样**：只监控不观测 → 知道「挂了」不知道「为什么挂」；只观测不监控 → 出问题没人告警。

#### 评测 vs 单元测试

| | 评测 | 单元测试 |
|---|---|---|
| **测什么** | LLM **答得对不对** | 代码**跑不跑得通** |
| **怎么测** | Golden Set + LLM-as-Judge | 输入输出断言 |
| **适合** | LLM 行为 | 业务逻辑 |

**判错会怎样**：用单元测试测 LLM 行为 → 答得「对」或「错」没标准；用评测测代码 → 代码错根本跑不通。

### 核心概念（变体 / 分支全扫）

Agent Runtime 有 10 个变体。

#### 1. 完整链路架构

**典型 6 层链路**（见「是什么 · 完整架构层次」ASCII 图）。

**例子**：餐厅（Agent Runtime）= 接待（API网关）→ 领位（鉴权）→ 厨房（Agent）→ 厨师（LLM/Tool）→ 出餐（响应）→ 收银（评测）。

**需求 1（完整链路架构）**：画出 6 层链路图；标出每层的职责 +关键依赖。

#### 2. 同步 / 异步边界判定

| 任务 | 链路 | 边界 |
|------|------|------|
| **简单问答** | 同步 + SSE | HTTP 60s 内 |
| **代码生成** | 同步 + SSE | HTTP 60s 内 |
| **长文档总结** | 异步 + 队列 | task_id + 轮询 / WS |
| **多步 Agent** | 异步 + 队列 | task_id + 步骤推送 |

**判定规则**：预期时长 > 60s → 异步；否则同步。

**需求 2（同步 / 异步边界）**：实现边界判定逻辑；同一任务两套实现。

#### 3. 鉴权与用户身份传递

**用户身份 → Agent → Tool 全程传递**：

```
1. 用户 OAuth / JWT → API Gateway 鉴权
2. Gateway 把 user_id 塞进请求 ctx
3. Agent Loop 收到 ctx；调 Tool 时带 user_id
4. Tool Gateway 校验 user_id + Scope
5. Tool 用 user_id 决定能看什么数据
```

**关键**：**user_id 一旦丢 = 跨用户数据泄露**。

**需求 3（鉴权 + 身份传递）**：实现 user_id 全链路传递；丢失时拒绝。

#### 4. Agent Loop 控制

**控制要素**：

| 控制 | 阈值 |
|------|------|
| **最大轮次** | 5~10 轮 |
| **单步超时** | 30s |
| **总超时** | 5min |
| **Token 上限** | 100K |
| **重复检测** | 同 Tool调 3 次相同 → 终止 |

**需求 4（Loop 控制）**：实现 5 维控制；超阈值时优雅终止 + 提示。

#### 5. Tool Gateway 集成

**Tool Gateway 在 Loop 和下游之间**——所有 Tool 必须经过：

```
Loop → Tool Gateway → 下游 Tool ↓
    身份 + Scope + 限流 + 审计
```

**需求 5（Tool Gateway）**：实现 Gateway 中间层；5 维校验（身份 /限流 / Scope / 参数 / 审计）。

#### 6. 多模型路由集成

**Loop 内调用 LLM 时**：

```
Agent Loop
  ↓
  Model Router（按难度选模型）
 ├─简单问答 → Haiku（小模型）
    ├─ 一般推理 → Sonnet（中模型）
    └─ 复杂规划 → Opus（大模型）
```

**降级**：主模型挂了 → 降级到备用模型。

**需求 6（多模型路由）**：实现 Router 在 Loop 内；主挂了自动降级。

#### 7. 缓存与加速

**三类缓存**：

| 缓存 | 缓存什么 | 省什么 |
|------|----------|--------|
| **Prompt Caching** | 长前缀（System + Tools） | 输入 Token |
| **Embedding Cache** | 文本 → 向量 | 重复 embed |
| **KV Cache** | 请求内 attention 状态 | 推理算力 |

**需求 7（缓存集成）**：开启 Prompt Cache + Embedding Cache；统计命中率。

#### 8. 观测层（Trace + 指标 + 日志）

**三件套**：

| 类别 | 工具 | 粒度 |
|------|------|------|
| **Trace / Span** | Langfuse / LangSmith / OpenTelemetry | 每步 LLM / Tool |
| **指标** | Prometheus / Datadog | 耗时 / 成本 / 失败率 |
| **日志** | 结构化 JSON + 脱敏 | 入参 / 出参 / 错误 |

**需求 8（观测层）**：实现 Trace + 指标 + 日志三件套；每步有 Span。

#### 9. 评测门禁（CI 拦截）

**改 Agent 代码 → 跑 Golden Set 评测 → 不达标 →拒绝合并**：

```yaml
# CI 流程
on: pull_request
jobs:
  eval:
    steps:
      - run: yarn eval # 跑 Golden Set
      - if: failure()
        run: exit 1     # 不达标拒绝合并
```

**需求 9（评测门禁）**：CI 接 Golden Set；不达标拒绝合并。

#### 10. 全链路压力测试

**压测场景**：

| 场景 | 验证什么 |
|------|----------|
| **100 并发** | API 网关限流 / Loop 不挂 |
| **1000 长任务** | 队列不爆 / Worker 不挂 |
| **流量突发** | 熔断触发 / 降级生效 |
| **Tool 慢返回** | 超时控制 / 不拖死 |

**需求 10（压测）**：起 4 个压测场景；输出延迟 / 失败率 / 资源占用报告。

### 例子

#### 餐厅 vs 便利店

餐厅（Agent Runtime）= 接待（API网关）→ 领位（鉴权）→ 厨房（Agent）→ 厨师（LLM/Tool）→ 出餐（响应）→ 收银（评测）→ 便利店（无 Runtime）= 自助服务，不分层。

对应：**Agent Runtime 是「分层服务」**。

#### 公司 vs 小作坊

公司（Agent Runtime）= 各部门协同 → 小作坊（无 Runtime）= 一个人全包。

对应：**公司 = 各层分工；作坊 = 全靠一个人**。

#### 流水线工厂 vs 手工作坊

流水线工厂（Agent Runtime）= 每道工序专门人 → 手工作坊（无 Runtime）= 一个师傅全做。

对应：**Runtime = 流水线；无 Runtime = 手工**。

#### 同步 vs 异步边界

简单问答（同步 + SSE）vs 长文档总结（异步 + 队列）→ 同一任务边界判定。

对应：**预期时长 > 60s → 异步**。

#### API Gateway vs Tool Gateway

API Gateway（前端鉴权）vs Tool Gateway（Agent 内鉴权）→ 两层都要。

对应：**用户身份全程传递**。

#### 评测门禁

改 Agent 代码 → CI 跑 Golden Set → 不达标 → 拒绝合并。

对应：**评测是 Agent 生产的最后一道门**。
