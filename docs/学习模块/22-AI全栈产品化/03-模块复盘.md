### 一句话讲完这个模块

Agent 产品化的核心 = **让用户看懂 Agent 在做什么**——两件事：流式 Markdown 不能闪（结果层稳定）+ Agent Steps 把过程结构化（过程层透明）。**Agent 不能做成只能看到最终答案的黑盒**——这一点做好了，产品感立刻上一个台阶。

### 这些条怎么连成一条线

本模块两条外部小节不是平行清单，而是**同一体验的两个层**——**过程层 + 结果层**，互补：

```
┌──────────────────────────────────────────────────────┐
│                  Agent 执行一次任务                    │
│                                                       │
│  ┌───────────────────────────────────────────────┐  │
│  │ 过程层（02 Agent Steps UI）                   │  │
│  │ 把「Agent 在做什么」结构化展示                  │  │
│  │ ✓ 思考 → ⟳ 调工具 → ✓ 调工具 → ▶ 输出      │  │
│  └───────────────────────────────────────────────┘  │
│                                                       │
│  ┌───────────────────────────────────────────────┐  │
│  │ 结果层（01 流式 Markdown）                     │  │
│  │ 把「Agent 给的答案」流式渲染                  │  │
│  │ [最终输出（流式）：HTTPS 是...]                │  │
│  └───────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘
```

- **过程层（02）**：管**「Agent 怎么得到这个答案」**——用户看到思考 / 调工具 / 完成的每一步
- **结果层（01）**：管**「Agent 给我的答案长什么样」**——用户看到流式渲染的最终 Markdown

两者关系是**互相补充**——过程层让用户**信任** Agent，结果层让用户**消费** Agent 的输出。

### 最容易记错的三条

1. **流式 Markdown ≠ 流式纯文本**——前者含语法（标题 / 列表 / 加粗 / 代码块），解析时**会闪**。把流式纯文本思路搬过来 → 没考虑 Markdown 语法抖动 → 上线后满屏闪。
2. **步骤 UI ≠ 流式 UI**——前者离散（步骤 1/2/3），后者连续（一行字流出来）。两者**不互换**——步骤用流式 UI → 看不到 Tool 调用；流式用步骤 UI → 看不到字出来。
3. **折叠 ≠ 隐藏**——折叠**保留内容**（点开看），隐藏**丢掉内容**。长流程步骤都隐藏 → 用户看不到关键步骤；都展开 → 屏幕塞满。

### 踩过的坑（跨小节）

写到这里，本对话未踩到具体代码坑（无 Demo 落地）。记录两条**预防性踩坑**：

- **「朴素重渲染」= CPU 飙升**：长内容（1000+ 字）+ 朴素 Markdown 重渲染 → O(n²) 复杂度 → 浏览器卡顿（特别是手机 / 低端机）。**判错代价**：用户体验明显抖动。模块 01「核心概念 2 朴素重渲染的代价」专门拉出一节；做真实项目时优先用 React 增量渲染 + 库（Streamdown / react-markdown + remark-gfm）。
- **「全显示 spinner」= 看不到流式输出**：把所有状态（思考中 / 调工具中 / 流式输出 / 完成 / 错误）都显示成 spinner → 用户看不到 Agent 输出的字。**判错代价**：流式体验丧失，等于回到非流式。模块 02「核心概念 2 思考中 spinner vs 完成文本」专门拉出一组对比；做真实项目时 spinner 状态只用于「无内容」时刻（思考中 / 调工具中），流式输出必须显式区分。
