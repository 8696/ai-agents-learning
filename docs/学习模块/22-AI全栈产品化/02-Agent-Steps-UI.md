### 是什么

**Agent Steps UI** 是把 Agent 的**执行轨迹**（trajectory）**结构化展示**给用户的界面——让用户能看清「Agent 现在在干什么」。

Agent一次执行通常分**三个状态**：

| 状态 | Agent 在干什么 | 用户需要看到什么 |
|------|---------------|------------------|
| **思考中（Thinking）** | LLM 在生成下一步计划 | 「在想什么呢」 / spinner |
| **调工具中（Calling Tool）** | Agent 在调一个 Tool（搜索 / 数据库 / API） | 调哪个 Tool / 输入什么 / 进度 |
| **完成（Done / Streaming）** | 流式输出最终答案 | 完整结果 +耗时 + token + 成本 |

**核心**：用户**看不懂 Agent 内部**——UI 把内部状态**翻译**成可读的步骤 + 进度 + 内容。

Agent 三大状态可视化 = 三个层次：

```
┌────────────────────────────────────────────────┐
│ Agent任务：写一篇文章                          │
├────────────────────────────────────────────────┤
│ ✓ 步骤 1: 思考 │  ← 思考完成
│   决定先搜索「HTTPS 原理」                       │
├────────────────────────────────────────────────┤
│ ⟳ 步骤 2: 调工具 search_web                    │  ← 调工具中（spinner）
│   输入: {"query": "HTTPS 原理"}                │
├────────────────────────────────────────────────┤
│ ○ 步骤 3: 调工具 write_file                    │  ← 未开始
├────────────────────────────────────────────────┤
│ ▶ 输出（流式）                                  │  ← 流式输出最终答案
│   HTTPS（超文本传输安全协议）是...               │
└────────────────────────────────────────────────┘
```

一句话：**Agent Steps UI = 「让用户看懂 Agent 内部」的结构化展示——三个状态 + 步骤折叠 + 错误态 + 轨迹**。

### 为什么（Agent 开发要懂）

Agent 的执行对用户是**黑盒**——LLM 在想什么、调了什么 Tool、为什么这么决定：

- **传统 chat**：LLM 一次性回复 → 用户看到结果
- **Agent**：LLM 多步 +调 Tool + 思考 → 用户看到结果，但**不知道过程**

具体后果（举四个最常见的）：

1. **Agent 卡住**：用户问「Agent 怎么不动了」→ 实际上 Agent 在调一个慢 Tool → 用户刷新页面 → 任务重复 → **资源浪费**。
2. **Agent 答错**：用户问「为什么 Agent 没找到？」→ 实际上 Agent 没调搜索 Tool → 用户看不到 → 误以为是 LLM 不行。
3. **调试困难**：Agent 输出错 → 开发者找不到是哪一步错 → 没法修。
4. **不信任**：用户不知道 Agent 在干什么 → 不敢用。

Agent 没有 Steps UI = **用户看不懂 Agent = 用不起来**。

### 易混点

Agent Steps UI 常被和它的「邻居机制」混淆。**判错任何一个会让用户看不懂**——必须分清。

#### 步骤 UI vs 流式 UI

| | 步骤 UI | 流式 UI |
|---|---|---|
| **单位** | **离散的步骤**（步骤 1/2/3） | **连续的文本**（一个字一个字） |
| **状态** | 多状态切换 | 单状态（生成中 → 完成） |
| **适合** | Agent Loop / Tool 调用 | LLM 流式输出 |

**判错会怎样**：把流式 UI 当步骤 UI → 用户看到一行字在变，但不知道 Agent 在调什么 Tool。

#### 思考中 spinner vs 完成文本

| | 思考中 | 完成文本 |
|---|---|---|
| **内容** | **没有**（Agent 还在想） | **有**（LLM 在生成最终答案） |
| **UI** | spinner +「思考中…」| 流式字符 |
| **耗时** | 1~5 秒 | 3~30 秒 |

**判错会怎样**：把所有状态都显示成「spinner」→ 用户看不到流式输出 → 体验差。

#### 调工具中 vs 工具完成

| | 调工具中 | 工具完成 |
|---|---|---|
| **状态** | **在等 Tool 返回** | Tool 已有返回值 |
| **UI** | spinner + Tool 名 + 输入 | ✓ + 返回值摘要 |
| **耗时** | 1~30 秒（看 Tool） | 完成 |

**判错会怎样**：把工具完成当调工具中 → 用户永远看不到工具返回 → 不知道 Agent 拿没拿到数据。

#### 步骤折叠 vs 步骤隐藏

| | 折叠 | 隐藏 |
|---|---|---|
| **内容** | **保留**（点开看） | **丢掉**（找不到） |
| **适合** | 长流程（多步骤） | 不重要步骤 |
| **UI** | 「展开/收起」按钮 | 完全不见 |

**判错会怎样**：把长流程步骤都隐藏 → 用户看不到关键步骤；都展开 → 屏幕塞满。

#### 轨迹可视化 vs 日志

| | 轨迹可视化 | 日志 |
|---|---|---|
| **形态** | 结构化 UI（树状 / 列表） | 文本流 |
| **查找** | 按步骤 / 按 Span / 按耗时 | 全文搜索 |
| **适合** | 用户 / 客服 | 开发排查 |

**判错会怎样**：只给日志不给轨迹 → 用户看不明白；只给轨迹不给日志 → 开发者排查难。

### 核心概念（变体 / 分支全扫）

Agent Steps UI 有 10 个变体。

#### 1. Agent 三状态可视化

**核心映射**：

| Agent 内部状态 | UI 表现 |
|---------------|---------|
| **思考中** | spinner +「Agent正在思考…」|
| **调工具中** | 步骤卡（Tool 名 + spinner + 输入参数） |
| **流式输出** | 流式字符 + 打字机效果 |
| **完成** | ✓ 标记 + 最终答案 + 元信息（耗时 / token） |
| **错误** | ✗ 红色 + 错误信息 + 重试按钮 |

**例子**：厨房烹饪流程（步骤式）洗菜→切菜→炒→装盘，用户看着知道在做什么。

**需求 1（三状态可视化）**：实现 Agent 内部状态 → UI 状态映射；5 种状态全覆盖。

#### 2. 思考中的 UI

**常见做法**：

| 做法 | 适合 |
|------|------|
| **spinner +「Agent 正在思考…」** | 通用 |
| **流式未完成文本**（草稿纸动效） | 长思考 |
| **动态短语**（「正在分析问题…」「正在搜索…」） | 高级感 |

**例子**：导航地图（步骤式）告诉你「现在右转」「再直行 500 米」；指南针（流式）只告诉你方向。

**需求 2（思考中 UI）**：实现 spinner + 动态短语；不卡顿；自动滚动到可见区域。

#### 3. 调工具中的 UI

**步骤卡展示**：

```
✓ 步骤 1: 思考                        耗时 1.2s Agent 决定先搜索「HTTPS 原理」

⟳ 步骤 2: 调用工具 search_web          耗时 3.4s
  输入: { "query": "HTTPS 原理" }
  等待返回...
```

**需求 3（调工具中 UI）**：实现步骤卡；Tool 名 + 输入 + spinner + 状态。

#### 4. 完成的 UI

**最终结果 + 元信息**：

```
▶ 最终输出（耗时 8.5s ·1.2k tokens · $0.02）

[HTTPS 流式超文本...]
```

**元信息**：耗时 / Token / 成本 / 工具调用次数。

**需求 4（完成 UI）**：实现最终输出区 + 元信息（耗时 + token + 成本 + 工具次数）。

#### 5. 步骤折叠 / 展开

**长流程折叠**：

```
[Agent 任务: 写一篇文章]
▼步骤 1: 思考
  Agent 决定先搜索...
▶ 步骤 2: 调工具 search_web  (自动展开最新)
  输入: ...
 ✓ 返回: 找到 3 条结果
▲ 步骤 3: 调工具 write_file
  ...
```

**规则**：默认折叠历史步骤，自动展开正在执行的步骤。

**需求 5（步骤折叠）**：实现「历史折叠 + 当前展开」；长流程可滚动。

#### 6. 错误态 UI

**失败步骤**：

```
✗ 步骤 3: 调工具 search_web (失败)
  错误: HTTP 503 Service Unavailable
  [重试此步]  [重试全部]
```

**错误信息**：错误码 / 错误描述 / 重试按钮。

**需求 6（错误态 UI）**：实现失败标记 + 错误信息 + 重试按钮。

#### 7. 流式 + 步骤并存

**两个区域**：

```
┌─────────────────────────────┐
│ Agent步骤：                  │
│ ✓ 思考                       │
│ ⟳ 调工具 search_web         │
│ ✓ 调工具 write_file         │
└─────────────────────────────┘

┌─────────────────────────────┐
│ 最终输出（流式）：            │
│ [HTTPS 是一种...]            │
└─────────────────────────────┘
```

**关键**：**步骤区显示「过程」**；**流式区显示「结果」**；两者分开。

**需求 7（流式 + 步骤并存）**：实现步骤区 + 流式区两个独立 UI；同步更新。

#### 8. Trajectory 可视化（Langfuse / LangSmith 风格）

**结构化 Trace**：

```
[Trace: agent_task_001]  总耗时 8.5s
├─ [Span1: thinking]    1.2s · 200 tokens
├─ [Span 2: search_web] 3.4s · 100 tokens
├─ [Span 3: thinking]    0.8s · 150 tokens
├─ [Span 4: write_file] 1.1s · 50 tokens
└─ [Span 5: streaming]  2.0s · 800 tokens
```

**特点**：树状结构 + 耗时 + token + 嵌套 Span。

**需求 8（Trajectory 可视化）**：实现 Langfuse 风格的 Trace 树；每步一个 Span；可点击展开详情。

#### 9. 可交互步骤

**用户能操控 Agent**：

| 操作 | 做什么 |
|------|--------|
| **点击展开参数** | 看调 Tool 的完整输入输出 |
| **重试此步** | 从失败步骤重跑 |
| **从此步继续** | 跳过失败步骤，从下一步继续 |
| **编辑后重跑** | 修改参数后再跑 |

**需求 9（可交互步骤）**：实现步骤卡可点击展开 + 重试 + 继续 + 编辑。

#### 10. A11y 与键盘操作

**无障碍**：

| 操作 | 怎么做 |
|------|--------|
| **屏幕阅读器** | `aria-live` 区域 + `role="status"` |
| **Tab 导航** | 所有步骤卡可键盘聚焦 |
| **Enter 操作** | Enter 展开步骤 / 重试 |
| **对比度** | 颜色对比度 ≥ WCAG AA |

**需求 10（A11y）**：实现 aria-live + Tab + Enter；颜色对比度合规。

### 例子

#### 厨房烹饪流程 vs 外卖配送

厨房烹饪流程（步骤式）洗菜→切菜→炒→装盘 → 外卖配送（流式）骑手在路上，用户只知道在送。

对应：**Agent Steps UI = 厨房流程；显示「在做什么」**。

#### 导航地图 vs 指南针

导航地图（步骤式）告诉你「现在右转」「再直行 500 米」→ 指南针（流式）只告诉你方向。

对应：**步骤 UI = 导航地图；具体动作可看**。

#### 聊天 vs 进度条

聊天（流式）边打边看 → 进度条（步骤式）「处理订单中…完成订单…」

对应：**Agent 两种输出模式：步骤（过程） + 流式（结果）**。

#### 失败步骤

「搜索失败」→ 红色 ✗ + 错误信息 + 重试按钮 → 用户知道哪步失败、能修。

对应：**错误态 UI 让用户参与修复**。

#### Langfuse Trace树

完整 Trace 树：思考 → 调工具 → 思考 → 调工具 → 流式输出 → 每步 Span 可展开。

对应：**Trajectory 可视化 = 给开发者调试用**。

#### 重试 + 继续

Agent 在步骤 3 失败 → 用户点「重试此步」 → Agent 从步骤 3 重跑 → 成功 → 用户能看到完整结果。

对应：**可交互步骤 = 用户能操控 Agent**。
