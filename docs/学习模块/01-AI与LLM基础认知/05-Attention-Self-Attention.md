# **Attention / Self-Attention**：每个词根据整句其它词算权重

> 对应模块：[模块 01 · AI & LLM 基础认知](./README.md) · 小节进度第 5 条

- **来源**：本对话（陪跑 Coach）；无外部 URL
- **状态**：已沉淀

### 是什么

**Self-Attention（自注意力）做什么**：让序列里每个 token 同时看所有其它 token，按「我对你有多关注」算一组权重（0~1 之间、加起来等于 1），再用这组权重把所有 token 的内容加权混合，得到一个新的、融合了整句上下文的向量。

**一句话**（模块表里的原文）：**每个词根据整句其它词算权重**。

---

**关键步骤**（不推公式，只走流程）：

1. **每个 token 同时准备三套东西**：Q（Query，查询）、K（Key，键）、V（Value，值）。三者由**同一个输入向量**经过**三套不同的可学习线性变换**得到 ——同一份输入可以产出三种不同的「投影」。
2. **算关注度（粗分）**：每个 token 用自己的 Q 去和所有 token 的 K 比对，得到「我对每个位置的关注度」。这个数还没归一化，是任意浮点数（可能是负的、也可能很大）。
3. **归一化（softmax）**：把上一步的分数整体过 softmax，强行变成 0~1 之间、加起来正好等于 1。这就是 **attention weights（注意力权重）**。
4. **加权求和**：用这套权重去乘所有 token 的 V，加起来，就是这个 token 的 Self-Attention 输出。

```text
每个 token:
  Q = 输入 · W_Q
  K = 输入 · W_K
  V = 输入 · W_V           ← 三套可学习矩阵

关注度（未归一化）:
  score[i, j] = Q[i] · K[j]   ← 第 i 个 token 对第 j 个位置的关注度

归一化（softmax）:
  weight[i, j] = softmax_j(score[i, i..N])   ← 一行加起来 = 1

Self-Attention 输出:
  out[i] = Σ_j  weight[i, j] · V[j]          ← 按权重把所有 V 加起来
```

---

**两个关键性质**：

- **整句同时算（并行）**：所有位置独立算 Q/K/V、独立算关注度、独立加权求和。不像 RNN 必须等前一个算完才能算下一个，Self-Attention 一锅端。
- **软分配**：权重是连续的、所有人都有份，不是「只选一个最相关的」。是「按比例混合」，不是「挑一个」。

---

**Q / K / V 的物理意义**（最容易混，必须各自讲清）：

- **Q = "我要找什么"**：我这个 token 想了解什么信息
- **K = "我能提供什么标签"**：我这个 token 能被用来匹配什么
- **V = "我的实际内容"**：我这个 token 的语义表示本身

同一份输入向量经过**三套不同的可学权重矩阵**（记作 W_Q / W_K / W_V），产出 Q/K/V。所以 Q/K/V 不是输入本身，是输入的**三种投影**。这跟「把同一份资料印成三份、贴不同的标签」是一回事。

---

**附带机制：多头（Multi-Head）**（本条不展开，只点到）：

实际模型不只一组 Q/K/V，而是 8 组或 16 组并行学。每组关注不同侧面（句法、指代、长距离依赖…）。最后把多组输出拼起来再过一次线性变换。这就是为啥叫 Transformer：它把注意力的不同侧面**并起来**。

---

### 为什么（Agent 开发要懂）

不懂 Self-Attention，做 Agent 会在这些地方翻车：

- **Context Window 成本估算的根**：Self-Attention 的算力是 **n²**（n 是序列长度）。Context 翻一倍、算力变四倍。这就是为啥长上下文模型贵、显存爆炸、KV cache 是工程优化的核心 —— 全部来自 Self-Attention 的 n²。上一节 [Context Window](./03-Context-Window.md) 给了现象，本节是机制。
- **RAG 检索调参**：RAG 用的「语义相似度」本质上就是 Q·K 这一类向量相似度。搞不清 Q/K/V，就调不好 embedding 模型、chunk 策略、reranker。
- **Agent 工具调用的概率解读**：模型不是「挑一个工具调」，是给所有工具算权重后采样概率最高的调用 —— 这就是 Self-Attention 的「软分配」思路延伸到工具选择。模块 05 落到代码上。
- **推理加速 / KV cache**：Self-Attention 的 K 和 V 会被缓存（KV cache），所以长对话推理才不会每生成一个 token 都重新算一遍。不懂 Self-Attention，看不懂任何推理优化文档。模块 19 用得上。
- **面试 / 架构串讲**：模块 23 收口时要向人讲清「Transformer 凭啥吃掉 RNN/CNN」—— 本节就是核心证据。

### 易混点

| 对比 | 差在哪 | 判错会怎样 |
| ---- | ------ | ---------- |
| **Self-Attention vs 一般 Attention** | Self = "自己问自己序列里的其它位置"；一般 Attention（Decoder 用 Encoder 输出的那种）= "我问别人的输出"。Self 是 Attention 的**特例**。 | 以为 Decoder 里那种跨序列的也叫 Self-Attention，其实那种是 cross-attention |
| **Self-Attention vs RNN** | RNN 顺序处理、必须等前一个算完；Self-Attention 所有位置**同时算**。RNN 长距离会遗忘、Self-Attention **全局视野**。 | 用 RNN 思路理解 Transformer，会以为它是「一个一个往后推」、远距离一定忘 |
| **Self-Attention vs CNN** | CNN 只能看窗口（局部感受野）、Self-Attention 看**全句**（全局）。 | 误以为 Transformer 也只能看邻近 token，其实它「看多远都行」 |
| **Q vs K vs V** | Q 是「我的需求」、K 是「我能匹配啥标签」、V 是「我的内容」。同一输入经**三套不同可学习矩阵**得到，不是输入本身。 | 把 Q/K/V 当成「输入的三个名字」→ 不理解为啥要三套独立变换 |
| **Soft vs Hard 注意力** | Soft：所有位置按 0~1 概率混合，**可微**；Hard：只选一个位置，不可微、训不动。 | 用 Hard 思路理解「模型挑了哪个词」→ 实际它每个词都用了，只是比例不同 |
| **Self-Attention vs 池化/平均** | 池化是「大家各贡献一份等比例」，Self-Attention 是「按相关性动态调整比例」。 | 误以为 Self-Attention 就是 fancy 一点的平均 |
| **Self-Attention vs Context Window** | Attention 决定「装进来的 token **彼此怎么联系**」；Window 决定「能装**多少** token」。一个管怎么看、一个管桌子多大。 | 以为「Attention 很强所以窗口无限」—— 算力和显存仍给窗口封顶 |
| **一次 forward vs 一次 SA**(本对话新) | 一次 forward 含 **L 层** Transformer Block(常 96 层),**每层**跑一次 SA。Decoder 还要自回归,每蹦一字重开一次 forward。一句话推理 = **L × N 次** 圆桌(n = 当前序列 token 数)。 | 以为"模型只看一眼就跑完了"——其实**内层并行 + 中层堆叠 L 层 + 外层自回归 N 轮**,三层都对、别混。 |

### 例子

每个核心对象自己的例子（不共用总类比）。

---

**Self-Attention 整体走一遍 → 会议室举牌打分**

5 个人围坐开「猫吃鱼」这句话的复盘会。每个人手里都拿着同一份原始资料（三个词的向量）。每人**同时**举三块牌子：

- 第一块写「我能被怎样匹配」（K）
- 第二块写「我在找什么信息」（Q）
- 第三块写「我发言的实际内容」（V）

然后每个人用自己 Q 去和**所有**人 K 比对，给「我对每个同事的关注度」打个分（一个 0~1 之间、加起来等于 1 的权重）。最后按权重把所有人的 V 混合成「我对这句话的综合理解」。

**关键**：5 个人**同时**举牌打分，不是排成一队 1→2→3→4→5。这跟 RNN 的「传话游戏」完全不同 —— 见下面独立对比。

---

**Q / K / V → 查通讯录找朋友**

你想找「能帮我修电脑的朋友」。

- **Q**（你的需求）= 「能修电脑」
- **K**（通讯录里每个人的标签）= 「会修电脑 / 会做饭 / 会开车」... 每个朋友有一组标签
- 匹配度 = Q · K 的余弦相似度 = 「你的需求」和「这个朋友的标签」有多契合
- **V**（朋友本人的信息）= 联系方式、住址、其它属性

匹配度高的朋友（「小明」标签是「会修电脑」），他的 V 在你最终结果里占比就大。匹配度低的（「小红」标签是「会做饭」），占比就小。

**三个东西不是同一份**：你的 Q 跟小明 K 算出的匹配度，只决定「小明的 V 进来多少」，**不决定**「小明的 V 进来啥」。

---

**加权求和 → 调鸡尾酒 / 按方抓药**

**鸡尾酒版**：一杯自由古巴 = 朗姆酒 40% + 可乐 50% + 柠檬汁 10%。每种原料的比例就是 attention weight，所有比例加和 = 100%。Self-Attention 的输出就是这种「按比例混合的鸡尾酒」，不是「只放一种酒」（那是 Hard 注意力）。

**按方抓药版**：医生开方「A 药 30% / B 药 50% / C 药 20%」，抓药师傅按这个比例从三个罐子里各抓一点混成你那一包。这包药 = 加权求和的结果。

---

**整句并行 vs 顺序 → 大厨 5 口灶 vs 一口锅流水线**

- **大厨模式（Self-Attention）**：5 口灶同时开，5 个菜一起炒。没人等别人。
- **流水线模式（RNN）**：一口锅，菜 1 做完才做菜 2，做到菜 5 时菜 1 已经凉了（信息失真）。

代价：5 口灶要 5 倍灶台面积 —— **并行 = 多核 = GPU 友好 = 显存吃得多**。

---

**Self-Attention vs RNN → 传话游戏 vs 圆桌会议**

- **传话游戏（RNN）**：1 号 → 2 号 → 3 号 → 4 号 → 5 号。5 号听到的内容已经经过 4 次转述，「猫」可能已经变成了「加菲猫」。
- **圆桌会议（Self-Attention）**：5 号直接听 1/2/3/4 各自的原话，没有中间人转述。

代价：圆桌会议每人要把其它 4 个人的话都听一遍并打分，**总工作量是 n × n**（n²），传话游戏只是 n。这就是 Context Window 有上限、KV cache 是工程核心的根本原因。

---

**Self-Attention vs CNN → 望远镜看全场 vs 只能看邻座**

- **CNN** 像坐在大礼堂最后一排、用望远镜只能扫到前 5 排。看得清、看得快，但不知道 30 排开外发生了什么。
- **Self-Attention** 像坐在会议室正中央、可以转头看任何人。没有「看不到」的距离限制。

代价：每多一个人，会议室里每人都要重新给别人打分（n²），望远镜队却几乎不变。

---

**多头 → 多人评审一篇稿**

一篇文章好不好，5 个评委同时打分：

- 评委 A 看逻辑通不通
- 评委 B 看文笔好不好
- 评委 C 看数据硬不硬
- 评委 D 看受众对不对
- 评委 E 看标题吸不吸睛

5 个人打分后拼起来，比 1 个人打分全面得多 —— **Multi-Head Attention 就是不止一组 Q/K/V，而是 8 组或 16 组并行学**，每组关注不同侧面。Transformer 这名字就来自「把多种关注并起来」。

---

**和上一节 Context Window 串起来（承上启下）**

[Context Window](./03-Context-Window.md) 给的现象：长 context 贵、慢、中间容易被忽略。本节给机制：算力 n² 是「贵+慢」的根；中间被忽略（lost in the middle）跟 attention 权重分布有关（U 型 = 两端高、中间低）。两条连起来看才完整。

---

**完整一次 forward 走查 · 「猫喜欢吃什么？」**

把上面所有机制在一条真实句子上串一遍。**数字 = 当前句子的真实 token 数 n**,不做任何编造。这里走的是**最直接能讲清机制**的版本,不做任何"够看"的凑数。

```text
用户问题(原文):"猫喜欢吃什么？"

第 0 步 · 分词
  "猫 喜欢 吃什么 ?"                    ← 切法按各 tokenizer 不同,这里取能讲清机制的版本
  [BOS] [t_猫] [t_喜] [t_欢] [t_吃] [t_什] [t_么] [t_？]   ← n = 8

第 1 步 · Embedding
  每个 t_i → x_i ∈ R^d (d 由模型定,常 4096)              ← 词表查表,不推公式

第 2 步 · 一次 forward 在 Transformer Block 里做了什么
  一次 forward = L 层 Block 串行堆叠(L = 96 量级)
  每层 Block = 一次 Self-Attention + 残差 + LayerNorm + FFN + 残差 + LayerNorm
  注意:Self-Attention **每层跑一次**,**整次推理跑 L 次**

第 3 步 · 第一次 Block 第 1 层 Self-Attention(n = 8,8 把椅子)
  8 把椅子同时算:
    Q_i = x_i · W_Q
    K_i = x_i · W_K
    V_i = x_i · W_V
  每人 Q 对所有 K 比对 → 8 × 8 = 64 个浮点分数
  每行过一次 softmax → 8 行,每行加和 = 1 → 8 × 8 权重矩阵
  每行用自己权重 × 所有 V → 8 个新向量(每个里**所有人都有份,只是比例不同**)
  送进 FFN → 进 Block 2 → ... → 进 Block L

  提示:第一层权重通常抓**句法 / 位置**(本句里 "喜" 跟 "欢" 的权重会高);中层之后才慢慢抓到**长程语义**(本句里 "什么" 跟 "吃" 隔了 2 个 token、仍然高关注——因为是"吃什么")。

第 4 步 · 最后一层 → "下一个字"的概率
  last_hidden (通常用最后一个 token 那一位的向量) × W_vocab → logits ∈ R^词表
  softmax(logits) → 整个词表的概率分布(加和 = 1)         ← **这里的 softmax 跟 SA 那次 softmax 不是同一次**!
  抽样 → 假设抽中"鱼" → 自回归开始

第 5 步 · 自回归(外层串行):每蹦一字 n + 1
  输入 "猫 喜欢 吃什么 ?"  n=8    → 抽 "鱼"   → n=9
  输入 "猫 喜欢 吃什么 ? 鱼" n=9 → 抽 "。"   → n=10
  输入 "猫 喜欢 吃什么 ? 鱼 。" n=10 → 抽 [EOS] → 停

  n 每蹦一字涨 1,圆桌每轮重开——n=8 是输入 token 数,**不是**输出 token 数。
```

> **三层循环的拆法**(本对话踩到的,显式记下来):
>
> | 层 | 范围 | 是不是循环 |
> |---|---|---|
> | **内层**(一次 forward 内的一次 SA) | n 把椅子**同时**算 | **并行,不循环** |
> | **中层**(一次 forward 内部) | L 层 Block 串行堆叠 | **串行** |
> | **外层**(Decoder 一直蹦字) | 每生成一个 token 重开一次 forward | **串行**(自回归) |
>
> 之前只说"不是循环"只说了内层,没说清外层——学习者追问时抓得对。三层都对,不要混。

> **KV cache 在省什么**:
> 每重开圆桌,Q 重算(新 token 的 Q 一定要算);K / V 之前位置的全部**缓存复用**。这是不懂 Self-Attention 就看不懂 vLLM / TGI 等推理框架的根本原因。

### 我追问过的

- 问了：圆桌会议 5 个人开会，当前最匹配的是第一个人的话，剩下的人是不是一直按那个逻辑在每匹配完一个字之后循环？→ 答在「易混点」下半段 + 「例子」开头：Self-Attention 是**软分配**(所有 token 全用、只是权重不同)，不是"挑一个最相关的"；内部是**所有位置同时算**而非串行循环。循环是**外层**(Decoder 每生成一个 token 就重跑一次 Attention)，不是内层。追问里"挑出当前最匹配的那一个 + 剩下人循环"的直觉是 RNN 思路,不是 Self-Attention。
- 问了：圆桌 5 个人是怎么定出来的？模型怎么知道是 5 个人？→ 答在「为什么」n² 段 + 「易混点」Self-Attention vs Hard 注意力 + 这一轮的"圆桌人数 = n"：**圆桌人数 = 当前输入切完 token 的长度 n**,不是模型挑的、也不是固定数。Self-Attention 对"几个人"无偏好,n 个 token 在场就 n 个人开会,n×n 个匹配分数一次算出。模型不挑人、所有人按比例混合。追问里"挑出最匹配的固定几个人"的画面把 Self-Attention 误想成 Top-K 检索,实际它是**全员参与**。这个误解跟 Hard 注意力（只选一个位置）同一根,已在易混点列出。
- 问了（紧接上一条,追问比喻数字本身）：5 这个数字是怎么定的？为什么是 5？→ **5 不是任何人定的,是 Coach 讲「猫吃鱼」时为了画面举牌人数够看顺手编的**;真实圆桌人数 = 当前输入切完 token 后的 token 数 n。机制根上 n 唯一受训练时 context window 封顶(n ≤ window − 预留输出)。**比喻里的数字不能让学习者误以为是机制里的数**——这次把"猫吃鱼"硬凑成 5 个人是错位比喻,下次讲类似机制优先让 n 等于真实 token 数(如"猫吃鱼"→ 3 个人),或干脆不写具体人数。
- 问了（同一问题的另一面,从通讯录比喻追问）：通讯录找朋友那个例子里,那些人(张三/李四/...)的数量是怎么定的?→ **是同一个机制换了个比喻**;通讯录 = 圆桌 = 当前这一轮的 token 列表,人数 = n,**不是任何独立的数**。错误根不是通讯录比喻本身,而是 Coach 多个比喻都没把"人数 = n"写死 —— 学习者会以为每个比喻有自己的固定数。修法:比喻时让"人数" = 真实 token 数,或干脆不写具体人数。
- 问了：AI 猜出 5 个 token,为什么圆桌就是 5 个人?为什么"等于 5"?不一定啊。→ 答: n **不是**输出 token 数,**也不是输入 token 数**,是**当前 context 里所有 token 的总数** = 输入 + 已生成。模型**每蹦一个字**就把新 token 加进 context,n 就涨 1,圆桌多一把椅子。讲 "5 个人" 时把输入漏算了 —— 真实情况是输入 N + 已生成 M,N+M 才是当刻的 n。
- 问了（紧接上一条）：每蹦一个字算一次,那不就是循环吗?为什么之前说不是循环?→ 答: **外层就是循环,这是 Decoder 的自回归** —— 每生成一个新 token 就重开一次圆桌,因为新 token 加进来了。Self-Attention 内层**不循环**(一次 forward pass 内全员同时算 Q/K/V、同时打分、同时混合,这是 n² 算力那一次)。两层都对,别混:**内层并行、外层串行**。之前 Coach 说"不是循环"只说了内层,没说清外层,学习者抓得对。

- 问了(本对话新):从一个问题开始(比如「猫喜欢吃什么?」),问题是怎么拆成 token 的?n 又是怎么来的?softmax 把分数加成 = 1 的过程具体是什么?每蹦一个 token 之后又做了什么?→ 答在「例子」末尾的**完整一次 forward 走查**段:分词 n = 8 → embedding 查表 → L = 96 层 Block 串行堆叠,每层一次 SA → 最后一层 LM head + softmax 出下一个字概率 → 抽样出"鱼" → 拼回去 n = 9 → 重开圆桌 → 抽 [EOS] 停。**关键**:提问里"拆 token → softmax 加和 = 1 → 再蹦一个"这三件事正好对应**第 0 步 + 第 3 步(SA 的 softmax)+ 第 5 步(外层)**。
- 问了(本对话新,紧接上一条):softmax 把那行分数压成 0~1 加和 = 1,**数学上是怎么做到的**?→ 答在「例子」走查第 3 步那一行下方:**softmax = e^x 放大 + 除以总和归一**。给定一行 n 个浮点 s_1 ... s_n,先算 e^s_i 把所有数拉到正数,再除以 Σ e^s_i 让和 = 1。**本机制不推公式**(AGENTS §6.2 禁止),但 "e^x" 这三个字本身要记一下——它是 softmax 能写出 0~1 加和 = 1 的关键,不是某个人拍脑袋定的。追问里"按比例分"是直觉,但真做事的是 e^x 这一步。
- 问了(本对话新):你前面说跑了一次 Self-Attention,这次又说整次推理跑 L 次——到底跑了几次?→ 答: **真跑的就是 L 次(中层)+ 外层 N 次,加起来 L × N 次**。把"三层"显式拆开:内层 = 一次 SA 内部 n 把椅子并行(本轮 8 × 8 = 64 个分数);中层 = 一次 forward 内 L 个 Block 串行堆叠;外层 = Decoder 蹦字自回归,每蹦一字重开一次 forward。**之前 Coach 只说了内层 = 并行、没说清中层和外层也是串行的**,抓得对——这是本对话新踩到的坑。答案在「例子」末尾走查段最后的表格。

### 取舍

| 选 A 还是 B | 选 A 的代价 | 选 B 的代价 | 真实世界选谁 |
| ----------- | ---------- | ---------- | ------------ |
| Self-Attention vs RNN | n² 算力 / 显存 | 长距离遗忘 / 串行慢 | Transformer（用 GPU + 工程优化扛） |
| Self-Attention vs CNN | 贵、n² | 局部感受野、看不到远处 | 视觉也用 ViT（图像切成 patch 当 token） |
| Soft vs Hard 注意力 | 算力多点 | 不可微、训不动 | NLP 几乎全 Soft |
| 单头 vs 多头 | 学不全（一种关系） | 每头维度变小 | 多头是标配，8 / 16 / 32 头 |
| Self-Attention vs 长 context | 看得多但贵、显存吃紧 | 看得快但视野窄 | 按任务定 —— 检索场景多用 RAG + 短 context，不要硬塞百万 token |
| 中层 L 层 Block 串行 vs 外层 Decoder 自回归串行(本对话新) | 一个 forward 内 L 层 Block 串行堆叠;Decoder 自回归每蹦一字重开一次 forward | 省钱手段不一样:中层靠**学权重**;外层靠 **KV cache**(K/V 缓存复用、Q 重算) | 长文本生成场景是这两个串行的合集,所以两条优化路径都要看 |

### 踩坑

- 错：以为 Self-Attention 是「选一个最相关的词」 / 对：按比例混合，没有「唯一选谁」。
- 错：以为 Q / K / V 就是输入本身 / 对：它们是输入经三套**不同的可学习线性变换**得到的。
- 错：以为 Q·K 的结果是 0/1 / 对：是浮点数，softmax 后才归一化到 0~1 且加和=1。
- 错：以为 Self-Attention 只能算句子 / 对：算任何 token 序列 —— 文本、图像 patch、音频帧都行，本质是有顺序的向量序列。
- 错：把 attention weights 当「重要性」 / 对：权重是「这个位置对当前 token 的相关度」，是动态、相对的、跟当前 token 走的，不是固定的「重要度」。
- 错：以为「Attention 很强所以 Context Window 无限」 / 对：Attention 管怎么看，Window 管桌子多大；超窗照样失败或被截。
- 错：陷进 Q·K^T 的矩阵推导 / 对：本条不推公式；机制记清就够，B 档数学留给真要训练 / 调架构的人。
- 错（本对话新）：以为一次推理只跑一次 Self-Attention / 对：一次 forward = **L 层** SA + Decoder 自回归再跑 **N 轮**，总 = **L × N** 次圆桌，n = 当前序列 token 数（输入 + 已生成）。

### 过关自检

对照 README「本条要能讲清」：**能用一句话说清 Self-Attention 在做什么**。能说出口即可勾本条。讲解上还要能转述下面 4 项，每一项都对应一个例子：

1. **一句话说清**：Self-Attention 让序列里每个 token 同时看所有其它 token，按学到的「关注度」把大家的内容加权混合，得到融合全句上下文的表示。
2. **Self-Attention vs 一般 Attention**：Self 是「自己问自己序列里其它位置」；一般 Attention（Decoder 用 Encoder 输出那种）是「我问别人的输出」，叫 cross-attention。
3. **为什么不是顺序的**：所有位置同时算，每个 token 只依赖输入本身、不依赖别人的输出；RNN 才是排队一个等一个。
4. **Q / K / V 各是什么**：Q 是「我要找啥」、K 是「我提供啥标签」、V 是「我的实际内容」；三者由同一输入经三套不同的可学习线性变换得到。
5. **为什么算力是 n²**：每个 token 要和所有 n 个 token 算匹配度（Q·K），算完再混合所有 V。长度翻倍、算力变 4 倍 —— 这就是 Context Window 有上限、KV cache 是工程核心的根本原因。
