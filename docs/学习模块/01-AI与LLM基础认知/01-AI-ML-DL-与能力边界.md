# **AI / ML / DL 与能力边界**：三者是包含关系；神经网络是用数据拟合输入→输出；LLM 有明确做不好的事

### 是什么

**AI ⊃ ML ⊃ DL：套圈，不是时间线。**

```text
┌─────────────────────────────────────┐
│  AI（人工智能）                      │
│  让机器「像人」干活的所有办法          │
│  ┌───────────────────────────────┐  │
│  │  ML（机器学习）                  │  │
│  │  不手写规则，从数据里找规律        │  │
│  │  ┌─────────────────────────┐  │  │
│  │  │  DL（深度学习）            │  │  │
│  │  │  用很深的神经网络          │  │  │
│  │  │  ┌───────────────────┐  │  │  │
│  │  │  │  LLM               │  │  │  │
│  │  │  │  预测下一个 Token    │  │  │  │
│  │  │  └───────────────────┘  │  │  │
│  │  └─────────────────────────┘  │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
```

| 圈 | 一句话 | 前端类比（帮助记，不是定义） |
|----|--------|------------------------------|
| **AI** | 最大圈：规则系统、专家系统、机器学习都算 | 「整个前端工程」这把大伞 |
| **ML** | AI 里「从数据学规律、不靠人手写 if-else」的那一类 | 数据驱动，而不是手写每一条 DOM 规则 |
| **DL** | ML 里用多层神经网络的那一支 | 同一条技术路线里更自动抽特征的那一支 |
| **LLM** | 落在 DL：海量文本上训出来的「下一个 Token 预测器」 | 不是搜索引擎，也不是数据库 |

**神经网络 vs 查数据库**

- **查数据库**：结构化存储 + 精确查询。答对答错由数据本身决定，不需要「训练」。
- **神经网络**：被喂大量「输入 → 输出」样本，自己**统计归纳**出映射，**训完定型**。新问题按「看着像训练里见过的」去续。
- **走偏原因**：做的是拟合 / 归纳，训练数据没覆盖的角落会按「像不像」去编。
- **关键区别**：一个是精确查找，一个是拟合。LLM 能生成流畅文字，**不等于**它在查百科或按计算器在算。

直觉（不推公式）：看了十万条「用户提问 → 客服回复」之后，新来一个问题能猜大概该怎么回——模型做的是同一类拟合，只是规模换成数十亿参数和互联网文本。

**四个圈，用人话各举一件事（帮助记，不是学术定义）**

- **AI**：导航里「红灯停、限速 60」是人写死的规则，也算人工智能大伞下的一种；不是只有神经网络才配叫 AI。
- **ML**：短视频「你爱看什么就多推什么」——没人给每条视频手写 if-else，是从点击数据里找规律。
- **DL**：手机解锁认脸——层次很多的网络自己从像素里抽「这是不是这张脸」，你不用手写五官坐标规则。
- **LLM**：聊天框里下一个字往外蹦——在海量文本上学会「前面这些字后面常接什么」，不是打开了维基百科页面。

**查通讯录 vs 猜下一句（神经网络 vs 数据库）**

查通讯录：你输入「张三」，系统返回存进去的那个号码。没有这条记录就是没有，不会编一个「看起来像」的号。这是精确查找。

猜下一句：你听过一万段客服对话，新客人说「我的快递没到」，你接一句听起来很像客服的话。你可能接对，也可能编一个不存在的运单号——因为你在**接得像**，不是在 **SELECT 运单号**。LLM 做的是后一种。

### 为什么（Agent 开发要懂）

后面 Tool Calling / RAG / Context 管理，对应的是三类**不同成因**的「做不好」。分不清就会用错修法：该接计算器的去调 Prompt，该检索的去怪模型「笨」，该切片的去怪「幻觉」。

模块 00 已经能发出请求、打出流式回复。本条要建立的地基是：**你调的这个东西是什么、明确有些事它不会。** 后面 Token、Context、Transformer 都建在这上面。

**统一根因：三类局限都来自同一个定义——LLM 在预测下一个 Token。** 不是三个独立 bug，而是同一根因的三个切面：

| 局限 | 从「预测下一个 Token」看出去 |
|------|--------------------------|
| **能力边界** | 训练目标是「接得像训练数据」，不是「做计算 / 查实时事实」——猜词猜不出精确算术，也猜不出训练截止后的世界 |
| **幻觉** | 训练目标是「接得像人话」，不是「答得对」——「不知道」和「知道」时输出得一样自信（[我追问过的](#我追问过的) 那一问的根） |
| **Context 上限** | Transformer 的 Self-Attention 对序列长度是 O(n²)——不是商业限制，是架构 + 算力的硬约束（[Context Window](./03-Context-Window.md) 展开） |

抓住这条根因，后面模块 05 Tool Calling / 06 Context / 08 RAG / 11 State 才不是「各自独立的修法」，而是「针对同一根因的三个不同切面」。本模块的 [Token](./02-Token.md) 是这条根因在「计费 + 序列长度」上的直接落地。

**做错修法会长什么样（所以本条要先分清）**

客服用模型算赔偿金额，数字漂亮但算错了——这是**能力边界**，该接计算器 / 代码，不是把 Prompt 写成「你必须算对」。

客服问「我们内部退货政策第 3 条」，模型编了一段很像真的条款——这是**幻觉**（没查库却说得像查过），该检索或 Tool，不是骂它记性差。

把 80 万字工单历史一次性塞进这一轮——请求失败或中间全忘了，这是**Context 上限**，该摘要 / 切片 / 检索，不是换一句更礼貌的系统提示。

### 易混点

- 不是三个进化阶段（先有 AI，再进化成 ML，再进化成 DL）。是**包含关系**。AI 一直在，ML 和 DL 是其中两类方法。
- **答错 ≠ 幻觉。** 能力边界答错、Context 超了答错，都不是幻觉。
- **答对 ≠ 不幻觉。** 蒙对也是幻觉。
- 「数据库需要训练」：错。数据库是精确查询，不需要训练。
- 「LLM 什么都能做，只是偶尔记错」：错。有些任务是架构决定就不擅长，不是记性不好。

LLM 三件做不好的事 —— 不同成因，不同修法：

| 类型 | 成因 | 类比 | 修法（后面模块） |
|------|------|------|------------------|
| **能力边界** | 架构本身就不会：它在猜下一个词，不是在执行计算器 / 不是实时感知世界 | 蒙眼心算 6 位数乘法；不知道「现在几点、今天股价」 | 调外部工具（计算器、代码、搜索） |
| **幻觉** | 目标是「接得像人话」不是「查事实」；不知道和知道时一样自信 | 博览群书但没联网的人谈昨天 NBA | Tool Calling 查外部 + 引用源（模块 05） |
| **Context 上限** | 一次请求塞不下那么多 Token | 看不完 100 万字就问某处细节 | 摘要 / 切片 / 检索（RAG，模块 08） |

本条要能讲清：能举 **3 件能力边界**上的事，并说明它们不是幻觉、也不是窗口满了。方向（用自己的话举真实例子，不要背名单）：

1. **精确计算 / 多步大数算术** — 在预测下一个 Token，不是在做运算。
2. **训练截止日期之后的实时事实** — 权重里没有「此刻」的世界。
3. **100% 事实保证 / 私有未提供的数据** — 没有内置可查询的数据库；你没塞给它的公司内部文档它不会真的「知道」。

### 例子

向非技术人员讲：LLM 不是百科全书，也不是计算器。它更像「读过很多书、说话很顺、但没联网、也不会真的演算」的人。

**圈怎么套（一分钟版）**

冰箱贴画三个圈：最外圈写「凡是让机器帮忙像人干活」= AI（包括闹钟到点响）。中圈写「不手写穷尽规则、从例子里学」= ML（邮箱垃圾信越用越准）。内圈写「很深的网络自己抽特征」= DL（刷脸）。最里面再点一下「专门接下一个字」= LLM。不要画成 2010→2015→2020 三条箭头。

**能力边界三件实事（和幻觉、窗口分开演）**

1. **精确计算**：把 `123456 × 789012` 丢给模型，它可能吐出一个「看起来位数对」的数。它在猜下一个数字长什么样，**没有在做乘法**。这不是编造一篇不存在的论文（幻觉），题目也没长到塞爆窗口。修法：计算器或跑代码。把 Prompt 写凶解决不了。
2. **此刻的世界**：问「此刻上证指数」或「我快递现在到哪了」。权重里没有「这一秒」的世界，它可能根据训练里见过的话术编一句。这是能力边界（没实时感知），若它捏造一个具体点数还说得很稳，表现上会像幻觉——根子仍是「在接词，不是在查行情」。修法：接行情 / 快递查询工具。
3. **你没给过的内部资料**：问「把我们公司 Wiki 里发薪日那一页贴出来」，对话里从未上传 Wiki。它没有内置你们的数据库，却可能写一段很像 HR 口吻的文字。这不是窗口满了（你根本没塞那一页），是**没有这份数据还在拟合口吻**。修法：把文档检索进去（后面 RAG），或明确说不知道。

**同一错答，三种标签怎么贴**

用户：「合同第 17 条违约金是多少？」

- 合同全文根本没进这一轮请求，模型却写出「第 17 条违约金为 20 万」——更像幻觉 + 没提供的私有数据（能力边界），不是窗口问题。
- 合同有 200K Token，接口直接 400——是 Context 上限，模型连猜的机会都没有。
- 合同只有 2 页且已贴进对话，问的是「17 条里 3.5% 乘以合同额等于几」，它口算口错——能力边界（算术），条款内容它其实「看见了」。

### 我追问过的

- 问了：把前四篇笔记继续按「详细讲透 + 通俗例子」补充 → 答在本文件「是什么」四圈人话、「为什么」用错修法、「例子」三件实事与贴标签。
- 问了：幻觉的真正标志是什么（本条要求能区分三类，不是等到 Hallucination 小节才出现）→ 答在「易混点」：
  - LLM 在「不知道」和「知道」时输出得一样自信、一样顺。
  - 判断标准：不是看答案对不对，而是看模型当时是「知道」还是「猜」——而**它分不清**。
  - 因此幻觉几乎无法根治，只能靠 Tool Calling / RAG 等外部约束兜底。

### 取舍

区分「答错」要按成因拆，不能一锅煮；不同成因对应不同修法。本条不推公式、不看开课级 ML 视频。勾进度最低是能画圈、能举 3 件边界上的事；讲解上要能用生活例子把「套圈 / 拟合不是查库 / 三种做不好」讲给非技术朋友。公式和训练细节不是本条的修法。

### 踩坑

- 错：「答错 = 幻觉」。对：先问是能力边界、幻觉，还是 Context 超了。
- 错：「答对 = 不幻觉」。对：蒙对也是幻觉。
- 错：「AI / ML / DL 是三个进化阶段」。对：包含关系，不是时间线。
- 错：陷进反向传播 / 梯度下降推导才肯往下学。对：本条不推公式；数学是 B 档，不挡模块 01 往下走。

### 过关自检

- 能画出 AI ⊃ ML ⊃ DL（三个圈或嵌套方框），不是三条时间线；能各举一件生活里的事（规则导航 / 推荐 / 刷脸 / 接下一个字）。
- 神经网络是用数据拟合输入→输出，不是查数据库；能用「查通讯录 vs 猜客服下一句」说明。
- 能举出三件做不好的事，并分开：能力边界 / 幻觉 / Context 上限（成因和修法不同）；能用合同问违约金把三种标签贴对。
- 能用「LLM 在预测下一个 Token」一句话同时解释三类局限的根因（不是三个独立 bug，是同一根因的三个切面）。
