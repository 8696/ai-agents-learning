# **Embedding**：文本 → 向量；语义近的距离近；和 Token 不是同一层

> 对应模块：[模块 01 · AI & LLM 基础认知](./README.md) · 小节进度第 6 条

- **来源**：本对话（陪跑 Coach）；无外部 URL
- **状态**：已沉淀
- **Demo**：伪代码（见机制）（Token 离散 vs Embedding 连续向量；不调嵌入 API 也能讲清分层）
- **回填**：无（本模块代码落点是笔记即可）

### 是什么

**Embedding 做什么**：把一段文本（一个词 / 一段话 / 一张图）映射成一串实数（**向量**），让**语义相近的文本在向量空间里挨得近**。这是大模型能做语义检索 / 语义记忆 / 工具匹配的最底层机制——**没有 Embedding，就没有 RAG 和 Agent 记忆**。

**一句话**（模块表里的原文）：**文本 → 向量；语义近的距离近；和 Token 不是同一层**。

---

**先认两个层级（最容易混，必须先分开）**：

| 层级 | 是什么 | 类比 | 关键性质 |
|------|--------|------|---------|
| **Token** | 词表里的一个**整数 ID**（代号） | 图书馆**索书号**（TP391.4） | 只能"标号"，算不出远近 |
| **Embedding** | 那个 ID 对应的**实数向量**（一串实数，常 768 / 1536 / 3072 维） | 那本书在地图上的**经纬度** | 能算远近（用余弦相似度） |

两件事**不是同一层**，各管各的：

- Token 解决"哪两个字不一样"（"猫"= 5001 ≠ "狗"= 3729）—— 区分用
- Embedding 解决"哪个词跟哪个词意思近"（"猫"的向量靠近"宠物""喵"）—— 检索用

**关键事实**：**Embedding 不是人标的**，是**训练时学出来的**。

---

**训练机制（一句话版）**：

> 让模型做"**填空题**"（给一段文本盖住中间一个词，让模型猜）。模型想答对，就必须让**"上下文里经常一起出现的词"向量靠近**。几亿篇文章训练下来，"语义近的词 → 向量挨得近"自动涌现。

**举例走查**：

```text
原文："我今天吃了一个 ___ ，很甜"
       ↓
盖住"苹果"，让模型猜
       ↓
模型想答对 → 必须让"苹果"的向量跟"水果""红""皮"等上下文常见词靠近
       ↓
几亿篇文章训练下来：
  "猫"的向量 → 自动跟"宠物""喵""动物""吃鱼"挨在一起
  "石头"的向量 → 自动跟"矿物""硬的""砸"挨在一起
  "猫"和"石头"在向量空间里离得远 —— 它们本来就语义不近
```

整个过程**没有人工标"猫是宠物类"**——是训练目标（猜词）撞出来的副产物。

---

**怎么用 Embedding · 余弦相似度**

拿到两个 Embedding 后，判断"它们多像"用**余弦相似度**：

```
余弦相似度 = 1    → 完全一样
余弦相似度 = 0    → 无关
余弦相似度 = -1   → 相反
```

为什么是余弦、不是欧氏距离？见 [§易混点](#易混点)。一句话：**余弦只看方向（语义），不被长度干扰**。

---

**静态 vs 上下文相关（两种 Embedding 思想）**：

| 类型 | 代表 | 「苹果」怎么变成向量 | 用在哪 |
|------|------|----------------------|--------|
| **词级静态** | word2vec / GloVe | 词表里一个词一串数，「苹果」在哪句话里都一样 | 老派词向量；现在 RAG 很少直接用 |
| **整段一个向量** | OpenAI text-embedding-3 / BGE | 一段文本 → 一个坐标，便宜可缓存。 Ambiguity 靠把整句一起 embed，不是词表里的「苹果」变了 | 经典 RAG |
| **上下文相关（中间层）** | LLM hidden state | 同一个词在「吃苹果」和「苹果手机」里向量不同 | 复杂语义、贵、不好整库缓存 |

两者**都是 Embedding 思想**（语义近 = 距离近）。区别只在"是否随上下文变"。经典 RAG 用静态——**便宜、快、可缓存**。

---

**一个容易漏的刀：LLM 自己底层也是固定 lookup**

上面那张表把「静态 = word2vec」「上下文相关 = LLM hidden state」对得清清楚楚——**但漏了一刀**：LLM 自己的**输入层 embedding 也是固定 lookup**，跟 word2vec **机理一模一样**。

**流水线看清**：

```text
token "bank" (id=8234)
    ↓
[Embedding 查表层] → 固定向量 v₁ = [0.12, -0.34, ...]    ← 跟 word2vec 没区别
    ↓
[Self-Attention × N 层]   ← 每跑一层，向量都被「重塑」一次
    ↓
最终表示 v_N ≠ v₁    ← 这才是笔记说的「LLM hidden state」
```

**所以严格说**：「上下文相关 Embedding」= **attention 之后**的表示，**不是**输入层那个固定向量。

**重新对齐四种东西**：

| 东西 | 在哪一层 | 是否上下文相关 |
|------|---------|--------------|
| word2vec / GloVe | 训好的查表 | ❌ 纯固定 |
| **LLM 底层输入 embedding** | 模型第一层查表 | ❌ **也是固定**（容易漏） |
| **LLM 顶层 hidden state** | 经过 N 层 attention 之后 | ✅ 上下文相关 |
| OpenAI text-embedding-3 / BGE | 端到端 API（走完整个网络） | ✅ 段内上下文已混，粒度是「段」 |

**怎么用**：

- **RAG 检索** → 用 OpenAI / BGE 这类**段级 API**，便宜、可缓存、可入库
- **细粒度语义**（比如「我踢了狗」vs「狗踢了我」） → **Embedding API 拿不到这种区分**，得靠 LLM 自身 + Self-Attention，**不是 Embedding 的活**

**和上节 Self-Attention 串起来**：Self-Attention 就是干「重塑」这件事的——它把底层固定的 v₁ 按上下文动态调成 v_N。**没有 Self-Attention，LLM 的 Embedding 层就是个高级 word2vec**。

---

### 为什么（Agent 开发要懂）

不懂 Embedding，做 Agent 会在这些地方翻车：

- **RAG 是 Agent 必装**：模块 00 提到的"调云端模型"和模块 02 的 API 调用是 Agent 的输入端；RAG 是知识端。**没有 Embedding 就没 RAG，Agent 只能依赖模型预训练知识**（过时、缺垂直、幻觉）。
- **检索调参的根**：chunk 大小切错、embedding 模型选错、要不要 rerank——**全部围绕 Embedding 相似度**做决策。模块 08/09 全是这事。
- **Agent 语义记忆**：用户上个月说"我不吃辣"，今天问"推荐餐厅"——**没有 Embedding**记忆只能按时间 / 关键词召回（漏）；**有 Embedding** 按"语义相关"召回（精准）。
- **工具调用效率**：工具多了（50+），不让模型从 50 个里选——先 Embedding 召回 top 5，模型从 5 个里选。效率 + 准确度都大幅提升。模块 05 落到代码。
- **幻觉缓解**：用户问"上季度营收"，模型不知道——**RAG + Embedding 把真实文档喂进去**，幻觉消失。这是从"能力边界 / 幻觉"那一条（[01-AI-ML-DL](./01-AI-ML-DL-与能力边界.md) / [08-Hallucination](./08-Hallucination.md) 待写）的工程出路。

### 易混点

| 对比 | 差在哪 | 判错会怎样 |
| ---- | ------ | ---------- |
| **Embedding vs Token** | Token = 离散整数 ID（索书号），**只标号、算不出远近**；Embedding = 连续实数向量（经纬度），**能算远近**。**不同层**，各管各的事 | 把 Embedding 当成"更详细的 Token"，不理解为什么能做语义检索 |
| **Embedding vs 位置编码** | Embedding = **含义**（这词什么意思）；位置编码 = **顺序**（这词在句子第几位）。**完全独立** | 把 Embedding 当成"位置信息"——前面 Q2 实际考的就是这一刀 |
| **Embedding vs Self-Attention 输出** | Embedding = **输入阶段**（token 进来就转好的固定向量）；Self-Attention 输出 = **中间层**（每跑一层变一次） | 把"模型的隐藏状态"和"输入 Embedding"混为一谈 |
| **静态 Embedding vs 上下文相关 Embedding** | 静态思路：词表里一个词一个向量，「苹果」永远同一串数。RAG 常用的是**整段文本 → 一个向量**（OpenAI text-embedding-3 / BGE 这类）：一段一个坐标，便宜可缓存，但「吃苹果」和「苹果手机」若整段都塞进同一条，仍可能糊。上下文相关：同一词在不同句子里向量不同（模型中间层） | 用「一个词永远一个向量」去处理整段歧义，检索会串味 |
| **余弦相似度 vs 欧氏距离** | 余弦 = 看方向（语义）；欧氏 = 看距离（位置 + 长度）。**余弦不受长度干扰** | 检索时被"长度"干扰，结果失真 |
| **Embedding相似 vs 字面相似** | Embedding 比**语义**；字面匹配比**字符**。"送女友礼物" vs "女朋友生日惊喜" 字面 0% 重合，Embedding 相似度 > 0.9 | 把字面匹配当语义搜索，召回不全 |
| **Embedding vs 模型分类** | Embedding 是**通用表征**（任何相似度任务都能用）；分类是**特定标签**（只能判预定义的几类） | 想做开放域检索时硬套分类模型 |

### 例子

每个核心对象自己的例子（不共用总类比）。

---

**Token vs Embedding → 图书馆索书号 vs 经纬度坐标**

| 任务 | 用 Token（索书号） | 用 Embedding（经纬度） |
|------|-------------------|----------------------|
| "《红楼梦》在不在馆里？" | ✅ 查号 | ❌ 大材小用 |
| "跟《红楼梦》相似的书有哪些？" | ❌ 算不出（TP391.4 - I247.5 = 没意义的数） | ✅ 找坐标最近的 10 本 |

两件事用两个工具，**不是同一层**。

---

**训练涌现 → 中国地图自动聚类**

打开一张中国地图，每个城市一个点。**没人告诉**你"北京和上海是同类城市"——但因为它们都是"首都/经济中心"，地图上**自动聚在一起**。

乌鲁木齐和拉萨挨着（都是西部边陲），跟北京远。

Embedding 就是这个**自动聚类**的过程。训练数据里没有"分类标签"，但分布自己长出来。

---

**语义搜索 → 淘宝搜"送女朋友礼物"**

搜"送女朋友的礼物"和搜"女朋友生日惊喜"：

- 关键词**完全不一样**
- 但 Embedding 向量会挨得近
- 淘宝按向量相似度返回另一类关键词的结果

**不是字面匹配，是含义匹配**。这就是"语义搜索"的根。

---

**按图搜图本质 → 也是 Embedding**

图片用专门的 vision embedding 模型嵌入成向量。用户上传一张"小黑裙"，淘宝搜出**长得像的小黑裙**——机制和文字搜"小黑裙"找商品**一模一样**，都是 Embedding → 余弦相似度 → 排序。

---

**"苹果"在不同 context → 静态 vs 上下文相关**

- "我今天吃了一个**苹果**" → 苹果 ≈ 水果 ≈ 香蕉 ≈ 梨
- "他新买了一个**苹果**手机" → 苹果 ≈ 手机 ≈ iPhone ≈ 华为

**静态 Embedding**：两个"苹果"**共享同一个向量** → 检索会混淆。
**上下文相关 Embedding**：两个"苹果"**向量不同** → 检索精确。

---

**RAG 完整走查 · 1000 份工单**

```text
离线阶段（提前做一次）：
  1000 份工单 → Embedding API → 1000 个向量 → 存进向量数据库

在线阶段（每次用户提问）：
  用户问："我的订阅被多扣款了怎么办？"
       ↓
  调同一个 Embedding 模型 → 1 个 query 向量 q
       ↓
  算 q 与 1000 个向量的余弦相似度 → 按相似度降序排
       ↓
  取 top 3：
    #1 工单 #237：用户反馈订阅续费时被【重复扣款】，已退款 (sim=0.92)
    #2 工单 #519：客户账单出现【双倍扣费】，客服已处理   (sim=0.88)
    #3 工单 #142：自动续费失败导致【多扣】，已退订      (sim=0.85)
       ↓
  把 top 3 工单原文 + 用户问题拼进 LLM prompt → LLM 生成回答
```

**关键洞察**：top 3 里**没有一个用了"多扣款"这三个字**——用的是「重复扣款」「双倍扣费」「多扣」。**字面完全不一样，但 Embedding 让它们挨得近**。字面匹配召回率为 0，Embedding 召回率 100%。

---

**律师查判例 · 语义检索的杀手价值**

| 用户问 | 字面匹配能召回 | Embedding 检索能召回 |
|--------|---------------|---------------------|
| "软件开源协议违约怎么判" | ✅ 直接命中 | ✅ 召回 |
| "违反 GPL 协议判例" | ❌ "开源" ≠ "GPL" | ✅ 召回（语义近） |
| "copyleft 协议纠纷" | ❌ 中英混杂 | ✅ 召回 |
| "代码许可侵权" | ❌ 字面零重合 | ✅ 召回（语义近） |

用户用什么词表达不重要，**意思对就行**。这就是 Embedding 检索相对字面检索的**杀手价值**。

---

**和上一节 Self-Attention 串起来（承上启下）**

[Self-Attention](./05-Attention-Self-Attention.md) 给的机制：n² 算力是圆桌的代价。本节给基础：**圆桌上坐的"人"是哪来的？**——是 Embedding 把 Token ID 转成向量，才能坐进圆桌开 Self-Attention。

两条连起来：Embedding = 输入阶段的"语义坐标化"，Self-Attention = 中间阶段的"关系混合化"。**两者不是同一层**。

---

**和前面所有概念串起来（总图）**

```text
Token（编号）     →  区分用："这是哪个词"
     ↓
Embedding（坐标） →  检索用："这词什么意思、跟哪个近"
     ↓
Self-Attention    →  关系用："这词跟上下文里其它词什么关系"
     ↓
Context Window    →  容量用："一次能看多少"
```

**逐层往上，每层解决前一层的不足**。少任何一层，模型就玩不转。

### 我追问过的

- 问了（Q1 第一题）：Embedding 是什么？「语义近 = 距离近」这性质怎么来的？→ 答在「是什么」：「Embedding 是什么」答对（是一个向量），但**测距工具和 Embedding 本身混淆**——说"Embedding 是通过余弦或欧氏距离算出来的"，实际余弦/欧氏是**测 Embedding 间距离的工具**，不是**生成 Embedding 的方式**。修正一句话：Embedding = 一串实数向量；想比较两个 Embedding 像不像，**用余弦相似度**（看方向、不看长度）；**用欧氏距离会被长度干扰**。性质来源**机制没讲清**——「机器自监督跟监督学习出来的」对了"自监督"那半，**没展开训练目标**：让模型填空，让"上下文相似的词向量靠近"，几亿篇文章训练下来自动涌现。追问里"机器自己学出来的"是直觉，但**真做事的是填空任务 + 上下文相似 → 向量靠近**这条机制。

- 问了（Q2 第二题）：Token 和 Embedding 各自在做什么？为什么不是同一层？→ 答在「是什么」+「易混点」：Token 部分对（"把文本输入成一个 ID 的过程"接近），但**Embedding 部分关键错**——说"Embedding 是用多维度数字表示 Token 在哪个位置"。这把 Embedding 和**位置编码（Positional Encoding）**搞混了。位置编码是给每个位置加"我是第几位"的标签，跟 Token 在哪一句的第几位有关，**跟 Token 的语义无关**。**正解**：Embedding 表示**含义坐标**（跟"宠物""喵"挨近），位置编码表示**顺序标签**（"我是第 3 位"）。**两件事完全独立**——这是前面 Self-Attention 那节就提到的，本节跟 Embedding 区分清楚。**6 字口诀**：「Embedding 看含义，Pos 看顺序」。

- 问了（Q3 第三题）：1000 份工单 RAG 场景怎么做？→ 让 Coach 答（答在「例子」RAG 完整走查段）：离线嵌入 + 在线 query 嵌入 + 余弦相似度排序 + top K 召回 + 拼进 LLM prompt。**关键洞察**：top 3 召回里没有一个用了"多扣款"字面，Embedding 让语义近的挨在一起。**这就是 RAG 的骨架**，模块 08 会把这套机制从"会做"讲到"做精"。

- 问了（沉淀后的补刀）：能不能先沉淀文档，再来答题？→ 答：按 §7.0 / §7.2 沉淀成 9 节模板（**本对话详解 + 出门包 + Q&A 全部归位**），学习者再答 Q1 + Q2。这一刀是为了**避免边学边写时漏掉对话里的关键转折**（比如 Q2 的 Embedding ≠ 位置编码，是追问才暴露的真实混淆点）。

- 钉死记录（第 4 答）：用 5 个新角度钉 Embedding ≠ 位置编码——(1) Token Embedding 表的"行键"是 ID 不是位置、(2) Positional Encoding 表的"行键"是位置不是 token、(3) 两张表相加才送模型、(4) 同一 token 在不同位置 Embedding 完全一样、(5) 两表信息完全不重叠。学习者前 3 答都把"Embedding 代表位置"再讲一遍，**第 4 答**终于用自己的话讲出「我踢了狗」vs「狗踢了我」这个金标准例子——**同词、同 Embedding，但语义完全相反**——这是真懂的标志（不是死记口诀）。本条从"还没搞懂的"**移出**。

### 取舍

| 选 A 还是 B | 选 A 的代价 | 选 B 的代价 | 真实世界选谁 |
| ----------- | ---------- |---------- | ------------ |
| 静态 vs 上下文相关 Embedding | 便宜、快、可缓存 | 不区分歧义 | RAG 用静态；复杂语义用上下文相关 |
| 余弦 vs 欧氏距离 | 不受长度干扰 | 对绝对位置不敏感 | 几乎全用余弦 |
| Embed 整段 vs Embed 逐句 | 整段更连贯 | 长段超出模型上限 | 长文本用 chunk → 逐句 Embed → 求平均 / 加权 |
| 自家训 Embedding vs 调 API | 私有、可控、可微调 | 贵、要数据、要算力 | 80% 调 API（OpenAI / BGE）；垂直领域才自家训 |
| Embedding 检索 vs 字面检索 | 召回全、能跨语 / 跨词 | 贵、要 Embedding API | 默认 Embedding 检索；只在"必须精确匹配 ID / 代码"用字面 |

### 踩坑

- 错：以为 Embedding = 更详细的 Token / 对：Token = 离散 ID（索书号）；Embedding = 连续向量（经纬度）。**不同层**，各管各的事。
- 错：以为 Embedding 是人标的 / 对：是训练时让"上下文相似 → 向量靠近"自动学的（填空任务撞出来的副产物）。
- 错：用欧氏距离做语义检索 / 对：用余弦相似度（欧氏受长度干扰）。
- 错：用静态 Embedding 处理歧义词 / 对：歧义场景用上下文相关 Embedding，或专门 chunking 处理。
- 错：以为"Embedding 相似 = 字面相似" / 对：Embedding 比**语义**。"送女友礼物" ≈ "女朋友惊喜"（字面 0%，语义 > 0.9）。
- 错（本对话新）：以为 Embedding 表示 Token 在哪个位置 / 对：那是**位置编码**干的活。Embedding 表示**含义坐标**。口诀："Embedding 看含义，Pos 看顺序"。钉死：「我踢了狗」和「狗踢了我」——同样的词、同样的 Embedding，语义完全相反；没有位置编码，句子级语义丢掉。
- 错（本对话新）：以为 Embedding 是"通过余弦 / 欧氏距离算出来的" / 对：Embedding 是**结果**（那串数字），余弦 / 欧氏是**测量工具**。一个是饼，一个是尺。

### 过关自检

对照 README「本条要能讲清」：**能区分 Token（离散计数）和 Embedding（连续向量）**。能说出口即可勾本条。讲解上还要能转述下面 5 项，每一项都对应一个例子：

1. **一句话说清**：Embedding 把文本映射成连续向量，**语义相近的文本在向量空间里挨得近**，靠训练时让"上下文相似的词向量靠近"学出来。
2. **Token vs Embedding**：Token = 词表里的**整数 ID**（"猫" → 5001），是"这是第几号词"；Embedding = 那个 ID 对应的**实数向量**（5001 → `[0.12, -0.34, 0.78, ...]`），是"这个词的语义坐标"。**前者是离散计数，后者是连续坐标**——不同层。
3. **Embedding ≠ 位置编码**：Embedding 表示**含义**（这词什么意思）；位置编码表示**顺序**（这词在句子第几位）。**完全独立的两件事**。6 字口诀："Embedding 看含义，Pos 看顺序"。
4. **训练机制**：Embedding 是**自监督**学出来的（没有人工标签），训练时让模型**填空**，结果就是"上下文相似的词向量靠近"。**几亿篇文章训练下来，"语义近 = 距离近"自动涌现**。
5. **Agent 三个用途**：(a) RAG 检索——把文档和 query 都嵌入，**找最像的 chunk**；(b) 语义记忆——历史对话嵌入向量库，下次按语义召回；(c) 工具相似度匹配——把工具描述嵌入，挑最相关的几个让模型选。
