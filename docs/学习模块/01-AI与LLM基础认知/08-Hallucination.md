# **Hallucination**：模型在预测下一个 Token，不是在查数据库

> 对应模块：[模块 01 · AI & LLM 基础认知 ⭐⭐⭐⭐⭐](./README.md) · 小节进度第 8 条

- **来源**：本对话（`coach start` §6.2 详解，2026-08-31）
- **状态**：已沉淀

### 是什么

Hallucination（幻觉）指**模型生成的内容在事实上不正确，但不是用户能轻易分辨**的那种不正确。它的本质是：

> 模型在「预测下一个 token」，不是在「查数据库」。

**模型没有事实核查这一步**——它只关心"接得通不通"，不关心"是不是真的"。结果就是：

- 它编的内容**形式上对**（标题、作者、年份、语气、术语都对）
- 它编的内容**事实上错**（你搜不到那篇论文、没那个人、那个公司没那个产品）
- 它编的时候**特别自信**——它没有"我不知道"按钮，编出来就跟你打包票。

**幻觉的 5 种典型形态**：

1. **编造引用**：编一篇看起来真实存在的论文（标题、作者、年份都对，但你搜不到）
2. **编造人物**：给一个看起来真实的"传记段落"，但这人根本不存在 / 这事没发生过
3. **虚构数据**：编一组"实验结果"或"统计数据"，数字是模型造的
4. **混淆相似概念**：把 A 概念的属性贴到 B 概念上（听起来对，但张冠李戴）
5. **时间穿越**：说"截至 2024 年 X 公司已经做了 Y"，但 X 公司根本没宣布这件事 / Y 还没发生

**关键点**：模型"不知道自己在编"——它没有事实数据库可以核对，所以它说出来的内容在它内部是"接得通"的，但在外部世界是错的。

---

### 为什么（Agent 开发要懂）

做 Agent 最怕的不是"模型答错"——而是**"模型答错还特别自信"**。三个根因：

1. **模型没有"我不知道"按钮**——它没有"我说不出来"的回路，只能硬编一个。
2. **模型没有"我去查一下"的回路**——它没有外接数据库 / 工具的能力，除非你给它。
3. **模型的训练目标是"下一个 token 像不像真的"，不是"事实是否正确"**——训练阶段就没人告诉它"别编"。

**做 Agent 时具体会在哪些场景翻车**：

| 场景 | 幻觉翻车的样子 | 后果 |
| ---- | -------------- | ---- |
| **客服 Agent** | 用户问"你们公司有 X 功能吗"，模型编"是的我们有"——其实公司根本没这功能 | 用户被误导、客服部门背锅 |
| **法律 / 医疗 Agent** | 模型编"这个药剂量是 Z mg"——其实是错的 | 严重后果（吃错药 / 误导诉讼） |
| **RAG / 检索增强** | 检索没命中时，模型仍然"接龙"补完一段答案，看上去很完整 | 用户以为模型查过了，其实没查到 |
| **代码生成 Agent** | 模型编一个不存在的 API 或函数名 | 代码编辑器里立刻报错——**这是最"友好"的一类幻觉**，因为立刻挂；其他幻觉可能要等用户被坑了才发现 |
| **报告 / 摘要 Agent** | 模型给一份"市场分析"，但里面所有数据都是编的 | 决策基于假数据 |

**一句话总结**：幻觉是 LLM 的**默认行为**——它不是 bug、不是偶尔犯的错、不是 prompt 没调好。**它是模型的本质**。

### 易混点

| 对比 | 差在哪 | 判错代价 |
| ---- | ------ | -------- |
| **幻觉 vs 故意撒谎** | 模型没有"故意"——它没有意图、没有动机、没有事实核查机制 | 把幻觉当"它故意的"会让人去调"道德约束" prompt（"请诚实回答""不要骗我"），**完全没用**——它没有道德开关给你按 |
| **幻觉 vs 能力差** | 幻觉发生在"模型本来能做对"的场景里——它只是没去查；能力差发生在"模型物理上做不好"的场景（精确计算大数、长程推理） | 把幻觉当"模型不行"会让你去换更大模型——**大模型也会幻觉**，换了没解决 |
| **幻觉 vs Temperature 随机性** | Temperature 高让输出"更花"（措辞飘），但**不是事实错**；幻觉是事实错，**与 Temperature 无关** | 调温度治幻觉——**完全没用**，浪费 prompt 调试时间 |
| **幻觉 vs 能力边界** | 能力边界是架构就不会：猜词猜不出精确大数算术、也猜不出没提供的私有库。幻觉是「接得像人话」，知道和不知道时一样自信；**蒙对也是幻觉** | 把答错一锅煮成幻觉，会用错修法：该接计算器的去改 Prompt |
| **幻觉 vs Prompt 不清楚** | Prompt 模糊时模型乱猜也是「事实错」，但成因是题没出清 | 改 prompt 有上限；该上检索 / 工具 / 结构化时不要无限改字 |

### 例子

#### 例子 1：自动补全的极端情况（IDE 类比）

你写邮件，IDE 自动补全帮你写下一句。补全出来的句子**通顺、语法对、语气对**——但你邮件里要引用同事名字，IDE 补全出的版本里名字错了。这就是"自动补全的极端情况"。

LLM 模型就是「自动补全的极端情况」——它的整个训练目标是"下一个 token 像不像真话"，**不是"它是不是真话"**。

#### 例子 2：接龙的极端情况（生活类比）

一群人接龙编故事，每个人接一句：

- 第 1 个："从前有只狐狸"
- 第 2 个："它有三条尾巴"
- 第 3 个："它会飞"
- 第 4 个："它的邻居是奥巴马"

**没有人去查"奥巴马是不是狐狸的邻居"**——大家只关心"接得通不通"。

LLM 也是这样——它只关心"接得通不通"，不关心"是不是真的"。

#### 例子 3：演员演戏（生活类比）

想象一个演员接到剧本："扮演一个物理学家，解释量子纠缠"。演员**没有真学过物理**，但剧本说"要讲得自信、讲得像真的"。

演员能做到——讲得自信、术语堆得对、语气像专家——但**内容可能是错的**。

LLM 就是这种"超级演员"——它能讲得像真的，但不一定是真的。

#### 例子 4：前端组件库文档的具体幻觉（前端类比）

你用 React，问模型"React 中 `useEffect` 怎么用？"模型答得很详细。但你追问"那 `useEffect` 的 cleanup function 什么时候执行？"

模型可能编一段：**"在每次渲染前执行"**——其实**官方文档**说"在下一次 effect 跑之前执行"。

LLM 编的"在每次渲染前执行"听起来很合理，但其实是错的。这就是幻觉——**表面顺、内在错**。前端开发里这种"看起来对、其实错"的幻觉最坑人，因为它能编译能跑，但行为不对。

#### 例子 5：胡编论文引用的具体表现（学术类比）

让模型写"关于 Transformer 的论文摘要"：

- **真论文**：Vaswani et al. 2017, "Attention Is All You Need"
- **模型编的**：Smith et al. 2019, "Attention Reimagined for Vision"

**两个症状**：

1. **看起来像真论文**（标题、作者、年份、期刊位都有）
2. **你搜不到**（作者名可能是真有其人但论文不存在，或者作者名是编的）

这就是幻觉的典型形态——**形式对、内容错**。

### 取舍

不是所有幻觉都必须治。要分场景：

| 场景 | 幻觉能不能接受 | 治法 |
| ---- | -------------- | ---- |
| **闲聊 / 创意写作** | 能接受 | 不治；用户知道模型在玩 |
| **客服 / 业务查询** | **不能接受** | RAG（检索 + 生成）让模型先查再答；或结构化输出强制给出来源 |
| **代码生成** | 部分接受 | 幻觉立刻让代码挂——最"友好"的一类；但要 unit test 兜底 |
| **法律 / 医疗 / 金融** | **绝对不能接受** | 必须用工具调用 + 检索 + 人工复核；单靠 prompt 没用 |
| **教育 / 学习** | 取决于年龄 | 小孩需要事实准，用 RAG + 限制 prompt；成人可接受"启发式" |
| **内容创作 / 营销** | 能接受 | 创意本身就要"想象"；不用治 |
| **数据查询 / 报告** | **不能接受** | 必须用工具调用 + 结构化输出强制字段；不让模型"自由发挥" |

**一句话取舍**：

> 幻觉不是 bug——是模型的**本质**。治幻觉靠**外挂**（检索 / 工具 / 结构化），不是靠 prompt 里写"请不要编造"。

### 踩坑

| 错 | 对 | 症状 |
| ---- | ---- | ---- |
| Prompt 写"请不要编造、不要胡说不存在的内容" | 模型没有事实数据库，写"不要编"没用 | 模型仍幻觉，只是换了一种编法 |
| 把温度调低当治幻觉 | 幻觉与 Temperature 无关 | 调来调去还是幻觉，浪费 prompt 调试时间 |
| 把幻觉当"模型故意的"加道德 prompt | 模型没有意图 | "请诚实回答""不要骗我"——没用，模型不知道自己在错 |
| 把幻觉当"模型能力差"去换更大模型 | 大模型也会幻觉 | 换模型没解决，本质问题没动 |
| 把幻觉当"prompt 不清"无限改 prompt | 改 prompt 有上限 | 改到怀疑人生，应该上 RAG / 工具 / 结构化 |
| RAG 后没检查检索结果 | 检索没命中模型仍会接龙补完 | "RAG 之后还是有幻觉"——因为检索是源头不是兜底 |
| 不在 Agent 层面设"我不知道"按钮 | 不告诉模型"不知道就说不知道" | 模型答错还自信，下游照单全收 |
| 不在结构化输出里强制给来源 | 让模型自由发挥 | 幻觉无法溯源；下游用错也无法追责 |

### 过关自检

- 我能用一句话说清 **幻觉的成因**：模型在「预测下一个 token」，不在「查数据库」——它没有事实核查这一步，所以会编，编的时候语气还特别自信。
- 我能区分 **幻觉 vs 故意撒谎**（没有意图）、**幻觉 vs 能力边界**（换更大模型不能根治幻觉；蒙对也是幻觉）、**幻觉 vs 调温度**（温度治不了幻觉）。
- 我能说出 **3 种常见治幻觉的办法**：RAG（检索 + 生成）/ 工具调用（让模型能查）/ 结构化输出（强制给出来源 + 让"不知道"成为合法答案）。
