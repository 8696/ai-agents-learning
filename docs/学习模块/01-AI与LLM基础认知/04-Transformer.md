# **Transformer**：Encoder / Decoder；Self-Attention 用来「看整句关系」

- **来源**：本对话 · 外部 AI（学习者贴回的笔记）· 学习者澄清：不要收短，要写到能真正理解
- **状态**：已沉淀

### 是什么

先分清两个词，后面才不会绕。

- **Transformer**：一种神经网络的**搭法**（架构）。规定「文字怎么进来、中间怎么互看、结果怎么出去」。
- **LLM**（Large Language Model）：用（通常就是）这套搭法、再加海量文本**训练出来的具体模型**。GPT、Claude、Llama 是 LLM；它们内部大多是 Transformer。

类比：Transformer 是引擎图纸；某一款 LLM 是已经造好、加满油的那辆车。你会开 GPT，不等于图纸你已经看懂；但做 Agent 至少要知道引擎分哪三大块，否则后面的 Token、窗口、流式输出会对不上号。

---

**它要解决的问题（为什么需要这三块）**

人读句子可以来回瞄：看到 `它` 会回头找 `小猫`。早期一种做法（RNN）更像从左扫到右，走一步更新一次「记忆」，离得远的词容易糊。Transformer 换了思路：句子先切成 Token（上一节），**每个 Token 都可以直接看整句里其它 Token**，用权重表示「此刻谁更重要」。这个「互看」就是 Self-Attention。Encoder / Decoder 是把这套互看装在「读」还是「写」两条流水线上。

本条不推公式。记住数据怎么走即可。

---

**第一块：Encoder（读）**

输入是一整段 Token。Encoder 的工作不是往外写故事，而是：**把这段话变成一份内部表示**——模型后面用来「当作已经读懂了」。

生活里像：考官把文章读完，脑子里留下印象，还没开始写作文。前端里像：把一份 JSON 解析成内存里的对象，此时还没有渲染出页面。

所以 Encoder 擅长「理解」类任务：这段话什么意思、两段是否相近、属于哪一类。后面模块会碰到的 Embedding（文本变向量去检索），思想上更靠近 Encoder 这条「读完给表示」的路，细节留给那一条。

---

**第二块：Decoder（写）**

Decoder 的工作是**生成**：已经有一些 Token（提示 + 已经写出的字），预测**下一个** Token，写出来，再拿新序列预测再下一个。一次只拍板一个，所以你会看到一个字一个字往外蹦（产品上常用 SSE 流式推）。这叫自回归：刚写出的东西，立刻变成后面预测的输入。

生活里像接龙：桌上已有「今天天气」，你接「真」，再变成「今天天气真」，再接「好」。前端里像：不是一次算完整页 HTML 再返回，而是 chunk 往外推，每片都依赖已经推出去的内容。

---

**原论文为什么左右都有；你聊天为什么常常只有右边**

2017 年那篇 Transformer 面向翻译：**左边 Encoder 读懂原文，右边 Decoder 按理解逐词写出译文**。这叫 Encoder–Decoder（左右双塔）。

你现在用的 Chat API，多数模型是 **Decoder-only**：没有单独「只读不写」的左塔。用户 Prompt、系统说明、已经生成的回复，都当成**同一条正在写的序列的前缀**，Decoder 接着往后续。不是「少了半个引擎就残了」，而是生成对话这条产品线，用「把提示也当成已写内容」就够了。

另外还有 **Encoder-only**（如 BERT）：主要产出「读懂后的表示」，不负责像 ChatGPT 那样长篇接龙。三种不要画成一张「标准必填图」：

- 只要读懂 / 分类 / 后面说的向量检索 → 思想靠近 Encoder。
- 只要聊天、写代码、Agent 往外决策 → 你调用的就是 Decoder-only。
- 左边一篇进、右边一篇出（翻译、有些摘要）→ 才是教科书那张双塔。

Decoder 在写下一个词时，会把「还没写出来的右边」挡住，避免作弊偷看答案。这叫 Masked Self-Attention（看左不看右）。知道有这层限制即可；权重矩阵怎么乘是下一节。

---

**第三块：Self-Attention（看关系）**

Encoder 里、Decoder 里，真正让「读/写」变聪明的，是 Self-Attention：**处理某一个 Token 时，给句子里每个其它 Token（含自己）打分，分高的多看、分低的少看，再融合成这个位置的新含义。**

「Self」是因为看的和被看的都在**同一句话**里。翻译双塔里，右边写中文时还会去看左边已经读懂的英文，那是「看另一边」，本条知道有这回事即可，不必展开。

不是「从左扫到右、只记得上一个词」。也不是 Context Window。窗口管这次请求**塞得下多长**；Attention 管已经塞进来的那些 Token **彼此怎么建立联系**。

---

**三块怎么叠在一起（一张总图）**

```text
[Token 序列：Prompt / 原文 / 已生成的字]

        │
        ▼
 ┌──────────────┐     每个位置：看整句其它位置，更新自己的含义
 │ Self-Attention│
 └──────────────┘
        │
        ▼
   若在 Encoder：输出「整段读懂了」的表示，通常不再往外接龙
   若在 Decoder：用当前表示预测下一个 Token → 拼回去 → 再跑一轮
```

内部往往还有一层「各自位置再处理一下」（常叫 Feed Forward），以及多组 Attention 并行（Multi-Head，像会议室里同时有人盯语法、有人盯指代、有人盯谁先谁后）。本条把它们当成「Attention 后面的配件」，主路径仍是读 / 写 / 互看，不必背层名。

**和前三条怎么接上（一条请求里）**

你在 Chat 里打「把合同赔偿条款摘出来」。句子先被切成 Token（[02](./02-Token.md)），整串 ID 必须塞进这一次的窗口（[03](./03-Context-Window.md)）。窗口里的每一个位置，用 Self-Attention 看其它位置（本条）。Decoder-only 模型把你的这句话当成接龙前缀，一次吐一个 Token。它仍然是第 1 条说的「下一个 Token 预测器」：条款摘得顺，不等于它查了法务数据库（能力边界 / 幻觉另说）。

### 为什么（Agent 开发要懂）

你调 API 时看不到 Encoder 图纸，但行为都从这里来：

1. **长指令为什么可能被跟上**：系统提示、用户话、检索片段只要还在窗口里，Self-Attention 原则上能让后面的 Token 看到前面的约束。窗口超了是上一节的截断问题；没超但模型仍忽略某句，是「看见了但权重没给你想要的那路」——下一节和 Prompt 模块再拆。
2. **为什么是流式而不是整篇一次返回**：Decoder 一次只定下一个 Token。前端用 SSE 接，是在跟这个生成方式对齐，不是纯 UI 炫技。
3. **为什么搜索和聊天往往不是同一个模型**：聊天要 Decoder 接龙；「这段文档和 query 像不像」要的是读懂后的向量，更靠近 Encoder 思路。选错会出现「拿聊天模型当检索器」或反过来。
4. **不要指望结构消灭胡说**：Attention 让模型更会「把句子圆上」，圆上不等于事实对。幻觉是「在预测 Token，不是在查库」，后面专条。

### 易混点

**Transformer vs LLM**  
图纸 vs 量产车。判错：以为 Transformer 是某一家的产品名，或以为会调 Chat Completions 就等于懂架构。

**三种 Encoder/Decoder 画法**  
BERT ≠ GPT ≠ 论文双塔。判错：复习时只记一张「左边 Encoder 右边 Decoder」却去解释 ChatGPT，对不上你实际在调的东西。

**Self-Attention vs 从左到右读**  
人的阅读顺序和模型内部「每个位置同时看全句（Decoder 则看已写下的左边）」不是同一件事。判错：以为 Transformer 仍是一步一步传隐藏状态、远距离一定忘。

**Self-Attention vs Context Window**  
怎么看 vs 能装多长。判错：「Attention 很强所以窗口可以无限」——算力和产品仍给窗口封顶；超了仍截断或摘要。

**看清关系 vs 不会幻觉 / 能力边界**  
语法指代可以对，事实仍可以编。也不是「数学题一定算对」那种能力边界。本条只划界，不展开后两条。

**Encoder 输出的「向量」vs 下一节 Embedding 产品**  
笔记里说「语义向量」指层内表示。OpenAI Embeddings 那种「专用接口、一段文本一个向量去搜」是后一条的产品层，不要在本条混成同一个作业。

### 例子

下面每块都能讲给没做过模型的人听。定义在「是什么」，这里只演戏。

**1. Transformer vs LLM：图纸和量产车**

小区修车厂墙上贴着「直列四缸」的结构图，那是 Transformer。门口开出去的那辆蓝色轿车，有车名、有油耗，那是某款 LLM。你会开车，不等于你会指认气缸；但修 Agent 时至少要能指「读 / 写 / 互看」三块在哪。

**2. Encoder：读完菜单，还没点菜**

你进餐厅把菜单从上到下看完，脑子里已经有「有宫保鸡丁、偏辣、大约 38 元」，但还没对服务员开口。Encoder 就是这一步：整份文本读完，留下印象，**不负责把下一句话说出来**。前端对应：`JSON.parse` 已经成功，页面还没 `render`。

再比如：HR 把一百份简历读完，给每份打了「像不做前端」的印象分，还没写录用通知。那是 Encoder 思路。后面用向量搜文档，也是「先读成印象再比较」，细节留给 Embedding 那条。

**3. Decoder：接龙 / 微信边打边出字**

饭桌上成语接龙：上一个人说「今天天气」，你只能接**一个**词「真」，全桌变成「今天天气真」，下一个人再接「好」。Decoder 就是这个：每次只决定下一个 Token，写出来立刻变成下一次的已知内容。

对应你盯着的 Chat 窗口：字一个一个往外蹦，像对方在微信里正在输入。不是服务器先写完整篇作文再贴上来（就算接口等写完再返回，厨房里仍然是一字一字接的）。前端像 SSE：一个 chunk 依赖已经发出去的那些。

**4. Decoder-only：把你的话当成接龙已经写好的前半句**

你对 GPT 说：「用三句话解释 Token」。模型不当你是「另一边的考卷」，而当你已经写在纸上的前半句，它从空格后面接着写「Token 是……」。所以聊天模型常常没有单独的「只读左塔」，不是缺零件，是接龙规则把提示也算进已写内容。

**5. Encoder–Decoder 双塔：同声传译**

左边座位上的人把英文讲稿听完（Encoder），右边座位上的人看着「听懂了的印象」用中文一个词一个词说出来（Decoder）。这是 2017 年论文那张图，适合翻译。你平时聊 GPT，更像只有右边那位，把你的中文提示也当成他已经说了一半的稿。

**6. Encoder-only（BERT 这类）：只打分，不写小说**

电影网站只给你「这部片偏喜剧、和《某某》很像」的标签，不替你续写第二季剧本。和 GPT「接着往下编」不是同一张结构图。

**7. Self-Attention：会议室里对上号，不是只听邻座**

句子：「小明把手机放在桌子上，因为它没电了。」

若每个人只能问左右邻座：坐在「它」旁边的是「因为」和「没」，对不上号。Self-Attention 是：轮到「它」发言时，可以看全桌每个人，给「手机」举牌很高（没电的是电器），给「桌子」举牌很低。所以「它」的意思被更新成「那部手机」。

英文同一出戏：*The animal didn't cross the street because it was too tired.* 「太累」更像动物，不像马路，所以 `it` 看向 `animal`。

再补一个开会的说法：项目经理说「把**它**改了再发」。只听前后两个字会懵；你扫一眼白板，发现刚圈过的是「登录按钮」不是「整份 PRD」，这就是「看整句关系」。

**8. Masked：考试不能翻后面的答案**

写作文时不允许先偷看自己还没写到的结尾。Decoder 预测「下一个字」时把右边挡住，叫 Masked（看左不看右）。知道「不能作弊」就行，怎么算分下一节。

**9. Attention vs 窗口：怎么看 vs 桌子多大**

全桌人可以互相看（Attention），但会议室只准进 8 个人（Context Window）。互看能力再强，第 9 个人进不来，还是要请出去或做摘要。不要说「大家都能对上号，所以房间无限大」。

**10. 能对上号 ≠ 不编故事**

接龙接得很顺（「它」正确指代手机），仍可能把手机品牌、价格说错。圆上句子不是查了数据库。胡说留给 Hallucination。

**11. 一条请求从头走到尾（把 01～04 串成生活剧）**

场景：你问「上周那双鞋的运单到哪了」。

1. 模型仍是「猜下一个字的人」（01），没有快递公司的实时库。
2. 你的字变成一件件编号包裹（02）；中文可能比同等英文更碎。
3. 系统提示 + 历史 + 这一句 + 它准备回的话，挤同一台电梯（03）。历史太长，门卫可能直接不让进。
4. 电梯里的人可以互相看，好对上「那双鞋」三个字指哪次购物（04 Self-Attention）。它一个字一个字回你（Decoder），像微信正在输入。
5. 回得像真的运单号，仍可能是编的——要修的是接查询工具，不是画一张更复杂的结构图。

**12. 前端一条链路**

`JSON.parse`（Encoder 读懂）→ 还没 `render`。`render` 时按已有 VDOM 一块块往外刷（Decoder 接龙）。列表里每一项可以读 store 里别人的状态（Self-Attention 看全句）。`sessionStorage` 只有这一页（窗口）；用户资料在 DB 里（Memory，后面模块）。

### 取舍

- 学结构：优先能讲清三块和「聊天模型 = Decoder-only」，而不是复原论文每一层名字。
- 选型：要续写、对话、Agent → Decoder-only LLM；要「读懂并比相似度」→ Encoder 思路 / Embedding 模型（产品细节后一条）。
- 翻译或「左进右出」任务才需要认真对待 Encoder–Decoder 双塔；做 Chat Agent 不必假装每天都在跑 2017 年那张完整图。

### 踩坑

- 错：用收短提纲代替理解（只剩三行箭头）。 / 对：能用自己的话把「读 / 写 / 互看」走一遍，并能举 it 的例子。
- 错：本条推矩阵、softmax。 / 对：知道有打分、有融合就够。
- 错：ChatGPT 必须画上左边 Encoder。 / 对：你调的生成接口多半是 Decoder-only。
- 错：能看整句 = 窗口无限 = 不会编造。 / 对：三件不同的事。

### 过关自检

- 能不看笔记画出三块：Encoder 读懂、Decoder 按已有内容写下个 Token、Self-Attention 让每个词按权重看整句关系；能用菜单/接龙/会议室举牌转述。
- 能解释：论文可以左右都有；日常聊天 LLM 多为 Decoder-only（Prompt 当接龙前缀）；BERT 类不要和 GPT 画成一张图。
- 能用 it/animal（或中文「它」）说明「只看邻居不够」；能分开 Attention（怎么看）和 Context Window（能装多长）；能说看清关系仍可能胡说。
- 能把一次「查运单」从预测器 → Token → 窗口 → 互看 → 接龙串起来（例子 11）。
- 不要求公式；不要求会写 Multi-Head 实现。
