# **预训练 vs 推理**：训练你不做；你调 API 做的是推理

> 对应模块：[模块 01 · AI & LLM 基础认知 ⭐⭐⭐⭐⭐](./README.md) · 小节进度第 9 条

- **来源**：本对话（`coach start` §6.2 详解，2026-08-31）
- **状态**：已沉淀
- **Demo**：无（两阶段各自发生什么是概念边界，跑推理 API 分不清训练）

### 是什么

大模型生命周期里有**四个阶段**，不是一个：

```
预训练 (Pretraining)
   ↓ 数万亿 token + 数千 GPU × 数周
   ↓ 成本数百万-数千万美元
   ↓ 输出：base model（只会"接龙"，不会聊天）
   ↓
SFT / RLHF（对齐 / Alignment）
   ↓ 几万-几十万条人工数据 + 几百 GPU × 几天
   ↓ 成本几万美元
   ↓ 输出：chat model（会聊天、会听指令）
   ↓
Fine-tuning（微调，可选）
   ↓ 几千-几万条你自己的数据 + 单 GPU × 几小时
   ↓ 成本几十-几百美元
   ↓ 输出：定制 model（你的风格 / 私有知识）
   ↓
推理 (Inference)
   ↓ 你的一条 prompt
   ↓ 成本几分钱/千 token
   ↓ 输出：模型回复（每个 API 调用都是一次推理）
```

**这四件事的边界**：

| 阶段 | 谁在做 | 改不改模型权重 | 数据规模 | 算力 | 成本 |
| ---- | ------ | -------------- | -------- | ---- | ---- |
| **预训练** | 模型公司 | 改 | 万亿 token | 数千 GPU × 数周 | 数百万-数千万美元/次 |
| **SFT / RLHF** | 模型公司 | 改 | 几万-几十万条 | 数百 GPU × 数天 | 几万美元/次 |
| **Fine-tuning** | **你**（少数情况）| 改 | 几千-几万条 | 单 GPU × 几小时 | 几十-几百美元/次 |
| **推理** | **你**（每次调 API）| **不改** | 一条 prompt | 单次调用 | 几分钱/千 token |

**关键点**：**推理时模型权重不变**——你调 API 时，模型内部那一大堆参数（数十亿到数千亿个数字）是**冻结的**；你只是给它一条 prompt，让它逐 token 输出。**改权重才叫"训练"**；不改权重只"喂数据拿输出"叫"推理"。

---

### 为什么（Agent 开发要懂）

不懂这四个阶段，做 Agent 会在四个地方翻车：

1. **把"模型能聊天"当成预训练的结果——错误**
   - base model 只会"接龙"（你给它"从前有只狐狸"，它会接"它有三条尾巴"）。**会聊天、会听指令**是 SFT / RLHF 的功劳。
   - 很多人误以为 OpenAI 训出 GPT-4 那一刻，模型就会聊天了。其实训出来的是 base model，**不会聊天的**，要经过对齐才变成 chat model。

2. **以为"调 API 就是训练"——错误**
   - 调 API 时模型权重不变。你调 1000 次 API，模型内部还是那一套参数——它没"学到"你的 prompt、你的风格、你的私有知识。
   - 想让模型"学会"你的风格 → 你得 **fine-tune**（自己再训一遍），而不是"调更多 API"。

3. **把 fine-tuning 当成万能药——浪费钱**
   - 90% 的场景 **prompt 工程**就够——你不需要改模型权重就能让模型输出你想要的东西。
   - fine-tune 一次几十到几百美元，还要准备几千条数据、维护模型仓库、处理版本……**prompt 工程搞不定时**才上 fine-tune。

4. **不知道训练 / 推理是"两个独立的产品线"——商业误判**
   - 模型公司靠**推理**收费（OpenAI / Anthropic 按 token 收费）。
   - 模型公司预训练 / 对齐**自己掏钱**，不收你钱——你买不到"帮我训一遍"的服务（除非走 Azure OpenAI / AWS Bedrock 的 fine-tune 接口）。
   - 你以为"花钱就能让模型学我的数据"——其实 fine-tune 只是推理产品线的一个**附加功能**，不是训练产品线的入口。

### 易混点

| 对比 | 差在哪 | 判错代价 |
| ---- | ------ | -------- |
| **预训练 vs SFT / RLHF** | 预训练用互联网海量数据训 base model；SFT / RLHF 用几万-几十万条人工数据对齐 chat model | 把"模型能聊天"归功于预训练——其实是对齐的功劳；以为"模型变大就自动会聊天"——不一定 |
| **SFT vs RLHF** | SFT 用"理想回复"训练（监督学习）；RLHF 用"哪个回复更好"训练（强化学习） | 把对齐当成"一种"——其实分两步、机制不同；细节属模块 17 |
| **Fine-tuning vs Prompt Engineering** | Fine-tuning 改模型权重（要数据、要算力、要钱）；Prompt Engineering 改输入（不要数据、不要算力、不要钱） | 动不动就 fine-tune——浪费钱 + 时间；其实 90% 场景 prompt 够用 |
| **推理 vs 训练** | 推理不改模型权重、调 API 即可；训练改模型权重、要么自己做要么用厂商服务 | 以为调 API 能让模型"学到"——它学不到；以为 fine-tune 调一次就 forever——其实每次都得再训 |
| **Base model vs Chat model** | Base model 只接龙、不听指令；Chat model 会聊天、会听指令 | 用 base model 做客服——它答非所问；用 chat model 做接龙——它强行"按指令"反而不自然 |
| **微调 vs 蒸馏（Distillation）** | 微调用"理想数据"训练；蒸馏用"大模型的输出"作为小模型的训练数据 | 混淆两者会以为"小模型也能学会所有能力"——其实有上限；蒸馏属模块 22 |

### 例子

#### 例子 1：厨师学做菜 vs 给客人做菜（生活类比）

**预训练 = 厨师学做菜**：

- 一个厨师从学徒到大师傅，要学 10000 道菜、练 10000 小时。
- 时间 = **数年**；成本 = **多年的学费 + 食材 + 时间**。
- 输出 = 一个"什么菜都会做"的大师傅——但他**不会自己开菜单**，只会"你说要什么菜我做什么菜"。

**推理 = 给客人做菜**：

- 客人点"宫保鸡丁"，大师傅 30 分钟做好——这就是一次**推理**。
- 时间 = **30 分钟**；成本 = **一份菜的食材**。
- 客人点 100 次菜，大师傅的厨艺**不会因此变好**——他还是那个大师傅（模型权重不变）。

**SFT / RLHF = 大师傅学"怎么跟客人聊天"**：

- 大师傅做菜好吃，但客人说"你能推荐一道菜吗？"他答"我不知道你要什么"——不会聊天。
- SFT = 给大师傅一本《100 个常见问题与回答》让他背——他学会了"客人问 X 我答 Y"。
- RLHF = 客人给大师傅的回复打分（"这个回答很好 5 分"），大师傅根据分数调整——他学会了"什么回答客人更喜欢"。

**前端转 Agent 对应**：

- 预训练 = OpenAI 训 GPT-4 的 base model——你**永远不做**
- SFT / RLHF = OpenAI 把 GPT-4 base 变成 GPT-4 chat——你**永远不做**
- 推理 = 你调 OpenAI API 让 GPT-4 回答你的 prompt——你**每天做**

#### 例子 2：学生学课本 vs 考试答题（教育类比）

**预训练 = 学生 12 年学课本**：

- 从小学到高中，语数外物化生政史地——**海量知识**。
- 时间 = **12 年**；成本 = **多年学费 + 时间**。
- 输出 = 一个"什么都知道一点"的高中生——但他**不会写论文**，只会"填空 + 选择 + 简答"。

**推理 = 高考答题**：

- 考卷 90 分钟，答完交卷——这就是一次**推理**。
- 时间 = **90 分钟**；成本 = **几张考卷 + 监考**。
- 学生考 100 次高考，分数**不会因此提高**——他还是那个学生。

**SFT / RLHF = 学"怎么写作文 / 怎么解应用题"**：

- 高中生会填空，但不会写作文——SFT 给他看 100 篇范文，他学会了"开头怎么写、结尾怎么收"。
- 老师给学生作文打分——RLHF 他学会了"什么作文老师更喜欢"。

**前端转 Agent 对应**：

- 预训练 = 高中 12 年——你**不重新读一遍**
- SFT / RLHF = 高三冲刺班——你**不报**
- 推理 = 你用学过的知识去解决一个具体问题——你**每天做**

#### 例子 3：演员训练 vs 演员拍戏（生活类比）

**预训练 = 演员训练**：

- 演员训练班 3-5 年，学台词、学形体、学表演——**海量基本功**。
- 时间 = **数年**；成本 = **多年学费**。
- 输出 = 一个"什么角色都能演"的新人——但他**不会自己挑剧本**。

**推理 = 演员拍戏**：

- 一部戏 3 个月拍完——这就是一次**推理**。
- 时间 = **3 个月**；成本 = **片酬 + 剧组**。
- 演员拍 100 部戏，演技**不会因此提升**——他还是那个演员。

**SFT / RLHF = 学"怎么接这部戏的剧本"**：

- 演员会演，但导演说"这场戏你要哭"——他不会哭。SFT 给他看 100 部哭戏，他学会了"什么时候该哭"。
- 导演给演员的表演打分——RLHF 他学会了"什么表演导演更喜欢"。

#### 例子 4：模型公司视角 vs 用户视角（业务类比）

**模型公司视角**：

- 预训练花 1000 万美元训出 base model——**不卖给你**
- SFT / RLHF 花 50 万美元把 base 变成 chat——**不卖给你**
- 推理按 token 收费（几分钱/千 token）——**这是他们赚钱的产品**

**用户视角**：

- 你买不到"帮我训一遍"的服务
- 你买不到"帮我 SFT 一遍"的服务（除非走厂商的 fine-tune API）
- 你**只能用推理 API**——调一次收一次的钱

**关键洞察**：你以为 OpenAI / Anthropic 是"训模型 + 卖模型"的公司——其实他们是**"训模型 + 卖推理"**的公司。预训练 / 对齐是**成本中心**，推理是**收入中心**。

#### 例子 5：Fine-tuning 的具体例子（前端类比）

场景：你想让模型**用你们公司的代码风格写 React 组件**（而不是通用风格）。

**Prompt Engineering 路线**：

- 在 prompt 里塞 5-10 个示例："这是我们的 Button 组件，这样写：……"
- 效果：模型**能模仿**，但**不是 100% 一致**；每次都要塞示例，浪费 token。

**Fine-tuning 路线**：

- 准备 **几千条** "你们的代码风格 → 输出" 的训练数据
- 调 fine-tune API（OpenAI / Anthropic 都提供）训几个小时
- 效果：模型**学会了**你们的风格——**prompt 里不用塞示例**，输出天然像你们写的
- 成本：**几十-几百美元/次**

**取舍**：90% 场景 prompt 够用；只有"prompt 怎么写都不像"才 fine-tune。

### 取舍

作为前端转 Agent 的学习者，**你的工作边界**：

| 阶段 | 你做不做 | 原因 |
| ---- | -------- | ---- |
| **预训练** | ❌ 永远不做 | 算力 / 数据 / 成本都不是个人 / 小公司能负担的；只有大厂做 |
| **SFT / RLHF** | ❌ 永远不做 | 同上；模型公司自己做对齐 |
| **Fine-tuning** | ⚠️ 偶尔做 | 只有 prompt 工程搞不定时才上；数据 / 算力 / 成本都在个人可承受范围 |
| **推理** | ✅ 每天做 | 调 API、选模型、调 prompt、控成本、设计 Agent 流程——这是 Agent 开发的核心工作 |

**学习优先级**：

- 80% 时间学 **推理**（prompt 工程、模型选型、成本控制、Agent 流程）——这是你吃饭的家伙
- 15% 时间学 **fine-tuning**（知道什么时候该用、成本多少、坑在哪）——这是备用技能
- 5% 时间理解 **预训练 / SFT / RLHF** 是什么——不用会做，但要懂原理（不然被坑时不知道为什么）

### 踩坑

| 错 | 对 | 症状 |
| ---- | ---- | ---- |
| 以为"模型能聊天是预训练的结果" | 是 SFT / RLHF 的功劳 | 期待"模型变大就自动会聊天"——不一定；要对齐才聊得来 |
| 以为"调 API 能让模型学到我的数据" | 调 API 是推理，模型权重不变；想让它学 → fine-tune | 调 1000 次 API，模型还是不会你的风格——以为"它没学够"，其实它根本没在学 |
| 动不动就 fine-tune | 90% 场景 prompt 工程够用 | 浪费钱（每次几十-几百美元）+ 浪费时间（准备数据）+ 维护负担（版本管理） |
| 用 base model 做客服 | base model 只接龙，不听指令 | 客服答非所问，用户抱怨 |
| 用 chat model 做生成 | chat model 被对齐过，会强行按指令 | 让它"自由发挥写诗"——它非要"按你的要求写"，反而不自然 |
| 以为 fine-tune 一次 forever | 每次 fine-tune 都是一次独立训练 | 模型更新（厂商升级 base）后你的 fine-tune 失效——要重训 |
| 不知道"训练 / 推理"是两步 | 是两个完全不同的阶段 | 误以为"花钱就能让模型学我的数据"——其实 fine-tune 只是推理产品线的附加功能 |
