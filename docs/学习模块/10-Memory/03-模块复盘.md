## 一句话讲完这个模块

让 Agent 拥有跨会话的长期记忆——不只在本会话用上下文窗口工作，还在外部存储里记住用户的偏好、事实、历史经历，下次会话一上来就能接上。关键不是「记住多少」，是「记什么 / 怎么写 / 怎么管寿命 / 怎么保安全」四件事。模块 10 用两小节回答：01 记忆分类（先切清楚「记忆」这件事），02 写入策略（再回答怎么写得对——八关流水线）。

 │  + 短 / 长期分层          │  输入   │  每一类走不同的写入规则            │
 └─────────────────────────┘         └──────────────────────────────────┘

                                       ▼
                              ┌──────────────────────┐

- **01 是「是什么」**：切清概念（哪四类、怎么分、怎么放）
- **02 是「怎么做」**：把值得记的写对（八关流水线）
- **关系 = 概念 → 实现**：分类是写入策略的输入（语义 / 情景 / 程序性走不同的关）。没有 01 的分类，02 的把关第三关「是不是事实」判不准；没有 02 的写入策略，01 的语义记忆会全堆成原始对话、三个月后召回精度雪崩。
- **03 = 收口**：把前两条串成一条「Agent 拥有跨会话记忆」的完整路径——也写明这模块没答的问题去哪解决（存储选型 / 评测 / 调度）。

## 最容易记错的三条（跨小节）

1. **工作记忆 ≠ 长期记忆**。前者是本轮对话上下文（messages 数组），离开本会话就丢；后者是外部存储（SQLite），跨会话持久。「上下文累积」和「记忆积累」是两件不同的事——别混。
2. **提取 ≠ 整段存**。一段对话原文（几千字）要抽出几条结构化短句（每条几十字），否则召回精度雪崩。「把整段对话塞进库」是模块 README 点名的最常见坑——后果 1 列得很重。
3. **写入策略八关是流水线，不是单个函数**。每一关可以独立换实现 / 独立看日志 / 独立测试。把八关写成一个函数 = 不可观测 + 不可分别调优（后果 8）。

## 踩过的坑（跨小节）

跨 01 + 02 的踩坑：

1. **把所有历史消息当记忆存**——模块 README 点名的最常见坑。后果：召回精度雪崩。
2. **让模型自由给候选事实起键**——同一件事第一次叫 `framework`、第二次 `tech_stack`、第三次 `frontend_framework`，覆盖代码写得再对也白搭（02-写入策略 踩坑第 2 条）。
3. **把「过期」实现成「删除」**——丢历史（02-写入策略 踩坑第 5 条）。修法：归档保留，原始记录还能查回。
4. **以为「审计表 = 软删」**——软删是审计的子集；审计记全部动作（02-写入策略 踩坑第 7 条）。
5. **以为「审计表 = 加完就完」**——审计表靠 4 道判定叠起来保护（02-写入策略 踩坑第 8 条）：应用层禁止 / 存储层隔离 / 不可变导出 / 哈希链。
