### 一句话讲完这个模块

把一个能跑通的 Agent 从 Demo 推到 Production：让外部依赖（LLM、向量库、Tool）失败时不拖垮 Agent，让稳定输入不重复算钱，让简单任务不浪费贵模型，让长任务不占死连接，让关键操作不重复执行——五件事一起做，就是一个能上线的 Agent。

### 这些条怎么连成一条线

本模块三条外部小节的关系不是平行的，而是**一层底盘 + 双引擎省钱**：

```
                    ┌─────────────────────────────────┐
                    │     Model Routing（输出侧省钱）  │
                    │  按难度分模型；按总成本算账       │
                    └────────────────┬────────────────┘
                                     │
            ┌────────────────────────┼────────────────────────┐
            │                        │                        │
   ┌────────▼────────┐      ┌────────▼────────┐      ┌────────▼────────┐
   │ Prompt Caching  │      │  Circuit Breaker│      │  其他可靠性机制   │
   │ （输入侧省钱）  │      │  （错误兜底）   │      │  （不在本模块三条 │
   │ 前缀一字不差    │      │  连续失败断开   │      │   限流 / 队列 /   │
   │ 才命中          │      │  保护调用方     │      │   幂等 / 重试 /   │
   └─────────────────┘      └─────────────────┘      │   超时 / 成本看板）│
                                                     └──────────────────┘
```

- **熔断是底盘**：没有它，Agent 一遇到 LLM 5xx 就重试放大、Token 白烧、用户等死。Caching 和 Routing 都建立在「调用方还活着」之上。
- **Prompt Caching 是输入侧省钱**：稳定前缀（System + Tools + 长文档开头）不重复算；和 Routing 是**两个独立维度**——一个省「一次调用内的输入」，一个省「选哪个模型」。
- **Model Routing 是输出侧省钱**：让简单任务走便宜模型；和 Caching **叠加使用**（前缀缓存 + 小模型 = 最便宜）。

未在本模块三条里展开但属于「Production Agent」必需：限流（保护下游配额）、指数退避重试、超时清理、异步队列、幂等性、成本看板——这些是其他模块或真实项目里的事。

### 最容易记错的三条

1. **路由 ≠ 降级**——路由按任务难度选模型（省钱主动）；降级按主模型挂了换备用（保命被动）。把降级当路由做 = 主挂了用户难题被发到小模型 = 用户体验崩塌。
2. **Prompt Caching 缓存的是前缀，不是任意中间段**——同一段长内容放 System 开头 vs User 末尾命中率差几个数量级。位置决定一切，**不是**「内容决定一切」。
3. **成本按任务总成本算，不是按单次单价**——小模型 0.1 元 / 百万 tokens × 重试 5 次 = 0.5 元；大模型 15 元一次答对。重试 5 次的小模型**比**一次大模型贵 30 倍。

### 踩过的坑（跨小节）

写到这里，本对话未踩到具体代码坑（无 Demo 落地）。记录一条**预防性踩坑**：

- **「主模型挂了换备用」被归到路由里**：很多初学者看到「按模型切」就把降级（fallback）当路由的一种。**判错代价**：主模型挂了，用户难题被路由逻辑发到小模型 → 用户体验崩塌。模块 03 「易混点 3.1」专门拉出一组对比 + 边界图提醒；做真实项目时每次写「主模型不可用时换 X」分支，先确认这是降级而不是路由。
