### 是什么

**Model Routing（模型路由）** 是一种**按任务难度 / 成本预算，把请求分给不同模型**的策略——同一个 Agent 不是「一律用最强模型」，而是**先判定任务，再选最合适的模型**：简单问答走小模型（便宜、快），复杂推理走大模型（贵、准）。整个过程由一个**路由器（Router）** 决定。

核心三件事：

1. **路由器**：拿到请求后判定任务该走哪个模型——可以用规则（关键词 / 长度 / 用户等级）、分类器（小模型自己分）、或另一个 LLM（让 LLM 决策）。
2. **模型分档**：至少两档——便宜档（典型 0.1~0.3 元/百万 tokens）和贵档（典型 15~75 元/百万 tokens），价格差 50~500 倍。
3. **按任务总成本**：不是单次单价，而是**这个任务从头到尾所有调用的总和**（含重试、含路由器自己的成本、含失败补救）。

一句话：**路由不是「让 AI 更聪明」，是「让 AI 更省**——把每一块钱花在真正需要强模型的地方。

### 为什么（Agent 开发要懂）

Agent 在生产里几乎一定有**任务分布**：

- 70% 的请求是简单问答、格式转换、查文档摘要 → 小模型能搞定。
- 20% 是中等推理、写代码片段 → 中模型。
- 10% 是复杂多步推理、规划、需要回滚的决策 → 大模型。

具体后果（举三个最常见的）：

1. **Agent 一律用最强模型** → 月账单 90% 花在「不需要那么强」的任务上 → 单纯靠 Prompt 优化省不下来。
2. **不知道路由和降级的区别** → 主模型挂了，路由逻辑把请求发到更便宜的备用模型 → 用户体验反而**比之前差**（用户问题是难题，备用小模型答不了）。
3. **按单次单价算成本** → 觉得小模型便宜就一直用 → 简单题用小模型要重试 5 次才能答对（一次答错一次重试），总成本反而**超过一次大模型**。

Agent 路由做不做 = 月账单量级差**一个数量级**。

### 易混点

Model Routing 最容易被三个「长得像」的概念混淆——尤其是**降级**，这是本节第一关键区分。

#### 路由（Routing）vs 降级（Fallback / Failover）——核心区分

| | 路由 | 降级 |
|---|---|---|
| **目标** | 给合适任务挑合适模型（省钱 + 保质量） | 主模型不可用时换能用的模型（保可用） |
| **判定依据** | **任务难度** / 用户等级 / 成本预算 | **主模型挂了** / 超时 / 5xx |
| **方向** | 高难度 → 大模型；低难度 → 小模型 | 不论任务难度，**主挂了就降** |
| **例子** | 简单问答 → Haiku；复杂推理 → Opus | Opus 5xx → 改 Haiku；Opus 超时 → 改 Sonnet |

**判错会怎样**：把「主模型挂了换备用」当路由的一种——错。**那是降级**。两件事的目标完全不同：路由是省钱的主动决策；降级是**保命的被动切换**。把降级当路由做，主模型挂了用户难题被发到小模型 → 用户体验崩塌。

#### 路由（Routing）vs 级联（Cascade）

| | 路由 | 级联 |
|---|---|---|
| **决定时机** | **开始前**就定好走哪个模型 | 走完一个再决定要不要升档 |
| **模型数** | 一次只跑一个 | 可能跑两次（先小不行再大） |
| **总成本** | 一次成本 = 选定的模型成本 | 一次成本 = 小模型 + （可能）大模型 |
| **适合** | 难度判定有把握的场景 | 难度判定不确定的场景 |

**判错会怎样**：把所有路由逻辑都做成级联 → 「先小不行再大」成本反而比**直接大**贵（两次调用 > 一次贵模型调用）。**两种策略按场景分**：难度容易判 → 路由；难度难判 → 级联。

#### 路由 vs 模型集成（Ensemble）

| | 路由 | 集成 |
|---|---|---|
| **跑几个模型** | **1 个**（选定的那个） | **N 个**（并行投票 / 取最优） |
| **输出** | 选定模型的输出 | N 个模型的综合结果 |
| **成本** | 1x 选定模型 | N x 模型成本 |
| **目的** | 省钱 | 提质量（多视角投票） |

**判错会怎样**：把集成当路由来用 → 每次都跑 5 个模型，成本 5x，**目的是保质量而不是省钱**。

#### 路由 vs 上下文压缩（Prompt Compression）

| | 路由 | 上下文压缩 |
|---|---|---|
| **做什么** | **换模型**（不同档位） | **改输入**（变短） |
| **省什么** | 模型的「单价」 | **Token 数** |
| **能不能同时用** | 能——压缩完的短输入照样可路由 |

**判错会怎样**：以为压缩就够，不做路由 → 同一段长输入用最贵模型算一遍，省不下大模型自己的成本。**压缩 + 路由是两层独立的优化**。

#### 路由 vs A/B 测试

| | 路由 | A/B 测试 |
|---|---|---|
| **目的** | **省钱 + 保质量**（生产决策） | **比较**（找更好的方案） |
| **输出** | 每个请求**一个**模型 | 部分请求 A，部分请求 B |
| **流量** | 按规则全量分配 | 按比例切流量 |

**判错会怎样**：把 A/B 当路由上线 → 用户体验随机（10% 用户用差模型），没省钱也没保质量。A/B 是**验证工具**，验证完才决定是不是要做路由。

### 核心概念（变体 / 分支全扫）

Model Routing 有 10 个变体。

#### 1. 路由判定输入

路由器的输入信号：

| 输入 | 怎么用 | 例子 |
|------|--------|------|
| **任务分类** | 关键词 / 意图识别 | 「翻译」→ 中模型；「代码」→ 大模型 |
| **输入长度** | 长 → 大；短 → 小 | < 500 token → 小；> 5000 token → 大 |
| **用户等级** | 付费用户 → 大；免费 → 小 | 免费 → 小；VIP → 大 |
| **历史轮次** | 多轮对话复杂 → 大；首轮简单 → 小 | 第 1 轮 → 小；第 5 轮 → 大 |
| **上一轮失败次数** | 重试过 2 次还失败 → 升级 | 失败 → 升档 |

**例子**：餐厅分诊台（看患者症状）→ 决定挂哪个科。

**需求 1（路由判定输入）**：实现 5 种路由输入信号，每种单独可开关；同一请求触发不同路由。

#### 2. 路由策略

三种主流策略：

| 策略 | 怎么判定 | 成本 | 准确度 |
|------|----------|------|--------|
| **规则路由** | 关键词 / 长度 / 用户等级正则 | 0（无 LLM 调用） | 中（关键词漏掉就判错） |
| **分类器路由** | 用一个小模型先分类 | 1 次小模型调用 | 较高 |
| **LLM 路由器** | 让 LLM 自己决定走哪个 | 1 次 LLM 调用（可和主调用合并） | 高（但路由器本身有成本） |

**例子**：快递分拣中心——条码颜色分（规则）、称重分（分类器）、人工分拣（LLM 路由）。

**需求 2（三种策略对比）**：同一组请求用三种策略路由，对比命中率 + 总成本 + 路由器自身成本。

#### 3. 模型分档

至少分两档，常见三档：

| 档位 | 典型用途 | 价格量级（每百万 tokens） |
|------|----------|---------------------------|
| **小模型** | 分类 / 摘要 / 简单问答 | 0.1~1 元 |
| **中模型** | 一般推理 / 代码片段 | 3~15 元 |
| **大模型** | 复杂推理 / 规划 / 多步 | 15~75 元 |

**例子**：医院分诊——普通门诊（小模型）、专科门诊（中模型）、专家门诊（大模型）。

**需求 3（模型分档定义）**：定义小/中/大三档，给每档指定适用任务类型；跑 100 次真实请求看分布。

#### 4. 降级（Fallback）与路由的明确边界

**关键区分**——本节最核心：

```
任务难度低 ──► 路由 ──► 小模型（省钱 + 够用）
任务难度高 ──► 路由 ──► 大模型（贵 + 必须）
                             ↓
                    主模型挂了（5xx / 超时）
                             ↓
                       降级 ──► 备用模型（任何档位都行）
```

**判错代价**：把降级当路由的一种 = 主挂了把用户难题发到小模型 = 用户体验崩塌。

**例子**：餐厅厨师 A 病了（挂了）→ 餐厅启动降级：让厨师 B 接手所有菜（不论难易）；不是「简单菜给 B、复杂菜等 A 回来」（那是路由 + 队列，不是降级）。

**需求 4（路由 vs 降级验证）**：同一主模型挂掉场景：
- 路由模式：难题照样等主模型恢复，不降级
- 降级模式：不论难易，立即换备用
两个模式在同一故障下的用户体验对比。

#### 5. 级联（Cascade）

级联 = 「先小模型，置信度低再大模型」。和路由的区别：**级联先跑再看**，路由**先看再跑**。

| 模式 | 决策时机 | 调用次数 | 适合 |
|------|----------|----------|------|
| **路由** | 跑之前 | 1 | 难度可判定 |
| **级联** | 小模型跑完看置信度 | 1 或 2 | 难度难判定 |

**例子**：自动驾驶先 LCC（低级辅助）跑，看不行升级到 NOA（高级辅助）——这是级联；直接判断「高速走 NOA、市区走 LCC」——这是路由。

**需求 5（级联模式）**：实现「先小模型 → 置信度低时升级到大模型」；对比「直接大模型」的总成本。

#### 6. 按任务总成本，不是单次单价

**单次单价误导**：小模型 0.1 元/百万 tokens，大模型 15 元/百万 tokens。看上去小模型便宜 150 倍。

**任务总成本**：实际一次任务的成本 =

```
任务总成本 =
  路由器成本（路由策略决定的额外调用）
+ 主调用成本（选定模型的输入 + 输出）
+ 重试成本（路由错了 / 模型答错的补救）
+ 降级成本（主模型挂了换备用的兜底）
```

**真实案例**：用小模型回答难题，重试 5 次才答对 → 0.1 × 5 = 0.5 元；用大模型一次答对 → 15 元。**小模型更贵**。

**例子**：超市促销「买一送一」——单看单价便宜，但一次买 5 次才买到要的东西，比一次买对贵 5 倍。

**需求 6（任务总成本计算）**：写一个任务成本计算函数，输入路由策略 + 模型 + 重试次数 + 降级次数，输出单次任务总成本。

#### 7. 延迟敏感场景

小模型首 token 快（典型 100~300ms），大模型首 token 慢（典型 500~1500ms）。**延迟敏感场景** = 用户在前端等着看第一行字：

| 场景 | 路由选择 |
|------|----------|
| **首句 / 摘要 / 简单问答** | 小模型（首 token 快） |
| **复杂代码生成** | 大模型（首 token 慢但必须） |
| **流式首屏** | 小模型先吐占位，再后台大模型补全 |

**例子**：客服自动回复的「您好，我是 AI 助手...」（小模型 100ms 出）vs 真正的答案（大模型 1500ms 出）——两段拼接。

**需求 7（延迟敏感路由）**：实现「首句小模型 + 完整答案大模型」的拼接路由；对比端到端首字延迟。

#### 8. 质量风险控制

**路由错的两类代价**：

| 错误方向 | 后果 |
|----------|------|
| **难题 → 小模型** | 答错 / 答偏 → 用户投诉 |
| **简单题 → 大模型** | 浪费钱（贵模型答简单题 = 杀鸡用牛刀） |
| **路由抖动** | 同一类题有时小有时大 → 用户体验不稳 |

**例子**：外卖平台分单——简单单（小件）派给菜鸟驿站，复杂单（生鲜冷链）派给顺丰。**反过来派**，要么生鲜坏了，要么大材小用。

**需求 8（路由质量兜底）**：路由选错时（小模型答错）的兜底：自动升级到大模型重试；统计路由错率。

#### 9. 可观测

每次路由决策必须能追溯：

| 字段 | 含义 |
|------|------|
| `request_id` | 请求唯一 ID |
| `route_strategy` | 用了哪种路由（规则 / 分类器 / LLM） |
| `selected_model` | 选了哪个模型 |
| `selection_reason` | 为什么选（关键词 / 分类结果 / 置信度） |
| `router_cost` | 路由器自己的成本 |
| `main_cost` | 主调用成本 |
| `total_cost` | 总成本（含重试 + 降级） |
| `fallback_used` | 是否降级 |

**例子**：餐厅每桌账单——菜价 + 服务费 + 包间费 + 加菜补单 = 总价。路由也要算清每一项。

**需求 9（路由日志与指标）**：每次路由决策写结构化日志；暴露「路由分布 / 路由错率 / 平均总成本 / 降级率」4 项指标。

#### 10. 动态调整：灰度 / A/B / 流量切换

路由策略不是一成不变：

| 调整 | 怎么做 |
|------|--------|
| **灰度上线** | 新路由策略从 5% 流量开始，逐步放大到 100% |
| **A/B 测试** | 同一请求分别跑两套路由策略，对比成本 + 质量 |
| **流量切换** | 紧急情况手动切到固定模型（如所有请求走大模型保质量） |

**例子**：外卖平台新分单算法上线——5% 商家先试（灰度）→ 看效果不错再全量。

**需求 10（灰度切换）**：实现路由策略的灰度上线机制（按百分比 / 按用户群 / 按请求类型）；能在故障时一键切回旧策略。

### 例子

#### 餐厅分菜（按难度路由）

简单沙拉走厨师 A（快便宜）→ 牛排走厨师 B（慢贵强）→ A 病了（挂了）→ 全部由 B 接手（**降级**，不是路由）。

对应：**路由按难度选**；**降级按可用性选**。

#### 医院分诊（路由判定输入）

感冒走普通门诊（小模型），心脏病走专家门诊（大模型）。输入信号：症状关键词。

对应：**关键词规则路由**。

#### 快递分单（输入长度路由）

同城小件走普通快递（小模型），跨省大件走顺丰（大模型）。输入信号：重量 + 体积 + 目的地。

对应：**多信号规则路由**。

#### 自动驾驶（路由 vs 级联）

先 LCC（低级辅助）跑（市区小模型）→ 高速场景升级到 NOA（高级辅助）→ 这是**路由**（按场景预判）。
先 LCC 跑，遇到复杂场景升级到 NOA → 这是**级联**（跑完再决定）。

对应：**两种模式按场景分**。

#### 客服自动回复（延迟敏感路由）

「您好，我是 AI 助手...」（小模型 100ms 出）→ 用户先看到问候 → 后台大模型算答案 → 答案出来接上。

对应：**流式首屏拼接**。

#### 网约车派单（按用户等级路由）

VIP 用户派专车（大模型决策）→ 普通用户派快车（小模型决策）。

对应：**用户等级信号**。
