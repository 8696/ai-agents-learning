### 一句话讲完这个模块

**「自己写一遍 Agent 循环 + 给循环套 7 道闸门，确保不烧账单 / 不卡死 / 不卡工具 / 听用户话。」** 对着不懂的人说：Agent 是个 while 循环，模型「想 → 做 → 看」三步无限跑。**「想跑多久」必须用闸门管**——7 道闸（按轮数 / 按时间 / 模型主动停 / 用户取消 / 工具重试 / 同模式死循环 / 成本预算）最少必备 4 道，否则 Agent 烧账单 / 调爆工具 / 等不到结果。

### 这些条怎么连成一条线

模块 07 共 3 条外部 + 1 条复盘（**当前条**）：

- **01-Agent-Loop-ReAct** 是本模块的**底座**——把 while 循环的「想 → 做 → 看」骨架写出来（ReAct 论文 + 多次工具调用 + 轨迹可见）。没有底座，下面两条没有意义。
- **02-先规划再执行 vs 一步步走** 是**节奏选择**——同一段任务用「先出计划再执行」还是「走一步看一步」，**两种都是合法的 Agent 节奏**，按业务挑。闸门是这层都通用的，但节奏不同决定了闸门触发频率。
- **03-死循环防护** 是本模块的**收口**——把 Agent 循环容易出的三种灾难（烧账单 / 卡死外部 / 等不到结果）逐一拆成 7 道闸门，演示「为什么必备」+「按业务选装」+「7 闸叠加谁先到谁说了算」。

**01 → 02 → 03 是层层递进**：
- 01 告诉你「循环长什么样」
- 02 告诉你「循环节奏可以选」
- 03 告诉你「循环怎么停」——前两节留的「无限跑」问题全在这一节收口

**02 vs 03 不是替代关系**：节奏是「循环的策略」，闸门是「循环的护栏」。即使你选了「一步步走」也需要 7 道闸。

**常见坑对答**（README 给的）：

- 「代码写死只许调一次工具就结束」——错。**真正的 Agent 循环必须能连续多轮调用工具直到任务完成**。死循环防护不是禁止多轮，是防止「停不下来」。step-1 反例就是示范这个错。
- 「用 `max=10` 就够了」——错。`max=10` 只装变体 1 一道闸，其他 6 道全没装 = 烧账单 / 卡死 / 等不到都可能发生。**最少必备 4 道**。

### 最容易记错的三条

跨条易混（**这些是本模块学习后最常复发的错**）：

1. **「max iterations 看到了就够」**——错。`max iterations` 只看「轮次」；`timeout` 看「时间」；`token budget` 看「钱」——**三个维度互补**。慢模型把响应拖到分钟级，max 看不见；快模型 + 高 max 把账单烧光，timeout 看不见；变体 1/2/7 任何两个一起装才能互补。
2. **「模型说停 = 软闸，可以单独装」**——错。模型上一轮说停这一轮又说「再试一次」很常见（这是大模型的本质特征，不是 bug）。必须叠硬闸（max / timeout）兜底，否则模型陷入「我以为我做完了」的死循环。变体 3 单独装 ≈ 没闸。
3. **「abort = kill 进程」**——错。`AbortController.abort()` 是给 while 一个「该停」的信号；**进程本身继续跑**，处理别的请求。`process.exit()` 把整个 Node 进程杀掉，所有别的用户请求也跟着死。**永远用 abort，不用 exit**。

### 踩过的坑（跨条）

按本模块学习的 8 个 demo + 文档沉淀，跨条易踩的坑（**不只是单条 demo 的踩坑**）：

- **「`AbortController.abort()` = `process.exit()`」**——abort 是给 while 信号，进程继续；exit 杀整个进程。详见 [03 「易混 3」](03-死循环防护.md) + [03 「踩坑」](03-死循环防护.md)。这条错的代价是「一个用户点取消 → 整个 Node 进程死了 → 所有别的用户请求 500」。
- **「mock 模型当真模型」**——mock 每轮都说「再查一次」是为了让闸门效果可见；真模型有「模型说停」闸，软硬闸必须叠。详见 03 「易混 5：闸门是『Agent 框架的活』不是『模型的活』」。这条错的代价是「测试时 mock 通过，上线真模型还是死循环」。
- **「`max=1000` 反正大」**——max=1000 等于没闸。要按任务合理估算（一般 5~50）。详见 03 「踩坑」。这条错的代价是「闸门形同虚设」。
- **「业务选型 = 装 7 道」**——最少必备 4 道（变体 1/2/3/4）；5/6/7 是「按业务选装」。**没有银弹**。详见 03 「场景选型」节 + step-8 业务选型面板。这条错的代价是「小项目也装 7 道 = 维护成本高；大项目只装 1 道 = 烧账单」。
- **「log 写 'task started' 不写参数」**——五条日志（开始 / 入参 / __code / 返回值 / 结束）缺一不可。`lib/logger.ts` 已经按这个规范冻结。详见 03 「## 取舍」节 + §5.3.16。这条错的代价是「出问题时只看一行，看不到带了什么进去、出来什么」。
