## 一句话讲完这个模块

模块 13 解决「**用框架替代/辅助手写 Agent 循环**」的问题 —— 让你看清「框架替你藏了什么、藏得对不对、什么时候不该用框架」。

## 这些条怎么连成一条线

- **step-1（三种走法对照）** 是入门：先看清「**同一句输入**」在不同编排产品里能走三条完全不同的路（手写循环 / 智能体应用 / 工作流画布）。没有 step-1 的对照，后面所有讨论「循环归谁」都没底座。
- **step-2（跨轮字段归谁）** 是 step-1 中栏的细化：把「消息列表归产品」拆成「**跨轮的字段也归产品**」 —— 会话变量 vs 你自己的 state 是同一个问题的不同伪装（一个藏、另一个留给自己）。
- **step-3（回边 + 次数变量）** 是 step-1 右栏的细化：画布上的圈**画是画了**，但**执行不归你** + 谁的次数变量记清楚才是闸门归谁。
- **step-4（条件分支 vs 边表核对）** 是 step-1 右栏的另一个细化：条件分支只按变量选边；边表核对才拦非法转移 —— **两件事不是同一件事**。
- **step-5（代码节点 + 输出变量）** 是 step-1 右栏的细化：局部变量函数返回就丢；要让下游读到必须写成输出变量。
- **step-5 加 page（全局 vs declared state）** 是 step-5 的反向对照：这一趟的字段归这一趟，别写进 `process.env`（密钥也混进配置）。
- **step-6（单次 vs 智能体节点）** 是 step-1 中栏的细化：**一个智能体节点**才是把 while 塞进一个方块；单独一个大模型节点**就是调一次**。minimax 这条路径传 tools 返 500（已修：前端加 provider select 让 zhipu/qwen 可切）。
- **step-7（人工方块 ≠ 检查点）** 是跨模块 11 闸门知识：产品上点「等人点头」≠ 你自己写的 checkpoint + idempotency。
- **step-8（知识库节点 vs Agent 循环节点）** 是 step-6 的细化：知识库节点 = 检索那一跳，调一次就停；Agent 循环节点 = 把 while + 调工具塞进一个方块。

**这些条不是四个独立展开问题** —— 是同一个东西的不同切片：「**编排产品替你藏了什么 / 你自己写的部分是什么**」。

## 最容易记错的三条（跨小节易混）

1. **「画了 ≠ 暴露」「写了 ≠ 进全图」**：画布上的回边画是画了，但执行权不归你（step-3）；代码节点里 `const price` 算了，但函数返回就丢（step-5）；这一趟的 cupSize 写进 declared state 是对的，写进 `process.env` 错（step-5 加 page）。**凡是要写跨小节跨轮跨进程的字段，第一反应是「进哪一层」**。

2. **「等点头 ≠ 检查点」「拖 KB ≠ 循环」「单次大模型节点 ≠ Agent」**：这三个反例属于同一类 —— 「产品上**看起来做了** ≠ **真做了**」。看产品回来能讲清「为什么这样」= 隐藏动作；不能讲清 = 落坑（step-7 / step-8 / step-6）。

3. **「脑补产品会拦 = 错」**：条件分支 ≠ 边表核对（step-4）；「未付款→出品」产品不一定会拦 —— 拦不拦看 declared 边表（你自己声明的，不是产品替你写）。**凡是想用产品机制替自己写校验时，先问「这层校验是谁写的」**。

## 踩过的坑（跨小节）

跨小节踩坑（不只是 Dify 编排产品这一小节）：

1. **「左 = 真调 / 右 = 不调」在某些 step 故意反过来**：step-1 是「左 + 中 = 真调 LLM，右 = 不调」（对照编排产品不调 LLM 是有意义的）；step-6 是「左 + 右 = 都调」 —— **不要假设「不调」=「不重要」**。判断一个 demo 在不调 LLM = 因为教学点不需要 LLM，不是 mock = 假数据。
2. **minimax 这条 OpenAI 路径对 tools 调用返 500**（P-031 引申）：打钩前要 push 一次真调，不能只看代码数决定。不调 = check-demo 全部通过 ≠ 跑得通。**修法**：客户端加 provider 字段 + route 按 provider 取 LLM 客户端（`pickLlm(provider)`）。
4. **前端 JSX 文本节点里 `<` 是被识别的**：P-032 引申。「`<think>...</think>`」这种字符串出现在最终正文里，浏览器把它当未识别 HTML 标签 → 渲染截断。修法：minimax 拆 reasoning 的 extractReasoningMiddleware 已经在用；但真接收到时还得在前端用 `{r.finalReply}` 包成表达式 + 后端 strip 掉 `<think>...</think>` 标签。
3. **JSX 写完即跑 `@babel/parser`**（P-025）：写完一个 demo 后立刻跑 `pnpm exec @babel/parser` 命令模板（P-025 引用 §5.3.6）——不要凭「看着没问题」就 commit。修法：写完即跑命令模板 + 报错按「block N: ERR Unexpected token (行:列)」精确修那一行。
5. **「用户报告 bug」先看 §3 索引有没有同类坑**：按 P-031 「minimax 把 reasoning 写在 text 里包 `<think>`」—— 已有同类坑，按修复走，不重写。**修法**：用户报「点击调用代码报错」先 grep §3 + curl 一次 → 命中已有坑就按坑的修复走，不要瞎写新修法。
