## 是什么

**思考（thinking / reasoning）**是模型在给出「给用户看的正文」之前，先走的一截内部推理。它可能计费、可能很长、通常不该直接当最终答案渲染。

同一家模型、两套协议，思考落在完全不同的字段里。下表是**信封层**（解析时先认这些位置），不是「四家官方都用同一套开关」：

| | 协议 A（Chat Completions） | 协议 B（Messages） |
| - | --- | --- |
| 流式增量可能在哪 | `delta.reasoning_content` / `reasoning_details[].text`，或 `delta.content` 里的 think 标记 | `content_block_delta.delta.thinking` vs `delta.text` |
| 非流式位置 | `choices[0].message` 的 `reasoning_*`，或 `content` 里嵌标记 | `content[]` 里 `type: "thinking"` 与 `type: "text"` |

开关叫什么、默认开还是关，是**厂商方言**，见下面「四家官方线路」。不要把 MiniMax 的 `extra_body.thinking.type = adaptive` 或 Anthropic 官方的 `enabled + budget_tokens` 当成所有协议 A/B 的写法。

**生活例子**：答题卡分成「草稿纸」和「答案栏」。草稿纸给阅卷老师核对思路（开发者面板），答案栏才贴在成绩单上（用户气泡）。两栏写混 = 用户看见一堆内心独白。

**前端例子**：流式时不能只 `text += chunk.content`。要两块 DOM：思考区追加 thinking 增量，正文区追加 content 增量。本条 Demo 左右栏就是这样。

协议相同只保证「信封长得像」，不保证思考怎么开、从哪回来、你传的字段对方会不会当真。拆成三层，别叠成一层：

| 层 | 是什么 | 谁说了算 |
| -- | ------ | -------- |
| **协议** | URL、SDK、大体字段名（`messages` / `choices[0].delta`） | OpenAI 兼容 vs Anthropic 兼容 |
| **厂商方言** | 思考开关叫什么、响应用哪几个键 | MiniMax / 智谱 / DeepSeek / 千问百炼 / 自定义网关 |
| **这个模型** | 会不会思考、默认开还是关、能不能关 | M3 vs GLM-5.3 vs deepseek-v4-pro vs qwen3.8-max |

同一套协议 A，请求参数就可以完全不是一套。MiniMax 是 `extra_body.thinking.type = adaptive` + `reasoning_split`；智谱是 `thinking.type = enabled`（GLM-5.3 **不能** `disabled`）；DeepSeek 是 `extra_body.thinking` + `reasoning_effort`；千问是 `extra_body.enable_thinking`（名字都不是 `thinking.type`）。协议 B 也不是一家：MiniMax 用 `adaptive`（默认关）；智谱强制想；DeepSeek 官方 Anthropic 表**没有开关**，强度走 `output_config.effort`；千问才是 `enabled + budget_tokens` / `disabled`。

本条 Demo **曾经**写死 MiniMax 方言。现在按四家官方各拼一套请求，页顶是官方对照表，每列再标「这一轮实测」。解析必须跟着**这一轮响应**走，不能按协议名、也不能按「我刚传了哪个键」写死。

同一套协议，返回位置也可以三种都撞上，所以解析必须跟着**这一轮响应**走，不能按协议名写死：

1. **独立字段**：`delta.reasoning_content` / `reasoning_details[].text`（协议 B 则是 `delta.thinking`），`content` / `text` 才是正文。
2. **嵌在正文**：挤在 `delta.content` 里，用 think 标记切开。
3. **看起来像没思考**：模型在想，但网关既不拆字段、也不打标记，全进 `content`。

**生活例子（方言）**：都叫快递面单（协议 A）。圆通要「增值服务码」，顺丰要勾「保价」。拿圆通的码贴到顺丰单上，单子照样能寄，那一栏是废的。

**前端例子（无效参数）**：请求 JSON 里明明有 `extra_body.thinking`，openai SDK 会带出去，网关 200 照回。页面不报「未知参数」，只表现为思考区空、或正文里突然冒出内心独白。兼容 API 的潜规则是：**不认识的字段多半静默丢掉，不 400。**「写了参数」≠「对方会用」。

## 为什么（Agent 开发要懂）

1. **JSON / 结构化输出会被思考污染**：协议 A 把思考嵌进 `content` 字符串时，下游 `JSON.parse` 会挂。工程上要剥思考，或换协议 B 不传 thinking。
2. **计费**：`completion_tokens` 常常含思考 + 正文；思考可能单独计价。看不见拆分字段就会把「贵的那截」当成普通回答。
3. **追问**：下一轮 `messages` 必须告诉模型「你上次说了啥」。协议 A 建议把思考一并回传（标记包住）；协议 B 没有 `signature` 的 thinking block **不能原样塞回去**，本 Demo 只回传正文。
4. **网关 / 厂商方言**：直连官方和自定义网关，同一套开关不一定都吐思考增量。请求里开了思考 ≠ 响应里一定有 thinking 帧。思考 Demo **不跟**顶层 `LLM_PROVIDER`：四家用各自分组的 Key + 模型 id（`MINIMAX_MODEL` / `ZHIPU_MODEL` / `DEEPSEEK_MODEL` / `QWEN_MODEL`），顶层那一行只决定「别的 Demo 现在打哪一家」。
5. **无效参数是常态，不是报错**：兼容网关常只映射 `model/messages/temperature/max_tokens`，整段 `extra_body` 或顶层 `thinking` 扔掉。看起来请求成功，旋钮其实是装饰。同一模型 id 换 `baseURL`，行为也可以两套。
6. **计费了 ≠ 把草稿纸给你**：自定义网关上 MiniMax / Qwen 的协议 A 常记 `reasoning_tokens` 却不回思考正文。官方线路上 DeepSeek / 千问 / 智谱（题够难时）的 A 会把草稿纸放进 `reasoning_content`。只看思考区会以为没想；账单上可能已经算了思考。
7. **官方文档认的键，国内站也可能不生效**：MiniMax-M3 官方写了 `reasoning_split` 和 `thinking.disabled`，直连国内站实测仍可能把思考嵌进 `content` 的 think 标记，关思考也关不干净。页上「这次实测」比请求 JSON 更可信。

## 易混点

| 别混成 | 差在哪 | 判错会怎样 |
| ------ | ------ | ---------- |
| 思考 = CoT Prompt | CoT 是你在 **Prompt 里要求「一步步想」**；thinking 是 **API 字段 / 模型能力** | 只写「请思考」却去协议 A 里找 `thinking` 参数，找不到就以为没思考 |
| `reasoning_split` = 开关思考 | 它只改**思考出现在哪**（独立字段 vs content 里的标记），不负责开/关 | 关思考要 `thinking: { type: "disabled" }`（M3）；M2.x 可能关不掉 |
| 协议 A / B 思考能用同一套解析 | A 是字符串帧 + 可能跨 chunk 的标记；B 是事件流 + 独立 block | 一套 parser 会把 B 的 thinking 当正文，或把 A 的标记渲染给用户 |
| 追问时两边历史可以同一个数组 | A、B 上一轮 assistant 文本不同，必须**分协议各记一份** | 用 A 的回答去当 B 的历史，B 会「记得」它没说过的话 |
| 「协议 A 都有 thinking 参数」 | MiniMax 是 `extra_body.thinking`；千问是 `enable_thinking`；DeepSeek 才是 `thinking.type enabled/disabled`。都不是 Chat Completions 标准字段 | 拿 MiniMax 的键去打千问，官方当空气或行为完全另一套 |
| 「参数无效 = 请求失败」 | 无效常常是 **200 成功但没生效** | 你以为开了思考、关了拆分，其实网关当没看见 |
| 「同一模型 id 换 baseURL 行为不变」 | 模型名可以一样，**网关实现可以完全两套** | 官方千问 A 回 `reasoning_content`，custom 上可能只计费不回文本 |
| 「协议 B 都是 enabled + budget_tokens」 | MiniMax-M3 官方是 `adaptive`（默认关）；DeepSeek 官方 Anthropic 表没有开关；智谱 GLM-5.3 强制想 | 四家共用一份 B 请求体会 400，或看起来开了其实没开 |
| 「GLM-5.3 能像别家一样关思考」 | 官方写明传 `disabled` **会失败**；本 Demo 关思考时跳过智谱两列 | 真发了就整列红字，不是「关了但还在想」 |
| 「协议 B 默认关思考」 | 直连 Anthropic / MiniMax 协议 B 默认关；智谱 / DeepSeek / 千问协议 B 默认就想；**custom 网关上四个模型默认都有 thinking 块** | 不传 `thinking` 就以为没思考 |
| 「思考区空 = 模型没想」 | 可能是网关剥了文本、题太简单没吐字段、或 `usage.reasoning_tokens` 仍 > 0 | 以为免费/没推理，其实在为看不见的思考付钱 |
| 「顶层 LLM_PROVIDER 决定思考 Demo 打谁」 | 思考 Demo 按 `PRODUCTION_PROVIDER_IDS` 同时打四家分组；`LLM_PROVIDER` 只影响其它只认当前家的入口 | 改顶层却看不到千问，或以为必须切到 `qwen` 才能对照 |

## 例子（数据怎么走）

第一句：「23 × 47 等于多少？」

1. 页顶先看到四家官方方言表（怎么开、怎么关、回哪个字段）。勾选要打的模型、开/关思考。
2. 浏览器对每家并发 `POST /api/stream`（`provider` + `protocol: A|B`），body 里 `messages` 最后一条是 user。顶层 `LLM_PROVIDER` **不用改**。
3. 服务端按该家官方方言组请求（不是写死 MiniMax `extra_body`），SSE 先发 `meta`（这次真正带的开关字段），再发 `thinking` / `content` / `raw`。
4. 页面按轮、按模型追加：每家左右两列（协议 A / B），思考区、正文区、原始请求、原始帧。
5. 追问「再乘以 2」：A 的 `messages` 含上一轮思考（MiniMax 用 think 标记包住；智谱 / DeepSeek / 千问带 `reasoning_content`）；B 的 assistant 只有正文（没有 signature 的 thinking 块不能原样回传）。
6. 每一列有「这一轮怎么开 · 从哪回来」：官方字段说明 + 这次请求开关 JSON + **实测**是单独字段 / 嵌在正文 / 没有思考增量。

**无效参数怎么演一遍**：官方文档写了的键，直连仍可能 200 但没生效（见 MiniMax 国内站）。自定义网关上更常见：整段 `extra_body` 当空气。那不是页面坏了，是这一跳线路没实现这个方言。

工程收口：解析跟着响应走，不跟着请求走；下游只信拆开后的正文。

### 四家官方线路（2026-09-03，直连各家，不是 custom 网关）

模型：`MiniMax-M3`、`glm-5.3`、`deepseek-v4-pro`、`qwen3.8-max`。Demo 用各自分组 Key，协议 A / B 各打一次。下面「官方」是文档怎么写；「实测」是这一轮 SSE。

| 模型 | 协议 A 官方开/关 | 协议 A 思考回哪 | 协议 B 官方开/关 | 协议 B 思考回哪 |
| --- | --- | --- | --- | --- |
| **MiniMax-M3** | `extra_body.thinking.type = adaptive` 开（默认开）；`disabled` 关。`reasoning_split` **只改位置** | 拆开应走 `reasoning_details` / `reasoning_content`；不拆则嵌 `content` 的 think 标记 | **默认关**；`thinking.type = adaptive` 开（不是 `enabled + budget_tokens`） | 独立块 `delta.thinking` |
| **glm-5.3** | `thinking.type = enabled`（强制开）；传 `disabled` **会失败**，Demo 关思考时跳过 | `delta.reasoning_content` | 默认就想；不能关，Demo 关思考时跳过 | 独立块 `delta.thinking` |
| **deepseek-v4-pro** | `extra_body.thinking`：`enabled` / `disabled`（默认开），可带 `reasoning_effort` | `delta.reasoning_content` | 官方 Anthropic 格式**没有开关**；强度 `output_config.effort`。要关走协议 A | 独立块 `delta.thinking` |
| **qwen3.8-max** | `extra_body.enable_thinking`：true / false（默认开；名字不是 `thinking.type`） | `delta.reasoning_content`。`preserve_thinking` 默认开，追问要回传该字段 | `thinking.type = enabled` + `budget_tokens` 开；`disabled` 关 | 独立块 `delta.thinking` |

本对话直连实测（简单乘法 / 鸡兔）：

- **MiniMax A** 即使传了 `reasoning_split: true` 或 `thinking.disabled`，思考仍可能嵌在 `content` 的 think 标记里 → 文档认的键，国内站可以不生效。
- **MiniMax B** `adaptive` → 独立字段 `delta.thinking`，和文档一致。
- **DeepSeek A** `enabled` → `reasoning_content`；**DeepSeek B** `output_config.effort=high` → `delta.thinking`。
- **智谱 A** 太简单的题可能不吐 `reasoning_content`（思考区空、正文仍有答案）；鸡兔同笼会走独立字段。关思考不发请求。
- **千问 A** `enable_thinking: true` → `reasoning_content`，和百炼文档一致。

和 custom 网关那张表对照：同一模型 id，换 `baseURL` 就是两套世界。官方上千问 A 会回思考文本；custom 上它往往只计 `reasoning_tokens`。官方上 MiniMax B 默认关、要 `adaptive` 才开；custom 上四家 B 默认都有 thinking 块且关不掉。

**生活例子**：四家快递公司都收「保价」。有的保价栏叫 `adaptive`，有的叫 `enable_thinking`，有的根本没这一栏（DeepSeek 的协议 B）。把圆通的码贴到顺丰单上，单子照样寄出，保价是废的。

**前端例子**：页上勾选四家再点发送 = 最多 8 路流式。每列自己的开关 JSON 和实测来源，不要把 MiniMax 那一列的 `extra_body` 抄去解释千问。

### 自定义网关四模型实测（`LLM_PROVIDER=custom`，2026-09-02）

线路：协议 A `…/v1`，协议 B 不带 `/v1`。模型 id：`minimax-m3`、`deepseek-v4-pro`、`glm-5.3`、`qwen3.8-max`。试过的开/关写法（多数被当空气）：A 默认、`extra_body.thinking.adaptive` + `reasoning_split`、`thinking.disabled`、`enable_thinking` true/false；B 默认、`thinking.enabled` + `budget_tokens`、`thinking.disabled`。题分两档：简单「23×47 只答数字」；鸡兔同笼（逼它真的想）。

这套网关上的硬结论：**思考开关几乎不跟你传的参数走**；同一协议四个模型返回位置也不一样。

| 模型 | 协议 A 怎么开 | 协议 A 能不能关 | 协议 A 思考回哪 | 协议 B 怎么开 | 协议 B 能不能关 | 协议 B 思考回哪 |
| --- | --- | --- | --- | --- | --- | --- |
| **minimax-m3** | 不用开。题够难时 `usage` 自己就有 `reasoning_tokens`。五种开法**看不出差别** | 传 `disabled` 后仍有 `reasoning_tokens` → **关不掉** | **不回思考正文**（无 `reasoning_content`，流式只有 `delta.content`）。只能从 `usage.completion_tokens_details.reasoning_tokens` 知道「想过、也计费了」 | **默认就有** thinking 块，再传 `enabled` 一样 | `disabled` 后仍是 `thinking`+`text` → **关不掉** | 独立块 `content[].type=thinking`；正文 `type=text` |
| **deepseek-v4-pro** | **默认就开**，不传思考字段也有 | `disabled` / `enable_thinking:false` **仍在想** | 独立字段 `message.reasoning_content`；正文 `content` 是答案。难题+强制关时出现过一次**只计费、字段空了**（吞回包，不是真关） | 默认就有 thinking 块 | `disabled` 仍有块 → **关不掉** | `content[].type=thinking` |
| **glm-5.3** | **默认就开** | A 上 `disabled` **仍回** `reasoning_content` | 同 DeepSeek：`reasoning_content` + 正文 `content` | 默认有 thinking 块 | **不稳定**：简单题+`disabled` 仍有块；鸡兔+`disabled` 有一次只剩 `text`。不能当可靠开关 | 开着时是独立 thinking 块 |
| **qwen3.8-max** | 和 MiniMax 同一类：难题会记 `reasoning_tokens`，你传的开法**全无效** | 关不掉计费思考 | 协议 A **不回思考文本** | 默认就有 thinking 块 | `disabled` 仍有块 → **关不掉** | `content[].type=thinking` |

简单乘法时：`minimax-m3` / `qwen3.8-max` 的 `reasoning_tokens` 为空（太简单就不想）；`deepseek-v4-pro` / `glm-5.3` 简单题也会想，并且 A 把草稿纸放在 `reasoning_content`。

和 Demo 的关系：思考 Demo 现在同时打官方四家，不再写死 MiniMax。若只开 custom 网关那一组，行为仍以本小节上一张表为准，不要和官方表混成一张。

**生活例子**：四个房间都写着「空调遥控」。有的键按了温度不动（无效参数）；有的默认一直开、没有关（DeepSeek / 多数 B）；有的制热在走、出风口被挡板挡住（MiniMax / Qwen 在这套 **custom** 网关的协议 A：钱扣了，草稿纸不给你）。

## 过关自检

合上笔记能讲清：

1. 思考和正文为什么要分开展示、混在一起会怎样。
2. 协议只定信封；开法按厂商：MiniMax `adaptive`、智谱强制 `enabled`、DeepSeek `extra_body.thinking`、千问 `enable_thinking`。协议 B 也不全是 `enabled + budget_tokens`。
3. 流式时 A 可能来自 `reasoning_content` / `reasoning_details` / content 里的 think 标记；B 来自 `delta.thinking`。跟着这一轮响应走。
4. 追问时为什么 A 可以回传思考、B 默认只回传正文。
5. 同一协议换厂商，开法 / 返回位置可以不同；请求里写了的思考参数，对方可以静默当无效（官方 MiniMax 国内站也会）。
6. custom 网关上：四模型 B 默认都有思考块且关不掉；A 上 DeepSeek/GLM 回 `reasoning_content`，MiniMax/Qwen 往往只计 `reasoning_tokens`。
7. 官方四家直连：开关多数跟文档走，但 MiniMax A 的拆分/关闭可能不生效；智谱太简单可能不吐思考字段；思考 Demo 不跟顶层 `LLM_PROVIDER`。
