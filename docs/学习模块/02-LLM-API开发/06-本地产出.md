## 这一课解决什么问题

按条 Demo 把 SSE、协议字段、取消、429、思考拆帧看清楚。本地产出要让值班**办完一件事**：贴客户问句 → 流式草稿 → 可选终审。不是把协议和故障按钮摆在同一页。

## 是什么

**豆谷值班台**一件产品：

1. 出草稿：协议 A + SSE + 取消 + 用量
2. 提交终审：协议 B + 一次性完整稿 + 用量

非流式能力用在终审，不单独做「关流式」勾选。

## 为什么

客服不会先选协议再选是否流式。草稿要尽快看见字；终审要一次拿稳妥稿。限流是后台的事，不是首页开关。

## 易混点

| 组 | 差在哪 |
| --- | --- |
| **产品 vs 拼盘** | 产品：问句 → 草稿 → 终审。拼盘：协议 A/B、流式勾选、故意 429 |
| **停止刷新 vs 服务端停算** | Abort 停的是客户端读流；上游可能还在生成 |
| **退避 vs 故意 429 按钮** | 产品里真 429 会重试；教学时间线在按条 Demo |

## 例子

贴「订单 80012345 到哪了？」：草稿逐字出现，底部有 Token 和估算成本。点停止刷新，字不再增加。再点终审，出现一版更稳的对外回复（协议 B）。

## 取舍

- 默认流式出草稿（TTFT）；终审非流式（完整稿再展示）。
- `PRICE_PER_1K = 0.001` 是教学占位价，不是账单。
- 思考拆帧不进值班首页。

## 踩坑

- 上一版首页是协议/流式/故意 429 拼盘，已返工。
- 真 API 不一定撞得出 429；产品路径是退避，对照实验去 `50204`。
- 多次开服务端口占用：`50206` 被占就先停旧进程。
