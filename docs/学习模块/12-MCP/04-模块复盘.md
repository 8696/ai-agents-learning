### 一句话讲完这个模块

MCP（Model Context Protocol）是一种「让 Agent 标准化地连接外部工具和数据」的协议。Agent 通过 MCP Client 连 MCP Server，按 JSON-RPC 2.0 调 Tool（动作）/ Resource（事实数据）/ Prompt 原语（用户点选的话术模板）；生产形态用 Streamable HTTP + 按用户鉴权（API Token / OAuth 2.1），玩具形态用 stdio。**MCP 管「能访问什么」，做法知识（怎么按你们的店规做）归 Skills / `AGENTS.md` / `SKILL.md`**——两条线不互相替换，按业务性质分桶。

### 这些条怎么连成一条线

```
01 MCP 架构（连接能力 + 三种原语）
    │  给出「客户端 / 服务端 + tools/call / resources/read / prompts/get」三种动词
    ▼
02 stdio vs Streamable HTTP（连接怎么传 + 怎么鉴权）
    │  给出「本地玩具 vs 远程生产 + 按用户鉴权」两个轴
    ▼
03 Skills vs MCP（连接能力 vs 做法知识分桶）
    │  把 Agent 旁边的工具协议 vs 仓库规则文件 / 技能包分开
    ▼
模块验收
```

- **01 → 02**：01 把 MCP 当「通用协议结构」讲完；02 才补上「这根管子怎么走、按用户怎么验身份」。没有 01 的协议形状，02 没法讲「按用户鉴权发生在 MCP 服务端」；没有 02 的鉴权，03 没法讲「店规在技能里，但真出杯必须按当前用户身份来」。
- **02 → 03**：02 解决「怎么接上吧台」，03 补「接上了吧台，但店规还要看」。02 已经按用户鉴权（HTTP + Token / OAuth），03 用「做法知识 vs 连接能力」把店规从工具描述里搬走。
- **三条不是一个硬币的两面**——01 和 02 是「连接层怎么造」，03 是「做法层怎么放」；03 不是 01 / 02 的兜底，而是同一宿主里另一条职责线（连接能力 vs 做法知识），所以才能独立按需求 5 / 6 / 7 拆分类题和三栏入口对照。

### 最容易记错的三条

1. **「MCP = Tool Calling 升级版」**：不是。MCP 是一种发现 + 鉴权 + 传输的协议（JSON-RPC 2.0 + transport + auth）；Tool Calling 是 Agent 决定调哪个工具的那一圈推理（`tools` → `tool_call` → 执行 → `tool_result`）。两者不是同层。误记成「升级版」会让你跳过「为什么有 MCP」「谁提供工具」这两个问题。
2. **「做了 MCP 就够了」**：不够。接上吧台不会让 Agent 按店规做——过敏客人照样喝到奶咖。要 MCP + 技能 + 仓库规则文件三件齐。模块 03 的分类题题 1（`apply_latte_policy` 这种只返文本的假工具）就是反例：店规放进 MCP 工具是错配（没副作用 = 不是 MCP 那种有真调用的协议）。
3. **「System Prompt 把店规全塞进去」**：错。System Prompt 是这一轮角色设定，不是全店制度库。模块 03 的 system-prompt-full vs on-demand 对照证明：周报全文每次塞进 System Prompt 会让「客人只问菜单」也背周报全文；正确做法是 AGENTS.md 留短底线常驻 + 技能按 utterance 命中按需加载。

### 踩过的坑（跨小节）

- **把 stdio 当「玩具」就跳过去**：stdio 不是玩具，是「父子进程同一台机器」最直接的协议边界；HTTP 是「Server 跨网络 + 按用户鉴权」的协议边界。两者不是「复杂 / 简单」对照，是「使用场景」对照。误读会让你在生产里选错传输层。
- **混 MCP 提示词模板（Prompt 原语）和 Skill**：上一节演示里的 `customer_service_greeting` 是 MCP 提示词模板（用户点选 → 服务端填参 → 返回 messages）；出杯技能是 Skill（任务相关时由宿主加载）。模块 03 的三栏对照证明它们住在不同地方、由不同主体决定用，控制权完全不同。混成一个会丢掉「谁决定用」这一维度。
- **点咖啡小程序当例子 vs 值班台退款**：第 1 / 第 2 节演示已经是点咖啡小程序 / 吧台（`make_latte` / `cafe://allergy-info` / `customer_service_greeting`），第 3 节应继续用同一家店，否则前一节的 workspace 传来关不上。模块 03 是因为这一约束贯穿 1+2+3，避免来回切场景。
- **把「学习 Agent 怎么用 MCP」和「学习怎么在 Agent 框架里写 MCP Server」混淆**：本模块只学前者（点咖啡小程序做宿主，按 MCP 协议接吧台）。怎么用 SDK / LangChain / Anthropic Agent SDK 写一个 MCP Server 框架里的 Host 是后面模块的事。
