### 一句话讲完这个模块

让 Agent 在「**看得到**」的两种范围里点得动——**Browser Agent** 看网页里的无障碍树，按角色和名字去点；**Computer Use** 看整个桌面的截图，按坐标（或操作系统的无障碍 API）去点；两者**差范围、差精度、差风险**，但共享同一组设计取舍：操作信号怎么走、失败怎么处理、敏感动作怎么拦、动作和值怎么可观测。

### 这些条怎么连成一条线

**01 Accessibility Tree** 是「Agent 看得到网页」这件事的最小可行方案：浏览器为读屏软件另算一棵树，给模型读够用。这一节给一组**确定性的抓手**——角色 + 可访问名称 + 状态，跟类名脱钩，跟样式脱钩；模型能反复用同一个动词点同一个控件。

**02 Computer Use** 是「01 这条思路走出浏览器后的样子」：浏览器里有无障碍树，桌面有截图（或操作系统的无障碍 API，如 Windows UI Automation / macOS Accessibility API / Linux AT-SPI）；模型能反复用同一个动词点同一个桌面控件。两者是**同一条主线在两个范围**的应用——同一个「Agent 看得到 → 操作信号 → 失败兜底 → 隔离与可观测」链条。

具体关系：

- **范围**：01 = 浏览器标签页（Tab）；02 = 整桌 / 指定窗口。
- **操作信号**：01 = 角色 + 名字；02 = 像素坐标（无无障碍树时）或操作系统的无障碍 API（暴露时）。
- **精度**：01 稳定（同 Tab 里名字不变）；02 脆（坐标随分辨率 / 缩放 / 多显示器变）。
- **风险面**：01 在浏览器进程内；02 在整个桌面（文件、已登录会话、跨应用）。
- **隔离**：01 用沙箱 profile；02 用虚拟机（Anthropic 官方推荐）。
- **失败路径**：01 是「无障碍快照过期 / 动态加载后没重取」；02 多一类「坐标点空 / 弹窗遮挡 / 敏感操作未拦住」。
- **可观测**：01 是快照 + 动作；02 多一类「敏感字段打码 + 双截图差异比对」。

**01 是 02 在网页里的特化版；02 是「01 这条思路」走出浏览器后的样子。** 从这层看，**01 是 02 的前提**——01 让你理解了「为什么角色 + 名字是好抓手」和「为什么短快照比整页 HTML 好」；到了 02，这套思路要套上**桌面这层独有的脆、风险、与权限问题**。

**README 自测问题同步回答**

- *为什么用 Accessibility Tree 而不是 DOM？* 01 给出答案：精确（角色和名字稳定）+ 短（词元省一个数量级）+ 不随样式变。
- *Browser Agent 的可靠性瓶颈在哪？* 01 + 02 共同答案是：**快照过期**（动态加载、对话框、虚拟列表、影子树）和**同名控件**这两件最容易让模型判断错；Computer Use 还多一类**坐标脆**和**风险面**。

### 最容易记错的三条（跨条）

1. **无障碍树 ≠ 截图**。Browser Agent 拿无障碍树（角色 + 名字 + 状态），Computer Use 拿截图（像素 + 文字识别（OCR）+ 视觉语言模型（VLM））。把它们当同一条路会出现「我截一张图给模型看，模型应该也能按角色和名字点」——做不到。前者拿到的是「控件」，后者拿到的是「颜色块」。准确说后者要依赖操作系统的无障碍 API 才能拿到「控件」。
2. **Browser Agent 的「网页」≠ Computer Use 的「桌面」**。把 Computer Use 当作「我也在操作网页」的备选，是浪费；它要做的事刚好是 Browser Agent **做不了**的（邮件客户端、老 Win32、企业内网、跨应用）。
3. **跑在虚拟机里 ≠ 跑在我自己的 Mac 上**。这两件事权限面差一个数量级。前者是隔离，后者是裸跑；后者任何一次「替坐席填表」都可能点错支付 / 提交 / 邮件外发。**生产 = 虚拟机 + 审计 + 敏感操作二次确认 + 敏感字段打码**，缺一不可。

### 踩过的坑（跨条）

- **把整页 HTML 塞进提示词**：01 的根本问题；一个后台页 10 万词元，类名 / 脚本都能让模型去猜一个下次发布就变的字符串。
- **只抽可见文字**：01 里的「状态徽章 vs 筛选芯片都叫『已发货』」；文字相同，一个该读、一个该点。
- **在宿主桌面裸跑模型**：02 的根本问题；桌面 + 已登录会话 = 一切权限。
- **凭模板坐标点控件**：02 的精度问题；分辨率、缩放、布局一动就废，坐标不能缓存。
- **替真人代登录 / 代签批**：02 的责任问题；合同和合规会出事。模型只整理素材，不代登录 / 代签。
- **继续调用已经删除的 `page.accessibility.snapshot()`**：01 中明确写，旧接口在 Playwright 1.57 已从接口里删除；现在用 `page.ariaSnapshot()`。
- **在可见文字上做「Computer Use 也能拿到角色」的假设**：02 里写明——Computer Use 拿到截图，看不到无障碍树，识别控件全靠操作系统的无障碍 API 或纯像素文字识别（OCR）+ 视觉语言模型（VLM）；不是同一条路。
