## 2.1 浓缩主线

```text
调得动模型 → 让模型调得动工具 → 让模型自己循环把事做完
        → 给它知识（RAG）、记忆（Memory）、状态（Workflow）
        → 用 MCP 和 Framework 把它接入真实世界
        → 用 Evaluation / Observability / Security 证明它靠谱
        → 用你的前端能力把它做成一个人们真的想用的产品
        → apps/ 里每个模块能跑、能看懂、你能讲清取舍
```

一句话：**先学会让 LLM 工作 → 再学会让 LLM 调用工具 → 再学会让 LLM 自主循环完成任务 → 再给它知识、记忆和状态 → 再用 MCP 和 Framework 扩展它 → 最后解决评测、稳定性、安全、成本和上线问题。**

1. **原理层**：Agent = LLM + Tools + Loop + State。其余全是它们的工程化。
2. **能力层**：能手写 Agent Loop 的人，学任何框架都是三天的事；只会框架的人，遇到框架不支持的场景就卡死。

每天问自己：当前模块 README 小节进度里**这一条**走完了吗（能讲清楚、链接补了没有、**该条小节 MD 按模板写了没有**；本地代码跑起来了没有、该 `apps/` 子文件夹 `README.md` 跟上了没有）？有一个「没有」下次必须补上。

## 2.2 路线图

```text
① LLM 基础（Token / Context / Transformer / Embedding）
        ↓
② LLM Application（API / Prompt / Streaming / Structured Output / Zod）
        ↓
③ Tool Calling（Schema / Execution）
        ↓
④ Agent 核心（Loop / ReAct / Planning / State / Memory）
        ↓
⑤ RAG（Chunking / Vector DB / Retrieval / Rerank）
        ↓
⑥ Workflow / MCP（State Graph / Checkpoint / HITL）
        ↓
⑦ Agent Framework（AI SDK / LangGraph …）
        ↓
⑧ Advanced Agent（Multi-Agent / Browser / Coding）
        ↓
⑨ Production（Evaluation / Observability / Security / Cost）
        ↓
⑩ Full-stack（React/Vue / 部署 / 完整产品 / README·架构图 / 能独立讲清取舍与复盘）
```

每一层都建立在你亲手实现过的上一层之上，而不是并列堆知识点。

### 顺序原则

**MCP 不是基础阶段。** 必须先走通 `LLM → Tool Calling → Agent Loop → Tool Execution`，再学 MCP 如何标准化连接。

1. **能力先于抽象。** 框架 / 协议排在它所抽象的能力之后（MCP 之于 Tool Calling，LangGraph 之于手写状态机）。
2. **单体先于协作。** 单 Agent 没扎实之前，Multi-Agent 只会放大设计缺陷。
3. **可观测先于优化。** Evaluation（17）和 Observability（18）排在可靠性/成本（19）前面。

允许的例外：模块 22 最简流式 UI 可提前到模块 02 之后；模块 13 可提前但必须先完成 07；模块 01 可深挖但不要陷进数学推导；已有后端经验则压缩模块 21。

### 两套顺序的差异

| 差异点 | 24 模块（默认） | 13 阶段 | 怎么选 |
|--------|----------------|---------|--------|
| Memory / State 与 Framework | 10、11 在 Framework(13) **之前** | 框架实战(6) 在 Memory+State(7) **之前** | **推荐前者**：先手写再看抽象 |
| 安全与多 Agent | Multi-Agent(14) 在 Security(20) **之前** | 安全(9) 在多 Agent(10) **之前** | 两者都行；较早做 Coding Agent 则提前学安全 |

**给 AI 助手**：默认按 2.3 的模块顺序；学习者明确说「按 13 阶段走」才按 2.5。

## 2.6 重点与坑

### 2.6.1 能力分级

系统性学习一定会问：「这么多东西，到底什么最重要？」分成四档。

| 等级 | 能力 | 重要程度 | 原因 |
| ---- | ---- | -------: | ---- |
| S | **LLM API + Token + Context + Streaming** | ⭐⭐⭐⭐⭐ | 所有 AI Application 的基础 |
| S | **Tool Calling** | ⭐⭐⭐⭐⭐ | Agent 的核心能力 |
| S | **手写 Agent Loop** | ⭐⭐⭐⭐⭐ | 真正理解 Agent |
| S | **RAG** | ⭐⭐⭐⭐⭐ | 企业 AI 应用极高频 |
| S | **Context Engineering** | ⭐⭐⭐⭐⭐ | Agent 效果的核心 |
| S | **State / Workflow** | ⭐⭐⭐⭐⭐ | 复杂 Agent 的基础 |
| S | **Evaluation** | ⭐⭐⭐⭐⭐ | 生产上要能做 ship/no-ship，不是「跑过一次评测」 |
| S | **Observability** | ⭐⭐⭐⭐⭐ | Debug Agent 必须具备 |
| S | **Security** | ⭐⭐⭐⭐⭐ | Agent 能执行真实操作 |
| S | **MCP（含生产形态）** | ⭐⭐⭐⭐⭐ | 生产要 HTTP + 鉴权；stdio 玩具不够 |
| S | **Coding Agent** | ⭐⭐⭐⭐⭐ | 程序员背景的差异化：文件 / Shell / 权限 / Sandbox |
| A | Browser / Computer Use | ⭐⭐⭐⭐ | 网页操作是进阶能力，不是 RAG / Workflow 的前置 |
| A | Agent Framework | ⭐⭐⭐⭐ | 实际开发会用，但不能靠框架理解 Agent |
| A | Memory | ⭐⭐⭐⭐ | 很重要，但不应该早于 Agent Loop |
| A | Multi-Agent | ⭐⭐⭐⭐ | 需要知道，但不要过早沉迷；更能讲「何时不该用」 |
| A | Skills / AGENTS.md | ⭐⭐⭐⭐ | 领域知识打包；用文档约束 Agent 行为 |
| B | A2A（Agent 间协议） | ⭐⭐⭐ | 认知即可：MCP=Agent→工具，A2A=Agent→Agent |
| B | Dify 等编排产品 | ⭐⭐ | **只体验**，能讲清和手写的差异，不当主线 |
| B | 能读 Python Agent 代码 | ⭐⭐ | 不转主线；能 `pip` 跑开源评测 / 读懂别人的 Agent |
| B | Transformer 深入原理 | ⭐⭐⭐ | 有帮助，但不用研究级深度 |
| B | Fine-tuning / LoRA / PyTorch | ⭐⭐ | Agent 开发初期不是重点 |
| C | CUDA / 从零训练 LLM | ⭐ | 和目标不是一条路线 |

| 档位 | 投入策略 | 掌握标准 |
|------|---------|---------|
| **S** | 70% 精力 | 能手写 + 能讲清取舍 + apps/ 里真实用过 |
| **A** | 20% | 能熟练使用 + 能讲清它解决什么问题 |
| **B** | 10% | 技术讨论中不露怯聊两分钟 |
| **C** | 0% | 知道它是什么、和自己无关即可 |

**给 AI 助手**：在 B / C 档停留过久，直接打断，拉回 S 档。`apps/` 子文件夹都要达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)；模块 03 / 04 / 08 / 12 是 RAG / MCP / 评测 / HITL 的主战场，模块 16 / 20 是权限 / Sandbox / 安全的主战场。不要为「显得全面」平均用力到做不厚。

---

### 2.6.2 不要「框架驱动学习」

看到 LangChain → LangGraph → Mastra → Vercel AI SDK → MCP，很容易变成「今天学框架、明天学新框架」，最后：**会 5 个框架，但是不会写 Agent。**

**第一遍完全手写**（Node + TS + LLM API + Zod）：`LLM → Tool Call → 执行 → Result → LLM → … → Final Answer`。

**第二遍再用框架。** 你会发现 LangGraph 的 State / Node / Edge / Checkpoint，就是你手写过的东西被抽象起来了。这时候才算真正学会。

---

### 2.6.3 另外四个高频坑

| 坑 | 表现 | 破解 |
|----|------|------|
| **教程永动机** | 一直看文档，代码量为零 | 看和写不低于 1:2；有代码的模块必须有 commit（理论模块如 01 写各小节 MD 即可） |
| **Demo 坟场** | 拿 20 个迷你项目代替统一作品，学完就扔 | 代码落点统一在 `apps/`（模块 00 mini-app + 每条外部小节最小可运行 Demo），新能力按 [AGENTS.md §5.2](../AGENTS.md#52-小节-demo) 落 `apps/{模块}/{小节}/`；**禁止**把 Demo 当成第二个 mini-app，也不在 `apps/` 里另外开平行 app |
| **Prompt 玄学调参** | 效果不好就改 Prompt，凭感觉判断变好 | 提前做模块 17 最小版：哪怕 20 条测试用例 |
| **只做 Happy Path** | 模型一返回意外格式就崩 | 每个模块验收强制包含异常路径 |

### 2.6.4 四个「真的学会了」的信号

1. **能画出来**：不看资料能在白板上画出数据流。
2. **能砍掉**：能说出这个技术在什么场景下**不该用**。
3. **能重建**：把代码删掉，能重新写出核心部分。
4. **能复盘**：能说出这个 Demo 最难的三个点怎么处理的，以及若重做会改哪三处。

### 2.7.2 交付标准（`apps/` 子文件夹）

模块级验收看 [docs/学习模块/](./学习模块/README.md) 对应模块 README。每个 `apps/` 子文件夹**学完时**还要同时达到下面这一条——别人打开仓库能跑、能看懂、你能讲清取舍。勾选落在 [学习总览 · 学习模块](./06-学习总览.md) 对应模块行的"本地"列。

- **README**：打开就能看懂做什么、怎么跑、数据流、技术选型与不选另一种方案的理由；按文档能跑通。别人 clone 下来不必再问你。
- **数据流**：图画的模块和 `apps/` 子文件夹里的目录对得上。
- **能讲清**：不看资料能向别人讲完一次真实输入怎么变成最终输出，以及这个 Demo 最难的三个点怎么处理的。
- **能复盘**：每个 Demo 能写出「当时最难的三处、怎么解的、若重做会改哪三处」。
- **学习总览对应格子**：README、数据流；知识库类还要有评测报告；能执行真实操作的还要有安全审计。
- **能不能改完就合进主线**：用模块 17 的数字决定，不凭感觉。

### 2.7.3 每个模块的代码落点范围和验收

拆需求时以本节为准。模块级验收仍看 [docs/学习模块/](./学习模块/README.md) 对应模块 README。

#### 模块 00 · 环境准备 → `apps/00-环境准备/01-mini-app/`

- **第一期必须有**：CLI 或 HTTP 发出一条消息并拿到流式回复；`.env` 不进 git。
- **做厚之后应有**：协议 A + 协议 B 双入口、HTTP+SSE 端点、Token / 成本打印、`.env.example` 模板、`engines >= 22` 约束。
- **模块级验收**：能向别人讲清「一次请求实际发给模型的上下文是什么」；异常路径至少测过流式被中断。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)（README / 数据流）。

#### 模块 02 · LLM API → `apps/02-LLM-API开发/0X-XX/`

- **第一期必须有**：Streaming/SSE 帧可视化（mock + 真 API 对照）；协议 A vs B 双协议端到端对照。
- **做厚之后应有**：AbortController 取消后客户端停写 + 服务端如何停；429 / 408 / 5xx 指数退避 + Retry-After + 不可重试错误（401 / 404）分类；Token Budget 滑动窗口。
- **模块级验收**：能讲清「一次请求实际发给模型的上下文是什么」；异常路径至少测过限流和取消。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 03 · Prompt → `apps/03-Prompt-Engineering/{小节文件夹}/`

- **第一期必须有**：System Prompt + Few-shot + CoT 三种模板各跑一条样例。
- **做厚之后应有**：Prompt 版本管理（同一问题的 v1 / v2 对照）；输出格式约束（JSON / Markdown）。
- **模块级验收**：能讲清 Prompt 改动为什么让效果变好 / 变差。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 04 · Structured Output → `apps/04-Structured-Output/{小节文件夹}/`

- **第一期必须有**：用 Zod 约束模型输出；解析失败时重试。
- **做厚之后应有**：JSON Mode ≠ Structured Output 对照；类型安全链路（LLM → Zod → TS Object）。
- **模块级验收**：模型返回非法 JSON 时系统怎么处理能讲清。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 05 · Tool Calling → `apps/05-Tool-Calling/{小节文件夹}/`

- **第一期必须有**：Tool Registry + 3～4 个 Tool 的完整调用闭环（含参数校验和错误回传）。
- **做厚之后应有**：至少一个 Tool 幂等；Tool Gateway（执行前鉴权，模型请求不等于执行）。
- **模块级验收**：不是「调一次工具就结束」；能画完整调用图。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 06 · 多轮 / Context → `apps/06-多轮对话与Context/{小节文件夹}/`

- **第一期必须有**：完整多轮对话 + Context Window 边界演示。
- **做厚之后应有**：摘要 vs 滑动窗口 vs 选择性注入三种策略；Token Budget 仪表盘。
- **模块级验收**：能讲清「模型为什么会忘记，以及如何给模型正确上下文」。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 07 · 手写 Agent → `apps/07-手写Agent/{小节文件夹}/`

- **第一期必须有**：无框架的 Reason → Act → Observe 循环 + 停止条件 + trajectory 打印。
- **做厚之后应有**：Retry / Timeout / Error Recovery；至少一次完整"模型编了一个不存在的 Tool"的错误处理。
- **模块级验收**：完全无 Agent 框架；杀掉进程能 resume 且不重复有副作用的 Tool。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 08 · RAG 基础 → `apps/08-RAG基础/{小节文件夹}/`

- **第一期必须有**：Markdown/PDF → Chunk → Embedding → 向量检索 → 注入 Prompt；检索是 Tool，不是每次都检索。
- **做厚之后应有**：Chunk Size / Overlap 对照；Top-K 边界；知识库里没有答案时说不知道。
- **模块级验收**：一次错误回答能归因到切分 / 检索 / 生成。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 09 · RAG 进阶 → `apps/09-RAG进阶/{小节文件夹}/`

- **第一期必须有**：Hybrid Search（向量 + BM25）+ Rerank + Query Rewrite；带引用。
- **做厚之后应有**：Parent-Child / Contextual Retrieval / Multi-query；≥20 条 RAG 评测集。
- **模块级验收**：检索失败时模型能优雅说不知道。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 10 · Memory → `apps/10-Memory/{小节文件夹}/`

- **第一期必须有**：短期（当前对话）+ 长期（用户偏好 / 历史）两类记忆分开存储。
- **做厚之后应有**：记忆冲突处理（「用 React」→「改 Vue」）；Entity Memory（人名 / 项目名）。
- **模块级验收**：能讲清三类记忆（工作 / episodic / semantic）各存什么。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 11 · State / Workflow → `apps/11-Agent-State-Workflow/{小节文件夹}/`

- **第一期必须有**：手写 State Machine + Checkpoint；可暂停 / 恢复 / 人工确认。
- **做厚之后应有**：Durable Resume（杀掉进程能 resume）；Reflection / Planner-Executor 两种范式对照。
- **模块级验收**：能讲清 State 里**不能**存什么。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 12 · MCP → `apps/12-MCP/{小节文件夹}/`

- **第一期必须有**：自己写的 MCP Server（≥2 个 Tool + 1 个 Resource）被 Agent 当 Client 调通；stdio 之外还有 HTTP 形态。
- **做厚之后应有**：HTTP + 最简鉴权；Skills vs MCP 边界。
- **模块级验收**：能口头区分 MCP 与 A2A。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 13 · Agent Framework → `apps/13-Agent-Framework/{小节文件夹}/`

- **第一期必须有**：用 Vercel AI SDK 或 LangGraph.js 重构模块 07 的手写 Agent；保留 State / Checkpoint / HITL。
- **做厚之后应有**：Handoff / Agents as Tools 两种多 Agent 范式；Guardrails。Dify 只体验、能讲差异即可。
- **模块级验收**：能列出「手写版 vs 框架版」至少三条具体差异。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 14 · Multi-Agent → `apps/14-Multi-Agent/{小节文件夹}/`

- **第一期必须有**：Researcher + Writer + Reviewer；能讲 Supervisor / Worker 分工。
- **做厚之后应有**：单 vs 多 Agent 成本 / 延迟对比；Shared State vs 隔离。
- **模块级验收**：能论证某任务该不该上多 Agent（含成本和延迟）。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 15 · Browser Agent → `apps/15-Browser-Computer-Agent/{小节文件夹}/`

- **第一期必须有**：Playwright 基础 Tool，用 Accessibility Tree 描述页面，完成一个多步骤网页任务。
- **做厚之后应有**：Screenshot / Click / Type / Navigate / Extract；动态页面降级方案。
- **模块级验收**：Browser 任务规划能拆解为 N 步。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 16 · Coding Agent → `apps/16-Coding-Agent/{小节文件夹}/`

- **第一期必须有**：读 / 改文件、受限 Shell、Git；危险操作 HITL。
- **做厚之后应有**：`AGENTS.md` / `SKILL.md`；精确编辑文件而不是整文件重写。
- **模块级验收**：Agent 不能碰到工作目录之外的文件。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 17 · Evaluation → `apps/17-Agent-Evaluation/{小节文件夹}/`

- **第一期必须有**：Golden Dataset + 一条命令出报告（accuracy / faithfulness / tool accuracy）。
- **做厚之后应有**：改动前后用数字决定 ship/no-ship；评测进 CI。
- **模块级验收**：能讲清 LLM-as-Judge 的偏差与缓解。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)（含评测报告）。

#### 模块 18 · Observability → `apps/18-Observability/{小节文件夹}/`

- **第一期必须有**：完整 Trace / Span，含 LLM Call / Tool Call / Latency / Token Usage。
- **做厚之后应有**：Agent Trajectory 可视化；LangSmith 或 Langfuse 接入。
- **模块级验收**：出错时能定位到具体 Span。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 19 · 可靠性 / 成本 / 性能 → `apps/19-可靠性成本性能/{小节文件夹}/`

- **第一期必须有**：重试、限流、缓存、成本统计四件套。
- **做厚之后应有**：熔断 / 队列 / Prompt Caching / Model Routing。
- **模块级验收**：能讲清某任务该不该用次级模型降级。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 20 · Security → `apps/20-AI-Security/{小节文件夹}/`

- **第一期必须有**：Tool Gateway（执行前策略层）；System Prompt 与 API Key 不泄漏验证。
- **做厚之后应有**：间接 Prompt Injection 自我攻击一次；OAuth 委托 vs 服务账号 Key 边界。
- **模块级验收**：做一次完整 Security Audit。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)（含安全审计）。

#### 模块 21 · 后端 / 基础设施 → `apps/21-后端与基础设施/{小节文件夹}/`

- **第一期必须有**：REST + SSE + 队列的最小后端骨架；Agent 部署成可访问服务。
- **做厚之后应有**：WebSocket / PostgreSQL / Redis / Object Storage；Docker 镜像。
- **模块级验收**：能讲清生产环境下流式响应在网关 / 超时 / 重连上的坑。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

#### 模块 22 · AI 全栈产品化 → `apps/22-AI全栈产品化/{小节文件夹}/`

- **第一期必须有**：流式 Markdown 渲染 + Tool Status + Agent Steps 可视化。
- **做厚之后应有**：引用展示 / 文件上传 / 任务状态 / Human Approval UI / 错误 UI。
- **模块级验收**：能讲清前端如何优雅展示 Agent 执行过程。同时达到 [2.7.2 交付标准](#272-交付标准apps-子文件夹)。

### 2.8 综合验收（模块 23 收口）

每个模块都达标之后，还要用下面这一条确认：**整条路线是通的，不是孤立的小节。** 勾选落在 [模块 23](./学习模块/23-Production-Agent-Architecture/README.md) 小节进度；自测题见 [题库 4.8](./04-自测题库.md#48-综合验收模块-23)。

| 验收项 | 要能讲清 |
| ------ | ---------- |
| **仓库能独立跑通** | `apps/` 每个子文件夹 README 按文档能跑；`.env` 不进 git；数据流和目录一致 |
| **选型能讲清** | 每个关键技术能说出至少两个备选、以及**为什么不选**另一个 |
| **Demo 能复盘** | 每个 `apps/` 子文件夹能讲：最难的三个点、怎么处理的、若重做改哪三处 |
| **原理能串讲** | 不看资料，用自己 apps/ 里的例子讲清：Token / Context、Tool Calling、Agent Loop、RAG 流水线、MCP 三原语（stdio vs HTTP） |
| **能独立设计** | 给定约束（例如企业内部知识库、要引用、要 HITL、长任务不能占死 HTTP），能画出架构并标出评测 / 观测 / 安全 / 成本各在哪一层 |
