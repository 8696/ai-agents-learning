# 怎么用

不要把它理解成「24 个必须线性通关的关卡」，而要理解成 **路线 + 验收 + apps**：

| 读哪里 | 用来做什么 |
| ------ | ---------- |
| [学习路线](./03-学习路线.md) | 顺序、重点与坑、综合验收（2.3 / 2.6 / 2.8） |
| [学习模块](./学习模块/README.md) | 每个模块一个文件夹：README = 验收 + 小节进度；每小节一个 MD（`01-短名.md`）= 学习沉淀 |
| [学习总览](./06-学习总览.md) | 整模块过完没有 |
| [核心术语](./07-核心术语.md) | 一句话定义；让助手抽术语考你 |

**优先级冲突时**：项目产出 > 验收标准 > 知识点覆盖度。宁可少学两个知识点，也不要交不出可运行的代码。

## 1.1 这份文档教什么、不教什么

| 在这里找 | 不在这里找 |
| -------- | ---------- |

API 细节、SDK 写法和过时点，以 [资源清单](./05-资源清单.md) 的**官方文档**为准。讲解由陪跑的 AI 助手按 [使用协议](./01-使用协议.md) 现场给；卡片本身不是教材。

**给 AI 助手**：未经学习者明确要求，不要换成文档未列供应商（OpenAI 官方、Google Gemini）；不要把 MiniMax 写成海外站 `*.minimax.io`；模块 00 只跑 MiniMax 协议 A；模块 02 再接入其它端点。智谱/OpenAI 兼容必须用 `openai` 包；Messages API 必须用 `@anthropic-ai/sdk`（含 MiniMax/智谱的 Anthropic 兼容端点，**换 baseURL，不是换 Key**）。

### 1.2.1 模型供应商速查（本仓库固定）

**三家供应商、两种协议、两个 SDK。** MiniMax 与智谱**各提供 OpenAI 兼容 + Anthropic 兼容**两套 endpoint，**同一家共用同一个 API Key**。环境变量只维护 `apps/.env.example`。

| 配置落点 | 路径 | 说明 |
| -------- | ---- | ---- |
| Key 模板 | `apps/.env.example` | 复制为 `apps/.env` 后填 Key |
| 业务代码 | 各 `apps/{模块}/{小节}/` | 客户端写在子文件夹；模块 00 mini-app 在 `apps/00-环境准备/01-mini-app-step-1/` |
| 读配置 | 入口 `loadRootEnv()`（`apps/load-root-env.ts`） | 指向 `apps/.env` |

#### 协议 × SDK × Base URL（默认中国区）

| 协议 | SDK | 调用方式 | MiniMax Base | 智谱 Base | Anthropic 官方 Base |
| ---- | --- | -------- | ------------ | --------- | ------------------- |
| **A · OpenAI Chat Completions** | `openai` | `chat.completions.create` | `https://api.minimaxi.com/v1` | `https://open.bigmodel.cn/api/paas/v4/` | — |
| **B · Anthropic Messages API** | `@anthropic-ai/sdk` | `messages.create` | `https://api.minimaxi.com/anthropic` | `https://open.bigmodel.cn/api/anthropic` | `https://api.anthropic.com` |

#### 环境变量（按供应商分组）

| 供应商 | 启用 | 变量 | 说明 |
| ------ | ---- | ---- | ---- |
| **MiniMax** | 00 起 | `MINIMAX_API_KEY` | 协议 A、B **共用** |
| | 00（协议 A） | `MINIMAX_BASE_URL` `MINIMAX_MODEL` | OpenAI 兼容，模块 00 默认 |
| | 02（协议 B） | `MINIMAX_ANTHROPIC_BASE_URL` `MINIMAX_ANTHROPIC_MODEL` | Anthropic 兼容，同 Key |
| **智谱 GLM** | 02 起 | `ZHIPU_API_KEY` | 协议 A、B **共用** |
| | 02（协议 A） | `ZHIPU_BASE_URL` `ZHIPU_MODEL` | OpenAI 兼容 |
| | 02（协议 B） | `ZHIPU_ANTHROPIC_BASE_URL` `ZHIPU_ANTHROPIC_MODEL` | Anthropic 兼容，同 Key |
| **Anthropic 官方** | 02 起 | `ANTHROPIC_API_KEY` `ANTHROPIC_BASE_URL` `ANTHROPIC_MODEL` | 仅协议 B，海外 |

文档链接：[MiniMax OpenAI](https://platform.minimaxi.com/docs/api-reference/text-openai-api) · [MiniMax Anthropic](https://platform.minimaxi.com/docs/api-reference/text-anthropic-api) · [智谱 OpenAI](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction) · [智谱 Anthropic](https://docs.bigmodel.cn/cn/guide/develop/claude/introduction) · [Anthropic 官方](https://docs.anthropic.com/en/api/getting-started)

#### 模块 02 推荐对比顺序（理解「同 Key、换协议」）

1. **MiniMax 协议 A vs B**（同一 `MINIMAX_API_KEY`，`openai` vs `@anthropic-ai/sdk`）— 最干净的协议对照实验
2. **智谱 协议 A vs B**（同一 `ZHIPU_API_KEY`）
3. **Anthropic 官方 协议 B**（与上面对照「原生 Claude」与「国内 Anthropic 兼容网关」）

| 对比维度 | 协议 A（OpenAI 兼容） | 协议 B（Messages API） |
| -------- | --------------------- | ------------------------ |
| SDK | `openai` | `@anthropic-ai/sdk` |
| 入口 | `chat.completions.create` | `messages.create` |
| system | `messages` 内 `role: "system"` | 顶层 `system` 参数 |
| 流式 | `choices[0].delta.content` | `content_block_delta` 等事件 |
| MiniMax/智谱 | 各有一套 Base URL | 各有一套 Base URL（**Key 不变**） |

**区域与域名（常见错误）**

| 错误 | 正确（本仓库默认） |
| ---- | ------------------ |
| `api.minimax.io` / `platform.minimax.io` | `api.minimaxi.com` / `platform.minimaxi.com` |
| 模块 00 同时配置并调用 `ZHIPU_*` / `ANTHROPIC_*` | 模块 00 只跑 MiniMax；另两家在 `apps/.env.example` 注释，模块 02 再启用 |
| 用 `openai` 包调 Messages API | Messages API（含 MiniMax/智谱 Anthropic 端点）一律 `@anthropic-ai/sdk` |
| 以为 Anthropic 兼容要换 Key | MiniMax/智谱 **同 Key**，只换 `*_ANTHROPIC_BASE_URL` |
| MiniMax Anthropic 端点写成 `/v1` | 应为 `https://api.minimaxi.com/anthropic`（无 `/v1`） |
| 智谱 Anthropic 端点写成 `/paas/v4/` | 应为 `https://open.bigmodel.cn/api/anthropic` |
| 为 GLM 安装 `@zhipuai/sdk` 等专属客户端 | GLM 继续用 `openai` 包，只换 `baseURL` + `apiKey` |
| 模块 00 把协议 B 当验收 | 验收只跑 `yarn app:00-01-mini-app-step-1`（协议 A HTTP）；协议对照留模块 02 |
| MiniMax **Token Plan 订阅 Key** 当按量 **API Key** 用（或反过来） | 按 [Token Plan 说明](https://platform.minimaxi.com/docs/token-plan/intro) 选对 Key 类型 |

**代码约定**：

- **协议 A**（MiniMax、智谱）：`openai` 包 + `*_BASE_URL`（含 `/v1` 或 `/v4/`）→ `chat.completions.create`。
- **协议 B**（MiniMax、智谱、Anthropic 官方）：`@anthropic-ai/sdk` + 对应 `*_ANTHROPIC_BASE_URL` 或 `ANTHROPIC_BASE_URL` → `messages.create`。
- MiniMax / 智谱：协议 A 与 B **共用** `MINIMAX_API_KEY` / `ZHIPU_API_KEY`，不要为 Anthropic 兼容再申请第二个 Key（除非控制台另有规定）。

### 1.2.2 本仓库代码规范

## 1.4 不要现在转 Python

Agent 应用开发主线就是 TypeScript + Node.js。模型训练、Fine-tuning、LoRA、PyTorch、CUDA 以后再补 Python。

**不要为了「AI」这个词把自己原来的技术栈推倒重来。** 在 Python 上花的精力超过总量 5%，说明跑偏了。

临时可以碰一点：`pip install` 跑别人的开源项目、抄只有 Python SDK 的文档、清洗评测集、**读懂一份 Python Agent 的循环代码**。这是 B 档：技术讨论能对上「Python 和/或 TypeScript」即可，不要系统学、不要超过总精力 5%。TS 生态在 Agent 方向已经完整（官方 SDK、LangGraph.js、MCP TS SDK、LanceDB、Langfuse），没有「必须用 Python」的硬缺口。唯一真正需要 Python 当主线的是模型训练侧，那不是日常工作。
